# 接口场景生成指引

## 什么时候用

用户要「把这几个接口串成一条业务链路」「生成下单/支付回归场景」「接口之间传参」时，
先按本指引盘点资产，再产出候选场景卡。单接口的功能用例不走这里。

## 步骤

1. 用 `get_project_outline` 看清模块树与接口用例数量，确认目标模块存在。
2. 用 `search_test_assets` 搜出可复用的接口用例（关键词用业务名而不是路径），
   记下用例 id 与它所属模块；**不要凭空编造接口路径和字段**。
3. 用 `propose_scenario_plans` 产出 **≥2** 个候选方案（正常链路 / 异常或补偿链路），
   每个方案给出步骤图与选择理由，让用户在卡片上确认或另存为正式场景。
4. 用户确认前不要声称「已保存」；保存由卡片按钮执行，模型不直接写库。

## 步骤图约定

- 节点类型：`start`、`api`、`assert`、`extract`、`end`；边只允许从 start 出发、
  汇入 end，不允许环（调度器会拒绝环与孤立节点）。
- 接口节点必须带 `case_id`（来自搜索结果）；没有对应用例时，先建议用户补用例。
- 前一步的响应字段传给后一步时，在 `extract` 节点声明变量名，并写清来源路径
  （如 `data.orderId`），后续步骤用 `${orderId}` 引用。
- 同一场景内的断言优先放在 `assert` 节点，不要在 `api` 节点里塞多组断言。

## 输出语气

- 先一句话说明方案差异（正常 vs 异常），再列步骤；不要复述工具返回的原始 JSON。
- 风险与前置数据（账号、库存、支付状态）单独列出，别藏在步骤描述里。
