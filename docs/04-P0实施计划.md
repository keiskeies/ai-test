# 04 · P0 实施计划（API 单端跑通）

P0 的**唯一验收**：一句话导入一个真实 swagger → 生成 ~20 条场景 → 跑出带证据的报告 → `atest run` 在 CI 里结果与本地一致。

P0 里**只有脚本模式**，IR 先只支持 JSON + Monaco 编辑，不做可视化编辑器，不碰 Playwright / ADB。理由见 `docs/01` §7。

---

## 包结构（pnpm workspace）

```
packages/
  ir/              # zod schema → JSON Schema/TS/OpenAPI；无 node 内置依赖
  engine/          # 解释器 + 变量空间 + 控制流 + 断言器 + 表达式(JSONPath/JSONata)
  engine-lint/     # 静态闸（docs/02 §7 规则表）
  adapter-http/    # undici + OpenAPI 解析 + openapiCall 参数具象化
  agent-core/      # planner/tool loop/skills/slash/上下文构建器
  mcp-servers/     # openapi / mysql / qdrant / redis /（内部）engine
  llm/             # provider registry / task group 路由 / 成本账本 / 语义缓存
  store/           # drizzle schema + 迁移；内容寻址证据存储
  cli/             # atest：run / lint / dryrun / import / gen / agent
  server/          # Fastify + BullMQ producer（P1 主体，P0 只留骨架）
  web/             # React 控制台（P1 主体，P0 只留骨架）
```

**第一天就要设的 lint 规则**：`packages/engine/**` 与 `packages/ir/**` 禁止 `import` 任何 node 内置模块（`fs`/`net`/`child_process`/`path`/`os`）。这条一破，浏览器端就得维护第二套校验，GUI 与执行器开始分叉 —— 那是调研里 Apifox/Postman/MeterSphere 全部踩过的坑（`docs/00` §6.6）。

### M0.6 的落点：两种执行形态**逐步等价**（`docs/09` §4.2）

`packages/engine/src/executor.ts`（503 行）把步骤执行抽成 `StepExecutor` 接口，
两个实现：**功能形态 = 解释器**（`functionalExecutor` 只是薄包装，不复制逻辑），
**预编译形态 = 编译成同步节点树后直跑**（`compilePlan`），压测走后者、整体绕开解释器。

判据不是"预编译能跑"，而是 `executor.test.ts` 的 **35 例等价性测试**：
同一条 IR 用同一颗冻结时钟跑两遍，**按 stepId 逐条对齐状态与 healed**，
另加 40 例随机步骤树的属性测试。对齐维度刻意**不含**报错文案 ——
措辞该各自演化，把文案写进判据会让测试变成谁也不敢改的字符串快照。

共用靠**调同一个函数**，不靠"两份写得很像的代码"：值求值走 `resolve.ts` 的 `resolveValue`、
断言走 `assertions.ts` 的 `evalStructAssert`、变量空间直接用解释器那个 `VarSpace` 类。
唯一必须两份的是**调度**（`runChildren` 是 async + 带重试 + 带事件，热路径必须同步无副作用），
所以 `runSeq` 的四条规则逐条注明了它抄自解释器的哪一段。

**等价性测试当场抓出的四处真实分叉**（都是"看着能用"的那类）：
`onError:'continue'` 被忽略（配了 continue 的用例在压测里少跑 4 步，曲线照样好看）、
容器节点不记自己的结论、`while` 少压一轮迭代帧、
以及**求值异常只抓了 `VarError`/`PathError`，漏了 `ExprError`** ——
后者让表达式语法错直接抛出 `run()`，整体状态确实是 error，
但**没有"哪一步坏了"这条记录**：压测里几千 VU 同时炸时屏幕上只剩一句 `ExprError`，谁也定位不到步骤。

**被测试自己骗过一次，值得记下来**：`while` 少压帧那个变异体**没有让任何测试变红**。
原因是要素泄漏对两边的结论毫无影响，于是"两边一致"的断言照样绿。
补的判据不是"更严的一致性检查"，而是**泄漏就可观察**：循环外引用循环变量必须报 error
（`leakCheck()`）。一个不咬人的测试比没有测试更糟 —— 它给出虚假的安全感。
本文件所有关键断言都过了变异验证（把对应实现改坏，测试必须变红），逐条结果：

| 变异（把实现改坏） | 变红的例数 | 备注 |
|---|---|---|
| 删 `runSeq` 里的 `onError==='continue'` | 1 / 35 | |
| 容器节点不再记自己的结论 | 9 / 35 | 嵌套用例全对不齐，抓得最狠 |
| `runSeq` 不再抓求值异常 | 1 / 35 | 就是漏 `ExprError` 那个 |
| 加回"全 skipped → 整体 skipped" | 1 / 35 | 这条是我自己加错的分支，见下 |
| **删 `while` 的迭代帧** | **0 / 35** ← 最初没抓到 | 补 `leakCheck` 后 1/35 |
| 删 `forEach` 的 `popTo` | 1 / 35 | |
| 基线判据去掉可比性检查 | 4 / 26 | |
| 没基线时判 pass | 1 / 26 | |
| 去掉"本次样本为 0"短路 | 2 / 26 | |
| `healed` 的 run 允许当基线 | 2 / 26 | |
| 阈值比较 `>` 改 `>=` | 1 / 26 | 边界只有一处，所以只红一条 |
| schema 里加回 `unordered` | 2 / 3 | |

支持子集与**拒绝**同样重要：`http`/`extract`/`sleep`/`call`/`parallel`/`db`/`assertLlm`/一切界面步骤
一律 `PrecompileRefused`，末尾还有一条"未归类的 kind 默认拒绝"，
这样以后加新 kind 忘了分类会被拒而不是被静默当成可压测。
`setup`/`teardown` 也走同一道闸 —— 否则主体是快的、前置是慢的，
压测数字混合两条路径而报告上看不出来。

`baseline` 模型在 `packages/ir/src/baseline.ts`（314 行 + 26 例）。
放在 ir 包是因为判据要在 CI/看板/编辑器三处给同一个结论。
核心不是"退化 20% 判 fail"，而是 **`unknown` 那几条路径**：
没基线、指纹不可比（施压机规格/并发/连接数/数据量/实例数/时长逐项比）、样本不足、同一被测版本。
**没基线绝不判 pass** —— 那等于新场景上线头三个月没有门禁而没人知道。
`LoadFingerprint` 刻意不复用 `EnvFingerprint`：后者管"回放是否等价"，
性能结论要的是 docs/09 §4.3 点名的另外三维，其中**数据量**是"同一条 SQL 慢十倍"的头号外因。
`healed`/`fail`/短跑的 run 不能当基线（**基线被悄悄下调是最隐蔽的失效**：
门禁看起来在工作，实际已经不再拦任何东西）；人手动 `pinned` 的绕开这三条，
但**不绕开可比性检查**。

**两条刻意的不一致**（不是待修 bug，写出来是因为"悄悄不一致的注释比没有注释更坏"，
P7 接 k6 时如果照功能形态的预期去读压测结果就会读错）：

| 维度 | 功能形态 | 预编译形态 | 为什么必须这样 |
|---|---|---|---|
| 重试 | `withRetry` 按 `step.retry` 重试 | **完全不重试** | 压测里重试会把一次故障算成两次负载，吞吐与错误率曲线就假了。k6 的 `retries` 同理应保持 0 |
| `wait{expr}` | `waitUntil` 轮询到 `timeoutMs`，指数退避 | 求值一次，不满足就直接按 `onTimeout` 办 | 热路径必须同步（`waitUntil` 内部 `await clock.sleep`）；且压测里"等外部条件"测的是我们自己的调度。**前提是压测用例的数据已预置**，谓词在负载下结果稳定 —— 不满足这个前提就不要用 `wait` |

另有两处**已知不足**（不是分叉，两边同样弱）：`ops` 只报"循环体几条"而不乘迭代次数
（它的用途是"每迭代成本"，乘了反而不对，但没有别的字段能算总成本）；
`LOOP_TRUNCATED` / `LOOP_CEILING_HIT` 两条 lint 事件在预编译形态发不出去
（那个形态压根没有事件通道），所以**用预编译形态跑过的用例不等于 lint 干净**，
lint 必须在功能形态上单独跑一遍。

### M0.6 顺带发现的三处"schema 有字段、执行侧没人读"

这个缺陷类别在本仓已出现三次（`maxCostUsdPerResolve` 是第一个），所以做了一次系统扫描
（列出所有 zod 字段，逐个查执行侧有没有读过它）：

| 发现 | 症状 | 处置 |
|---|---|---|
| `wait.onTimeout: 'error'` | IR 的三个合法取值之一。解释器只分 `'continue'` 与"其余"，**error 是永远走不到的 schema 取值** —— 用户显式要求"等不到算环境问题"，拿到的是 fail（=产品有 bug），值班人会去查一个不存在的功能问题 | 解释器补上第三态。`executor.test.ts` 三态各一例，把该分支改成不可达即变红 |
| `assertPerf.maxRegressionRatio` | 判据写作 `if (阈值 !== undefined && metrics.baselinePctl)`：**基线缺失时整条判据静默不跑、断言照样 pass**。性能门禁在基线表为空的那半年一直绿灯放行，看板一片绿而它拦下的次数是 0 | 改成缺有效基线判 **error**。`perf-assert.test.ts` 10 例（该断言此前**零测试**，这正是它能坏着活这么久的原因） |
| `Match.unordered` | schema 收、`evalMatch` 从不读，而且**它在这个子句形状里没有自洽含义**：Match 是"某个路径上的单个值满足什么"，没有"期望列表"可比，也就没有顺序可忽略。写了它的人拿到的是逐元素 each 或一个都不比的 exact，用例随机判失败 | **删除该键**。现在 `.strict()` 直接拒（比默默忽略诚实）。真要无序比较得先给 Match 加期望值维度，是 P2 编辑器的题 |

顺带把"新增 Match 键必须同步实现"做成了**自动对账**（`engine/test/match-keys.test.ts` 3 例）：
左边 `MATCH_KEYS` 从 schema 本体取（为此把 `MatchObject` 拆出来单独导出，
因为 `z.lazy` 自引用逼着 `MatchSchema` 擦成 `z.ZodType<Match>`，一擦就看不见 `.shape`，
"这个子句有哪些键"在类型层面消失，只能手抄），右边从 `evalMatch` 源码扫 `m.xxx`。
**两边都不是手抄清单** —— 手抄的测试只能验证"两份清单抄得一样"，而那正是出问题的地方。
第三条测试是写死在仓库里的自证（凭空加一个没人读的键必须被抓出来），
防止将来某次重构把扫描逻辑改失效、于是"空对空"也算一致。

对账放在 engine 侧而不是 ir 侧：论断的两端要都够得着 ——
ir 不能 import `node:fs` 去读 engine 源码（依赖方向禁止），
而 engine 读自己的源码 + import `@atest/ir` 的导出，两个方向都合法。

### M0.6 的另一处发现：`packages/ir/test` 从来没被类型检查过

**双向校验的语义差异**（这两条弄反都会烧掉红绿的可信度，所以写死在代码注释里）：
请求侧**发送前拦截**并判 error（本地的"少了 amount"比后端的"400 原因未知"有用），
但 `requiredMissing`/`typeViolation`/`negativeFuzz`/`boundary` 四种策略**只记事件不拦** ——
它们的用意就是发坏请求看后端拒不拒绝，一律拦等于把"后端缺参数校验"这类
最有价值的发现安静地作废。响应侧**只在 `env.specAuthoritative===true` 时做，且只上报**
（docs/05 §1.1：符合性问题的含义是"文档与实现谁错了"，混进业务回归红灯会让人
把所有红灯都当成误报）。

**故意没做，不要当成已交付**：

| 缺口 | 现状 | 何时必须补 |
|---|---|---|
| ~~鉴权层~~（docs/05 §2 整节） | **已实现**（bearer/basic/apiKey×3/oauth2 clientCredentials + `atest auth-check`）。**仍缺 cookie jar 与签名 provider**，见「鉴权层的落点」 | 已补。剩余两项各自有明确接入点 |

| `openapiCall` 的 query style | 引擎 `buildUrl` 用 `URLSearchParams`，**不读 spec 声明的 style/explode**。单值参数没事，数组参数一定错 | P2 做真实 API 回归前。目前只有单值用例掩盖了它 |

### M6 的落点：证据、报告出口、CLI

四块交付，各自有测试文件，**判据不是"能产出文件"而是"文件里的结论不撒谎"**：

| 交付 | 位置 | 判据由谁兑现 |
|---|---|---|
| 磁盘内容寻址存储 | `store/src/artifacts.ts` | 文件名 = 内容 sha256；**脱敏发生在序列化到磁盘的那一刻**（字段名规则 + 值形态规则），不是显示层；`keepRawKinds` 是**默认空的白名单** —— 要原文必须点名，默认脱敏 |
| zip 打包 | `store/src/zip.ts` | 自研写入器（无依赖可装）。`e2e.test.ts` 用**系统 `unzip -t` 解真包**，不是用我们自己的读取器验自己的写入器 |
| 三出口 | `engine/src/report.ts` | `trace.jsonl`（机器/复盘）+ JUnit XML（CI）+ `manifest.json`/`summary.txt`（人） |
| CLI `atest` | `packages/cli`（9 文件） | `run/lint/gen/agent/init/evidence` 六命令 |

**JUnit 的判据实现**（`engine/test/junit.test.ts`，15 例）：不用我们自己的导出器验自己 —— 那叫循环论证。XML 交给 **CPython 的 expat**（完全独立的实现）解析，判据算在解析后的 DOM 上：计数自洽、`fail`→`<failure>` 而 `error`→`<error>`、容器步骤不产出 `testcase`（否则 `tests` 大于真实用例数）、`time` 单位是秒、控制字符转义、测试名里的引号不改写报告结构。**六态映射里两条最容易被涂绿的写死了**：`healed` 默认判 `<failure>`（JUnit 没有软失败这一桶），`triaged` 判 `<skipped>`（不算失败也不算通过）。

**退出码就是 CLI 的 API**（`cli/src/exit.ts`）：`0` 全绿 / `1` 测出失败 / `2` 用法错 / `3` IR 或 lint 不合法 / `4` 环境缺失 / `5` 运行异常 / `10` 被中断。分这么细的理由只有一条 —— **一个配置写错的构建和一个真失败的构建，值班人的动作完全不同**，而默认写法（只看非零）把两者压成同一个红。`CI_HINT` 会随 `summary.txt` 与 `--help` 一起输出，因为"exit 1 是好消息"这件事只存在于写 CLI 的人脑子里。`126/127/128/130/137/139` 是**保留段**（npm 把信号死亡转成 `128+signum`），占用了它们就等于把"有人按了 Ctrl-C"读成我们某个业务结论；`ABORTED=10` 刻意落在低段，因为部分 runner 把 >125 当基础设施异常、不标红也不通知人。

**门禁判定是纯函数**（`cli/src/gate.ts`，18 例，直接调用测试，不起子进程）。四个设计点值得单独记：
1. **`--ci` 且 `frozen=false` → 一个请求都不发就返回**。跑了再拒绝，等于把 POST/下单/清理先做完了再说"这次不算"。
2. 先查 `frozen` 再查 `provenance`：未冻结是"还没定稿"，缺 provenance 是"定稿了但不知哪来的"。报后者会让人先去补 provenance，白做功。
3. **`triage` 降级必须显式**：降级了多少步失败要打印数字与待确认清单（`docs/05` §3 要点 1 —— 首轮必一片红，一片红的第一天 = 用户关掉整个门禁）。不显示数字就是偷偷涂绿。`StepSchema`/`ScenarioSchema` 都是 `.strict()`，塞不进自定义布尔，所以用 `tags: ['triage']` 表达。
4. **不按 `cause` 细分退出码**。曾经把 `env-unavailable` 映射成 `ENV`，错了：connection-refused 也走这个 cause，而它恰恰值得重试。换成运行**前**的 `requireAdapters` 预检 —— 缺什么、照抄哪行命令，在发第一个请求之前说清。

**生成器**（`cli/src/gen.ts`）7 个策略可生成、5 个**明确不生成并写明原因**（`statefulSequence`/`authMatrix`/`contract`/`idempotency`/`perfSmoke`，都依赖还没做的鉴权层、契约车道或基线模型）。`--strategies all` 会对每个不生成的策略打一条告警 —— 静默跳过会让人以为"all 已经包含它们"。硬规则三条：输出里**没有时间戳**（用 `specHash` 顶替 `generatedAt`，否则同一份 spec 重复生成必然产生 git 噪声）、`frozen: false`（生成物不是门禁依据）、非门禁策略打 `triage` 标签。

**M6 顺带修掉的两个引擎级缺陷**（都修在"没法再犯"的位置，不是改一处输出）：
- **`scenario.inputs[].default` 没人读** —— "schema 有字段、执行侧没人读"这个缺陷类别的**第 5 例**。症状很有迷惑性：**本地手工跑能过，CI 里必炸**，因为手工跑时 UI/命令行会带上表单里的默认值，而 CI 只给场景本体。现在 `applyInputDefaults()` 在 `compilePlan` 时套用（默认值是**场景的属性，不是迭代的属性**，放进每次迭代会让循环内外的值不一致），只有"根本没传这个键"才用 `default`（显式传 `null` 是想传 `null`）。生成器**刻意不写 `default`**：它不知道该填什么，写一个看着合理的值就是把这条用例变成"偶尔通过"。
- **耗时没格式化就写进 trace** —— 未格式化的 `performance.now()` 差值产出 `POST 201 4.305087999999955ms`，于是**每一次运行的每一行 trace 都不同**，`diff <(unzip -p a.zip trace.jsonl) <(unzip -p b.zip trace.jsonl)` 永远有差异，M7 的确定性验证根本无法做。现在统一走 `fmtMs()`（一位小数）。

**一处平台限制是被证明的，不是假设的**：中文成员名的 zip。我们把 UTF-8 flag（bit11）置上了，`ditto` 能正确解出 `artifacts/步骤 一/响应 体.json`，但 macOS 自带 Info-ZIP 6.0 **整包拒绝**（`Illegal byte sequence`），且与 locale 无关。测试因此改成断言三件事：flag 位确实置上了、名字往返一致、**真实成员名全 ASCII**（也就是产物命名规则本身避开这个问题）。顺带一提原先那条测试是**假通过**：它断言的是我们自己的读取器能读回来 —— 那当然能，写和读是同一份代码。

**M7 判据的准确形态**（写文档时最容易过度声明的一句）。原判据"同一冻结场景跑 20 次，**断言结果完全一致**"，实现分了两档，因为一锅端会做出一个假测试：
- 打真 socket 跑 20 次 → 断言**状态与 healed 逐条对齐**（只归一化 `time=`/`timestamp=`）。**不比字节**，因为真实 IO 的耗时本来就该变。
- 纯计算场景（不碰网络）跑两次 → 才要求 `evidence.zip` **字节完全一致**。
把第一条也写成字节比对，得到的会是一个"只要没人网抖动就永远绿"的测试。

**`irSha` 是现在算的，不是"P1 才有"**（这一度被我写成"依赖 P1 的版本表"，那是把两件事混了：`versionId` 需要版本表，`irSha` 只是内容哈希）。投影在 `ir/src/scenario.ts` 的 `canonicalScenario`（纯函数，浏览器里的编辑器也算得出来），哈希在 `store/src/ir-hash.ts`（那一层放得下 `node:crypto`），**证据包组装时自己算**、不接受入参 —— 入参意味着会有调用方忘传，而那正是"字段有、没人填"。唯一被排除的正式字段是 `frozen`：它是生命周期状态不是内容，进哈希会让"点一下冻结"凭空造出一个新版本。

**排除的代价要写明白，别当没有**：`frozen` 同时是证据清单与版本元数据里的字段，排除它意味着 **run 证据里的 `frozen` 不等于那一版的 `frozen`**（`--allow-unfrozen` 跑出的证据写着 `false`，而它指向的版本是冻结的）。不统一：证据要记**运行时的实际状态**（它决定这份证据能不能当门禁依据），版本表要记**生命周期动作**，读证据的人需要的是前者。

### M6 的另一处教训：测试通过的原因可能和它想验的东西无关

这一轮抓出 **6 个假通过的测试**（全绿，但断言根本没接触被测对象）。它们的共同形态值得当成一类来查：

| 假通过 | 为什么绿 |
|---|---|
| `junit.test.ts` 的"time 单位是秒" | `parseXml` 的返回类型漏写 `time` 字段 → 断言实际在比较 `undefined == undefined`，**恒真** |
| `evidence.test.ts` 的中文文件名 | 断言的是**我们自己的 zip 读取器**能读回来，而写和读是同一份代码（真正该验的是外部 `unzip`） |
| `args.test.ts` 的一条 | 断言写在**另一个开关**上（改名时把测试和实现一起改错了方向） |
| `lint-layers` 的两条"违例被拦" | store 的 reason 里含"adapter"一词但整句说的是**不要**依赖 adapter；adapter-http 的 reason 压根没论证为什么可以碰 node。收紧正则为 `/磁盘\|网络\|子进程\|进程\|副作用/` 后两条同时现形 |
| `evidence.test.ts` 的"少成员要报出来" | 断言写成 `missing.length >= 0` —— **恒真**，一个从不填 `missing` 的实现也能过，而这条测试的名字恰恰是"不能静默少一个成员" |
| `canonical.test.ts` 的"键顺序不影响指纹" | 看着在测排序，实际在测 zod：**`parseScenario` 出来的对象键顺序等于 schema 字段声明顺序**，两种书写 parse 完就一样了，把 `.sort()` 删掉它照样绿。真保留插入顺序的是 **record 字段**（`set.assign`/`http.query`/`args` 这类 `z.record`），补一条用 `assign: {zz,aa}` vs `{aa,zz}` 的测试才真的钉住那行 |

**最后两条是这一轮现抓的**，方法就是变异测试：把 `missing.push(r.id)` 与 `.sort()` 分别删掉看会不会红。
所以变异脚本报"未被抓到"时，先分清两种可能：**(a) 测试真有洞**（补测试）；
**(b) 那是等价变异**（改坏后的行为其实没变，补多少测试都抓不到）。
本轮确认的等价变异有两个：`if (val !== undefined)` 删掉（`JSON.stringify` 本来就丢 undefined 值的键）、
数组用默认 `.sort()`（对象全转成同一个字符串，顺序不动 —— 要测就得用比较器）。
**等价变异要当记录写下来**，否则下一个人会把它当成漏抓的洞，去补一条同样抓不到的测试。

这一类的完整清单与判别办法记在 `docs/08` §3（"测试通过的原因和它想验的东西无关"那一行）—— 它是"schema 有字段、执行侧没人读"的**测试侧镜像**：一个是字段没人读，一个是断言没接触被测对象，共同后果都是"显示成功而其实什么都没发生"。

两个可复用的动作：**(1) 变异测试是这里的常规步骤，不是可选步骤** —— 每个关键断言都必须在实现被故意改坏时变红（本轮对 `gate`/`args`/`gen`/adapter 注册/耗时格式化共做 15 处变异，抓到 13 处，2 处幸存 → 各补一条新测试而不是解释掉）。**(2) 变异脚本本身也会错**：`execFileSync` 抛异常时丢掉 stdout（把"抓到"报成"无法判定"）、跨包改 `src` 忘了 `tsc -b`（`dist` 是旧的，把真抓到的报成"未被抓到"）。**变异报告显示"未被抓到"时，先怀疑脚本。**

### 鉴权层的落点（docs/05 §2）

"生成用例跑出来全是 401" 被文档列为 API 平台第一体验杀手。落点在 `packages/adapter-http/src/auth/`（六文件 1152 行 / 47 例）+ `packages/cli/src/authcheck.ts`（339 行 / 23 例）+ 引擎侧 `identity.test.ts`（13 例）。

**中心决策：引擎声明意图，adapter 应用方案。** 引擎原先自己写 `headers.authorization = 'Bearer ' + secret(ref)`，三个后果：引擎认识了"方案"这种网关语义（而"引擎能在浏览器里跑只读校验"要求它不知道）；apiKey-in-query/cookie 与 basic 压根写不出来；**真值进了引擎内存**，于是能顺着任何一次 `keyContext`/`summary` 流到磁盘。现在引擎只传不透明引用（`auth?: {ref?, identity?, docRef?, operationId?, method?, path?}`），值只在 `apply.ts` 一处、发请求那一刻被取出。auth 测试的核心判据全部读 **`send()` 实际收到的请求**，而不是步骤状态 —— 状态本来就"该"通过，错的是它对下一步的影响。

| 交付 | 判据由哪个测试兑现 |
|---|---|
| 方案归一（apiKey×3 / http bearer+basic / oauth2 clientCredentials） | 每种畸形 securityScheme 各产出一条**指名道姓**的 issue（少 name、`in` 不认识、`scheme:'Digest'` 等），绝不"悄悄不加鉴权" |
| `security` 层级继承 + OR/AND 语义 | 数组项之间 OR、项内键之间 AND、`[]`/`[{}]` = 显式公开。选不到可满足组时报缺哪个 scheme |
| 凭证表 `(docRef, 身份) → secret:<ref>` | 顺序：身份精确 > 该 doc 的 default > 匿名 default，且**跨桶找身份**。只收 `secret:` 引用，配置文件里写明文一律拒 |
| oauth2 token：缓存 + 过期前刷新 | key = `env\|clientId\|scope`、TTL `expires_in-60s`（无则 5min）；用**不带 hook 的专用 client**（结构上杜绝递归取 token），仍透传 `fetchImpl`（SSRF allowlist）；`retries:0`（部分 IdP 每次签发吊销上一个） |
| `atest auth-check` | 逐方案×逐身份。**只走 GET/HEAD**（诊断命令在 CI 里产生业务副作用不可接受）。500/404 算凭证被接受（进到业务代码 = 网关放行）；needs-config / rejected / unreachable / not-probed 四态分开，因修法毫无重叠 |

**故意没做，不要读成已交付**：

| 缺口 | 现状 | 何时必须补 |
|---|---|---|
| cookie jar / session | `apply.ts` 的 `cookieHeader` 入参已接好，上游传 `undefined`。`in:cookie` 的 apiKey 已能合并进 Cookie 头，缺的是**跨步骤的会话持久化** | 与 `storageState`（Web 侧）一起做，单独做半套会误导 |
| `signProvider`（签名类/国密/自研 token） | 扩展点在 `AuthScheme` 联合类型里留了位，未实现 | 有真实项目带这种鉴权时。现在写等于凭想象写（同 `.gitlab-ci.yml` 的判断） |
| oauth2 authorizationCode / implicit / openIdConnect / digest | **明确拒绝**并各带 workaround（docs/05 §2："直说，别硬做"） | 需要人工录 cookie 或手填 token 的场景 |
| auth-check 的重定向选择（`followRedirects:false`） | **只由代码审查守着**，无测试：命令级测试走注入的 `send`，不经 HttpClient。已在变异集里标 `expect:"equivalent"` 标明这一点 | 命令收到 `send` 工厂注入点之后 |

**这一轮又抓到本仓那个缺陷类的三处新实例**（`docs/08` §3 已把计数抬到八）：

1. **`useIdentity` 只 `return {status:'pass'}` 什么都不切** —— 八例里唯一**报告成功**的一例，前几例至少会失败。权限矩阵用例（A 的资源 B 读不到）双方拿到同一个身份，表现为"权限测试全绿"而它压根没测权限。
2. **`openapiCall` 算出 `authIntent` 却没传给 `send()`**（算它的那段注释正好在长篇解释"为什么必须交给 adapter"）。读代码看不出来——变量确实"被使用"了，用在上一行的字面量里。**只有断言"send 收到了它"才拦得住。**
3. **`http` 步骤读 `scenario.identity`（场景级静态值）而不读切换后的当前身份** —— 意味着只修第 1 条是无效修复：混用 `useIdentity` + 普通 `http` 步骤的场景里，切换那步变绿、后面的请求一个没变。

三个身份公式现合成一处 `identityFor()`，让"两个入口各写一份、其中一份写错"不再可表达。另外把 `authIntent` 从 `identity ? {...} : undefined` 改成**无条件带上**：那个对象的主体是 docRef/method/path（adapter 拿它查 spec 的 security），跟"有没有切身份"无关，老写法等于把"没切身份"当成"这是公开接口"，所有走 spec 的正常请求都变匿名请求。

**fixture 让两种实现算出同一个值**是这一轮测试侧的新形态（5 例假通过，方法仍是变异测试）。教训不是补断言而是**换 fixture**：验"用解析结果 vs 直接用步骤值"，得造一个二者必然不同的用例（步骤声明 operationId 时两种写法算出来一模一样）。

### `parallel` 的两条：`failFast`（扫描器报出来的）与 `maxConcurrency`（它报不出来的）

鉴权层收尾后，把 `docs/08` §3 里那句"扫描办法：列出 ir/src 所有 zod 字段名，逐个查执行侧——一次脚本就能跑出来，别靠偶然发现"真的写成了脚本（`tooling/unread-fields.mjs`，`npm run lint:fields`，已并进 `npm run lint`）。

**它第一次跑报了 100 个未读字段**，其中一个是 `parallel.failFast` —— 那一条是**它自己抓到的真缺陷**（见下），而顺着它去读 `parallel` 的实现时，才撞见下面这个更严重的。两件事要分开记，因为它们的**归因不同**：

- **`failFast` 是扫描器直接报出来的**（第十例，纯形态）：字段声明了 `default(true)`，而解释器里**一次都没出现过**（`git show a35af76~1` 数得出来：0 处）。旧实现是"`Promise.allSettled` 全跑完，任一失败就 fail"，跟 `failFast` 毫无关系 —— 所以 `true` 与 `false` **行为完全相同**，这个字段写了等于没写。它比"配了没生效"更难察觉，因为两种写法都"看起来对"：`false` 恰好对上了旧实现的全跑完，`true` 则从没兑现过提前中止。已随本次修复接上（worker 池每轮查一次），并有 `failFast=false 时不拉停` 与 `failFast 拉停后没起跑的分支必须记 skipped` 两条测试各守一头。
- **`maxConcurrency` 是扫描器报不出来的**（第九例）：解释器实实在在读了它，只是把值用成了丢弃分支的下标。扫描器把我**领到了**这段代码（它把整个 `parallel` schema 拎出来让我逐字段过一遍），但缺陷本身在它的能力边界之外 —— 它判的是"名字有没有被碰过"，而这里碰过，用得不对。

把这两条混成"扫描器抓到了 parallel 的 bug"是不行的：那是给一把量不到东西的尺子记功，而下一个人会照着记功的那句去信它。

```ts
// 修之前
const settled = await Promise.allSettled(
  s.steps.slice(0, s.maxConcurrency).map(...)   // 只跑前 N 支
);
return { status: 'pass', summary: `并行 ${s.steps.length} 支` };  // 报的是声明数
```

分支数超过并发上限时，**多出来的分支压根没执行**，容器照样 pass，summary 还说"并行 5 支"。`maxConcurrency` 默认 4，所以任何 5 支以上的 `parallel` **每次都会静默丢尾巴**；丢掉的那支要跑的断言，正是这次运行唯一没验的部分，而结果里没有它的 stepId、报告里它是"通过"、覆盖率按分支数算——**全线一致地谎报**。

这一例比前八例都坏，值得单独记：

- **它不是"字段没人读"**。解释器实实在在读了 `maxConcurrency`，只是把值用成了丢弃分支的下标。所以扫描器**报不出它**（`parallel.test.ts` 里专门留了一条测试钉住这个能力边界，免得下一个人把那份报告读成"字段都用对了"）。
- 前八例最坏是"配置没生效"，这一例是**用例被删了而报告显示它过了**。测试平台的这种错没有征兆：没有失败、没有告警、覆盖率还挺高。
- 现改成 worker 池调度（谁先跑完谁补下一支），一支不漏；`failFast` 提前中止时没起跑的分支**逐个补记 `skipped`**，而不是从结果里消失——"没跑"必须在报告里读得出来。

顺带三条：`skipped` 分支不算失败也不拉停同批（否则"未执行"的规模由调度顺序决定，会被当 flaky 重试掉）；有分支通过时容器不整体报 `skipped`（`skipped` 不计入通过率分母，那会把真验过的分支一起抹掉）；分支抛 `RunAborted` 必须掀翻整个 run（吞掉的后果是取消之后其余分支还在往被测系统发请求）。`stop` 只留**一个**拉闸点：原先 try/catch 两边各写一次，而 catch 那一次**今天压根到不了**（`runStep` 把除 `RunAborted` 外的异常全收敛成 error 结果），是一行永远执行不到、变异也不会红的"看起来有防护"。

**同一道闸的 lint 侧（`PARALLEL_VAR_RACE`）**：闸原本只在解释器里，意味着"这份用例写得不对"要**跑到那一步**才知道。现在 `atest lint` 也报它，级别 **error**。

三条当时的判断，都记在这里因为事后看不出来：

- **判据不在 lint 里重写一遍**，`lint.ts` 直接 `import { parallelHazards } from '@atest/ir'` —— 与 `interpreter.ts` 的 `case 'parallel'` 是同一份函数。抄一份（哪怕一开始逐字相同）必然漂移，而漂移方向可预见：改判据的人只改引擎那侧（那边有 `parallel.test.ts` / `scope.test.ts` 盯着），lint 悄悄落后，于是 `atest lint` 说没问题、CI 放行、跑到那一步才被拒 —— 先信了 lint 再白跑一遍，而"白跑"在真实环境里意味着 parallel 之前的 POST 已经发出去了。`lint.test.ts` 里有一条**把同一批 IR 同时喂给 `lintScenario` 与 `runScenario` 并断言结论逐个相同**的对照测试，就是为了让"各写一份判据"这件事当天就红。
- **为什么是 error 而不是 warning：这是实测出来的，不是风格选择。** 我原先的理由是"运行时那道闸会落到 EXIT.RUNTIME(5)，而 warning 会让 CI 白跑一遍"—— 前半句**是错的**，实测推翻了它：一份"先一条断言、再一个撞名的 parallel"的场景，`atest run` 打出 `运行 … — error`、`计入 3 步：… 1 错误`，紧跟一句 `2 个断言全部通过。`，**退出码 0**。原因是 `cli/src/gate.ts` 的 `gateAfterRun` 里 `errors`/`fails` 都从 `leaves`（`!CONTAINER_KINDS.includes(kind)`）筛，而 `parallel` 是容器 —— **运行时闸记的那个 error 压根不进退出码判定**。（同一份场景把那条断言删掉才会落到 EXIT.INVALID(3)，走的是"0 个叶子步骤"那条分支；已单独上报，`gate.ts` 不在本轮改动范围内。）所以真实理由是反过来的：**撞名场景目前唯一能给出非零退出码的入口就是这条 lint**（`atest lint`，或 `atest run --strict`，两者都落 3 = "配置/用例问题，不是产品问题"）。降成 warning 等于把它放回"全绿但有一步压根没测"，正是本仓反复记的那类"用例被丢了而报告显示它过了"。
- **运行时那道闸不删**，虽然 lint 现在也报：`run` 默认不 lint（`commands.ts` 里写明是故意的，不把"IR 不对"与"产品坏了"压成同一个退出码）；`call` 的子场景是运行时由 CallResolver 取回来的，被 lint 过的父文件不代表子场景干净；engine 还以浏览器 bundle 的形态给前端做实时校验，没人强制调用方先 lint。lint 负责"写的时候早知道 + 拦下 CI"，运行时闸负责"绕过 lint 也不会跑出错误答案"，两个职责不重叠。

`tooling/mutate/lint-race.json`（改在"这条规则还报不报、级别对不对、报错里还有没有名字与分支、lint 与引擎还会不会给出同一个结论"上）。

**扫描器本身**：三级判定的**当前数字不写在这里**（写死过一次 "读过 129 / 判不出 233"，本轮改完 `gate.ts` 再跑已经是 130 / 232。是哪一处改动把它挪了一位**我没有核**，也不需要核 —— 重点是这类数字每次有人正常写代码都会动，抄进文档就等于登记一个必然过期的值）。现算：`npm run lint:fields`，或 `node tooling/unread-fields.mjs`。未读全部登记在 `tooling/unread-baseline.json`（判不出那批不逐条要求豁免，改为钉**上限** `inconclusiveCeiling`，上限省略即失败）（每条必须写归属阶段与理由；字段接上线后豁免不过期就报失败，改名/删字段漏清则报"悬空"）。它自己也有测试（例数同样不钉），其中一条钉**字段数下限**——它第一次跑的时候掩码函数漏了把代码字符复制回去，整份文件被抹平、扫出 0 个字段，然后输出一句"全部有豁免"并 `exit 0`：**一个抽不到字段的扫描器不会报错，它只会报告干净**。这条与它要防的缺陷同构。

`tooling/mutate/parallel.json`（改在"会不会少跑一支 / 少跑的那支会不会被记下来"上）、`tooling/mutate/scope.json`（改在"分支作用域还隔不隔离、合并还合不合得上"上）。

**变异集有几份、每份几例，这里一律不钉。** 上面那句"三份共 56 例"就是现成的反面教材：写下它的那一轮刚新增过变异集，数字当天就错了，而错的方式是**少算** —— 读的人以为自己看到的清单是全的。现算：`for f in tooling/mutate/*.json; do echo "$f $(python3 -c "import json;print(len(json.load(open('$f'))['cases']))")"; done`。**"抓到几例 / 几例没跑成"这里不钉** —— 那要真把实现改坏一遍才知道，而 `npm run mutate` 自己就会报；写死在文档里就等于把一个还没重跑的结论当事实（本轮改 `parallel` 那 6 例时，旧那句"50 例抓到 44"已经过期而无人察觉，正是同一件事）。

| 计划 | 实际 | 原因 |
|---|---|---|
| pnpm workspace | **npm workspace** | pnpm store 有 5.3G 但缺本工具链的 tarball，`ERR_PNPM_NO_OFFLINE_TARBALL` |
| vitest | **`node:test` + tsx** | vitest 的 vite/esbuild tarball 装不上（`ENOTCACHED`）。内置测试器零依赖，够用 |

| ESLint 的分层规则 | **`tooling/lint-layers.mjs` 自研** | 零依赖 + 规则需可单测 + 报错要能指向设计文档 |

### 写测试时暴露的 IR / 引擎缺陷（比测试本身更有价值）

这几条都是「看起来能用、实际从未生效」的类型，记下来是因为它们说明**只写实现不写测试，等于没写**：

1. **所有容器步骤解析不过**。`childSteps()` 返回的是 `StepSchema` 而不是 `z.array(StepSchema)` —— `while`/`if`/`forEach`/`repeat`/`parallel` 一个都构造不出来。IR 的核心表达力整个失效，直到第一个测试才暴露。
2. **`$..id` 递归搜索从未生效**。parser 产出 `recursive` + `key` 两段，而 `query()` 期望递归段自带键名，于是 `seg.value` 恒为 `undefined`，永远返回空。
3. **引用语言有两种互不兼容的方言**。表达式里 `$x` 合法，`against: "$x"` 却报「意外字符 x」；`$.row.score` 的变量名被拼成 `rowscore`，深层引用永远查不到。→ 现在 `$name` 与 `$.name` 处处等价，且 `resolveRef` 与 `asExprRoot` 的可见性规则严格一致（帧变量 > inputs > env）。
4. **静态闸引用扫描漏掉 `$.xxx`**。正则 `\$[A-Za-z_]` 在 `$` 后紧跟点号时**一个都匹配不上**，于是「引用不存在的步骤」「前向引用」两类检查实际从未执行。
5. **`HARDCODED_SECRET` 扫的是 `JSON.stringify` 结果，却按 `password:` 写法匹配**。JSON 里 `password` 后面是引号不是冒号 → 这条安全规则静默全量放行。另有一条 `SUBPATH_OK` 白名单放行 `fs/promises`，等于给分层检查开了直通口子（`import 'fs'` 拦、`import from 'fs/promises'` 放）。
6. **`INPUT_UNUSED` 用 `text.includes(name)` 判使用** —— 输入的声明本身就含这个名字，恒为真，规则从来没报过。
7. **`Date.now()` 混进引擎**（生成器 email/oid、`now()` 表达式、`nearNow` 断言）→ 「冻结时钟后回放逐字一致」在这些路径上并不成立。现在 `evalMatch` 的 `now` 是**必填参数**：给默认值等于把漏洞写进签名，每个忘记传参的调用点都会安静读墙上时间。
8. **循环帧提前 return 时不弹栈**，迭代变量泄漏到循环外。改为 `popTo(depth)`，不依赖子步骤的配对纪律。
9. **setup 失败被最终 tally 重算覆盖**（报 fail 而非 error）；teardown 失败会改写整体结论。现在 setup 失败一律升级 error，teardown 失败经 `TEARDOWN_FAILED` 事件暴露但**不改**「被测功能对不对」的判断。
10. **场景级 `config.retries` 与步骤级 `retry` 是同一概念的两套形状**（前者无法表达 `retryOn`/`maxMs`，写了被 strict 拒）。改为共用 `RetrySchema`。

### 新增的 IR 对外接口

- `StepDraft` / `ScenarioDraft`：**书写形态**（省略所有有默认值的字段）。裸 `Step` 要求手写 `onError`/`tags`/`exprExpected`，而这条链路的入口本来就是 JSON（Agent 生成、Excel 迁移、前端表单），TS 一律看不见 —— **合法性由 schema 判定，不由 TS 判定**。类型安全的书写请用 P2 的 SDK builder。
- `defineScenario(draft)`：不合法就抛。**人在写的**东西用它（builder / CLI / 测试夹具），**机器产出的**东西用 `parseScenario`（不合法是预期内，要拿 `errors` 驱动 Agent 的修复重试）。
- `withDerivedTargets` / `parseScenario` 现在自动按步骤补 `targets`。IR 里它是冗余字段，让每个作者自己算必然产生「targets 与步骤不一致」，而那会让能力校验给出错误答案。相应地 `targets` 放开 `min(1)`：纯逻辑场景（只做 set/assert、或专供 `call` 复用的数据准备）确实不触碰任何被测端。
- `LINT_DOCS: Record<LintCode, string>`：中心登记表。类型是 `Record<LintCode, …>`，**新增规则不登记就编译不过**；`push()` 兜底填 doc，所以「每条报错都有出处」是无条件的性质。

### 环境坑（跑测试前必读）

`tsx --test` 下**只要有断言失败**，单文件耗时会从 ~1s 涨到 **60–80 秒**：Node 的 source-map 机制用 acorn 重解析 `zod` 这类大文件来映射每个栈帧（profile 显示 acorn 行号表 + raise 占满 CPU）。所以：
- 迭代时先跑**单个文件**，或先用临时脚本验证；
- 见到"某条用例耗时 60s 且失败"，那不是引擎有性能问题（同一输入独立跑是 3ms）。

`exit=$?` **接在管道后面拿到的是管道末端那个命令的状态**，不是 `tsc`/`npm test` 的（本 session 栽过两次，两次都差点把"有 4 个类型错误"报成"typecheck exit=0"）。要看真实退出码就别接管道：`cmd > /tmp/x.log 2>&1; echo $?`。顺带一句，这个 shell 是 zsh，`${PIPESTATUS[0]}` 那套 bash 写法在这里也不生效。

### 已知取舍（不要读成"已经解决了"）

- `parsePath` 不支持切片与过滤表达式。故意的：通用库的任意表达式是静态分析的敌人，而静态分析是这个平台的根基。
- 断言对象是响应时**自动拆一层 `body`**（`value?.body ?? value`），所以路径写 `$.id` 而不是 `$.body.id`。这让 90% 的断言更短，但响应体自己有 `body` 字段时无法区分 —— 已记入 `docs/08` 欠账。
- `RESOURCE_LEASE_MISSING` 依赖 `deriveTargets` 把步骤归到移动端；纯 `noop`/`set` 场景 `targets` 为空，此时该规则不触发（这是对的：没有设备步骤自然不需要租约）。

## P0 阶段的取舍记录

- **不做 Qdrant（仅对 P0 成立）**。P0 只用到 embedding 的场景（元素语义检索、失败相似匹配）都还不存在，M5 的覆盖预览先用集合差集算。**⚠ 但已确认存在存量手工用例（`docs/08` C4），所以 Qdrant 在 P1 就是必需件而非优化** —— 用例族聚类去重与 fixture 语义检索是迁移的必需能力（`docs/11` M11）。这条取舍只管到 P0 边界，别把它读成"平台不需要向量库"。
- **不做可视化编辑**。API 场景用 JSON + Monaco 完全够；先做可视化会拖慢引擎打磨（`docs/01` §4）。
- **不引 Agent 模式**。IR 与自愈回写没定型前做自主 agent，轨迹无处落地，token 白烧。
- **不做 Playwright**。但 `LocatorSpec` 的数据结构要在 P0 就定下来（`docs/02` §6），因为 `assert`/`wait` 节点的 `uiPredicate` 条件依赖它 —— 定结构不等于实现执行器。
- **`script` 节点先禁用**。沙箱（`isolated-vm`）+ 资源限制有独立工作量，且它是不透明块，会绕过静态闸。P0 不开这个逃生舱口，倒逼 IR 表达力够用。
