| **parallel 的作用域模型** | 作用域帧是**整个 `VarSpace` 共享的一条栈**（`frames: Frame[]`），并发子步骤各自 `push`/`popTo` 同一条。于是两支并发时：A 支的 `popTo(depth)` 会把 B 支刚压的帧一起弹掉；`lookup` 从栈顶往下找，栈顶是谁决定读到谁的值。**已实测**：两支各带 `forEach{as:'item'}`，A 支的断言读到了 B 支的循环项值（`期望 1，实际 99`），B 支随后"变量未定义" —— 两支的 IR 写法都是最自然的那种 | **已修（不再是"临时盾牌"）**：每支一份局部作用域 —— `VarSpace.forkBranch(label)`（`engine/src/vars.ts`） **按引用共享 global 帧**、各自加一帧、各自一份 `stepExports` Map 与 `writes` 数组；继承的帧是**复制数组、帧对象按引用带走**， 所以写在 `forEach` 里的 parallel 仍然看得到那层迭代帧。收尾由 parallel 容器按**分支声明顺序**调 `adoptFrom`，并回**外层栈顶那一帧** （不是 global；用声明顺序而不是完成顺序是 M7 确定性的前提 —— 完成顺序会让同名由"谁先跑完"决定）。 合并判据是 `has()`（只看帧），不是 `knows()`：顺序执行时 `set token` 会遮蔽同名 env 变量， 用 knows 就会让同一步"写在 parallel 外生效、写进 parallel 里被静默丢弃" —— 同一份 IR 换个位置换语义。  **改造成本远低于本行原先的估计**（原话说要贯穿"36 处 `vars.` 调用"）：把闭包变量**改名**成 `rootVars`， 再给 `runStep`/`runChildren`/`dispatch` 加 `vars: VarSpace = rootVars` 就够 —— 改名让"漏改的站点"编译不过， 而不是静默读共享空间；`resolveValue`/`interpolate` 的 `vars` 是**必填、无默认值**，同一个理由。  **闸因此只剩一条判据**（两支写同一个名字），`frame-shadow` 那条已随根因一起删掉。 **本行原先记的"第三条漏判"（B 支 `set` 一个自己新声明的名字、值落进 A 支当时的迭代帧）就是这次修的**： 判据与对照组在 `engine/test/scope.test.ts`（含"另一支带 forEach"与"另一支只是 sleep"两半，后者是原缺陷的对照组 —— 只测坏的那一半等于把真正的自变量从测试里删掉），变异集 `tooling/mutate/scope.json`。 刻意**没有**为那个形态再加一条静态闸：那是"一支有循环 + 另一支新声明一个名字"，正是"并发各自收集结果、跑完统一断言"那个最常见写法， 拒掉它 parallel 就不能用了 —— **闸是盾牌不是修复，靠加规则追根因只会把它越收越窄**。  **仍未解决的两件事，别说成已闭环**： (1) 两支同名时是**拒**，不是"有解" —— 各支局部那份同名互不干扰（隔离了），但收尾只能留一份， 先声明者赢是确定的，**而确定的错答案比随机的错答案更难被发现**，所以宁可拒。 (2) `writtenNames` 是**过近似**（对分支的 JSON 取词，注释与同名字段都算），会误拒；当安全闸这是对的取向， 但它意味着"闸报了就一定是真竞态"不成立。  **lint 侧也接上了**（`engine/src/lint.ts` 的 `PARALLEL_VAR_RACE`，error 级）：判据直接 `import { parallelHazards } from "@atest/ir"`，与解释器同一份函数；`lint.test.ts` 里有一条把同一批 IR 同时喂给 `lintScenario` 与 `runScenario` 并断言逐个结论相同，专门拦"lint 侧自己抄一份判据"。 **它目前是撞名场景唯一能拦住 CI 的入口**，原因见下一行 |
