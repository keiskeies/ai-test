条/`）；**负向**断言（"不许多说"那一组）**不能用否定式正则** —— 否定式是 fail-open 的，措辞一改就永真，所以改成**逐字的特征化期望值**，并给"提示带不出现"那条补一个**正对照**（先证明判据在脏页面上成立，再要求在干净页面上不成立）。**否定式断言要么配正对照，要么改成等值的正向判据，否则它只是看起来在守。**<br>**(丁) 同一个字段有两条到磁盘的路，而测试只钉了其中一条 —— 本轮的密钥泄漏走的就是这个口子。** 脱敏有三条通路而不是两条：结构化那条按**字段名**判（`redactForDisk`，走 JSON），散文那条按**值形态**判（`redactSecretText`，走 HTML 正文 / XML 文本节点 / `summary.txt`）。改前的测试**全钉在 keyContext 那个结构化通道上**，于是散文通道从未被断言过；同一次 run 的实测形状是「`trace.jsonl` 干净，而 `report.html` / `junit.xml` / `summary.txt` 里的 `assertionSummary` 躺着真 JWT 与真 AWS key」。根因**不是规则表缺项**（规则表两边共用），而是**三个散文出口一个都没过值形态规则**。<br>**这一例的方法论要点不是"要多测几个出口"，而是"一条规则有几个序列化通道"这件事本身要数出来** —— 我当时想的是"脱敏有测试"，而那为真；它覆盖的是**另一条通路**。凡是"一条规则、多个出口"的东西（脱敏、转义、截断、单位换算、时间格式），判据要按**出口数**写而不是按**规则数**写：本轮那三个 chokepoint（`html.ts` 的 `esc`、`report.ts` 的 `xmlSafe` 与 `plainSafe`）各有一条变异守着（`tooling/mutate/prose-redaction.json`），漏一条就是那个出口从此没人守。<br>**顺带把"为什么这条规则能放在出口而不是放在拼句子的地方"这件事做实**：`advisories.ts` 刻意只排版不脱敏，因为它产出的文字会送进上面那三个出口、于是同一段话会过两遍规则。两遍**当前**是幂等的（有测试钉），但幂等是对脱敏实现的**假设**，把它当正确性依赖就是欠债 —— 所以那条"占位符自己命中某条规则"的变异（`expect` 是 caught）守的正是这个假设：占位符写法一旦撞上值形态规则表里的某一条，套娃文本只在**部分**出口上红。<br>等价变异（行为不变的改写）**照列**并标 `expect:"equivalent"`：它若变红，说明那条测试在钉实现细节而不是钉行为 —— **而"意外变红"本身还是个好用的污染探测器**（第 (d) 条就是靠它露馅的）。<br>**(戊) 我重写的代码，正是另一份变异集的锚点 —— 而 spec 与源码之间没有反向索引。** 本轮重写 `needsWeb` 的函数体时，我只看了它的调用点，没看 `tooling/mutate/*.json` 里有没有谁的 `anchor` 指着那一行；而 `ui-assert-world.json` 的 W5/W6 两条**正是**（它们盯的是"三层数组"这个行为，锚点写的就是被我换掉的那一句）。这种失效**不会以失败的形式出现**：驱动 `split(anchor).join(replace)` 找不到锚点时是恒等变换，"施加变异"等于什么都没施加，于是那两条永远"未被抓到"，而**"未被抓到"会被记成一个结论**（"这两条行为没被守住，去补测试"）—— 真相是它们压根没跑。本轮是 `tooling/test/mutate.specs.test.mjs` 那条"锚点必须在工作区的文件里出现"拦下的，也就是**靠仓库里已有的那道闸，不是靠我记得**。<br>**推论两条**：① **改一个函数之前先 `grep` 它的函数名/那一行在 `tooling/mutate/` 里出现没有**，就像改一个函数前 grep 它的调用点一样 —— 锚点是调用点的一种（它"调用"的是源码的**字面形状**）；② 这类"spec 指向代码的哪一行"的反向索引**今天只有 mutate.specs.test.mjs 那一道全量检查**，所以它不许被换成抽样，也不许在 CI 里被跳过。<br>(2) **判据尽量交给独立实现** —— JUnit 交给 CPython 的 expat、zip 交给系统 `unzip -t`，不要用同一份代码自证 | 每条关键断言问一句"实现坏了它会红吗"。答案是"应该会"的，去把它改坏一次 |
| **「登记一个做不到的前提，而它只是我没找到办法」这个缺陷类别** | 这一族与上面几行同源（都是"写下来的话比它保证的宽"），但它咬的不是代码也不是测试，**是后续决策**。形状：某一行写着"要修 X 得先有 Y（而 Y 拿不到）"，于是那一轮**跳过** X。本轮撞上的实例：`docs/14` §5 记着「填 `ctx.scenarioGraph` 要先把整棵调用图从文件系统扫出来，而 resolver 只解析得到被问到的那几个 ref」—— 我照这句话跳过了一整轮。真相是**反的**：环检测要的不是"全仓所有的边"而是**从入口可达的那些边**，而"resolver 只解析被问到的那几个"**正是让这件事可行的性质**。这种假前提特别难自持，因为它**看起来像在解释一个真实约束**（resolver 确实是惰性的、engine 侧确实没有 readdir 端口），而那个约束推不出"没法走闭包"。<br>**判据两条**：① 登记阻塞时，**"我没找到办法"与"没有办法"是两句话** —— 前者要写"下一条可能的路是什么、我为什么没走"，后者要写"我试到哪一步为止"；② 任何写着"这轮不做，因为缺 A"的行，**下一轮先花几分钟试一次最小的 A**（本轮那次是五分钟：现成的 resolver 加一个 BFS，`buildScenarioGraph` 一次写就）。假前提的存活期就是这么长：它落进文档之后与真前提**逐字相同**，而它挡住的那件事往往比登记它的那一轮更便宜 |
| **断言自动拆一层 `body`** | `assertions.ts` 里 `const body = value?.body ?? value` —— 断言对象是响应时自动拆一层 `body`，让 `$.id` 直接命中响应体的 id（90% 的断言因此更短）。代价：**响应体自己就有 `body` 字段时无法区分**"我要响应的 body 字段"和"整个响应体" | 已知取舍，有测试固定行为（`browser.test.ts` 里那条注释）。要消歧就得引入 `$..body` 与 `$.body` 的显式区分，或者规定 jsonPath 一律从响应体起算 —— 后者更干净，但会让所有既有写法整体位移一层，宜早不宜迟 |
| **多平台设备统一调度** | 安卓/iOS/鸿蒙共用一套租约与 agent 形态的可行性验证；Mac 池与 Linux 池混排的调度约束（`docs/09` §1.3） | 未写；契约已定，调度器未设计 |
