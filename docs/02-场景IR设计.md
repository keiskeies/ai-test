# 02 · 场景 IR 设计（Scenario Intermediate Representation）

IR 是整个平台**唯一的用例真相源**。可视化表、TS SDK、Agent 输出、执行器输入，全部围绕它。它同时也是静态闸（lint / dry-run / 覆盖预览）能成立的前提 —— 用例是结构化数据而非不透明脚本，才谈得上"AI 生成的东西能被机器把关"。

设计原则（每条都对应 `docs/00` 的一个坑）：

| 原则 | 反例 |
|---|---|
| **控制流节点显式存在**，不藏在脚本里 | Postman/Apifox 的循环只在 GUI 里，CLI 侧行为不明 |
| **每个等待都是条件而非时长** | `delay: 3000` = 一颗未来的 flake + 一次套件变慢 |
| **每个循环都有硬上限** | 无界 AI 循环 = 不可回放 + 成本失控（抄 Maestro `whileTrue:{max}`） |
| **断言是独立节点类型，不是脚本副产物** | 否则"无断言用例 lint"写不出来 |
| **变量引用是显式表达式** | 隐式 `${var}` 字符串替换无法做未定义检测与来源审计 |
| **模糊匹配是 id/时间戳/uuid 形态字段的默认** | LLM 从唯一样本过拟合字面断言 |
| **步骤是三类目标同构的** | 三端各一套模块 → 跨端传参只能人肉 |
| **每个生成用例钉 `{prompt_hash, model_id, seed, spec_hash}`** | 夜间跑出的 bug 复现不了 |

## 1. IR 顶层

```ts
// zod v4 定义，同时产出 JSON Schema / TS 类型 / OpenAPI（单一真相源）
Scenario = {
  schemaVersion: "1",
  id: string,                    // 稳定 id，与版本无关
  name: string,
  description?: string,
  tags: string[],
  targets: ("api"|"web"|"android")[],   // 由步骤推导，冗余存一份供检索
  mode: "script" | "agent",            // 显式切换（已确认决策）
  inputs: ParamDef[],                  // 上层输入：类型化 + 默认值 + 校验
  outputs: OutputDef[],                // 下层输出：显式声明要暴露什么
  env: {
    environmentRef: string,            // 环境名
    // 运行时解析为具体 env_revision 并记进 run；IR 里不写死值
  },
  setup: Step[],                       // 前置（登录/造数），失败=整个用例 error
  body: Step[],                        // 主体，失败=用例 fail
  teardown: Step[],                    // 默认必跑（含 data GC），失败单独标记
  config: {
    timeoutMs, maxCostUsd, retries: {count, backoff, retryOn},
    parallelGroup?: string,            // 同组内互斥（共享 fixture 时用）
    concurrencySafe: boolean,          // 数据驱动迭代间是否可并行
  },
  provenance?: {                       // 确定性边界（钉死）
    origin: "human"|"agent",
    promptHash, modelId, seed, specHash, generatedAt, caseVersion
  }
}
```

**`provenance` 与 `frozen` 是平台护城河所在**：CI 触发时若 `frozen=false`，引擎**拒绝执行**并报错"该场景尚未冻结，请在 Agent 工作台中冻结"。这一条把"Agent 对话入口"和"CI 门禁"安全地隔开。

## 2. 步骤节点全集（v1）

所有节点共享：`{ id, name?, when?: Expr, timeoutMs?, retry?, onError: "fail"|"continue"|"retry", retry?, tags?, note? }`。
`when` 守卫让**任何**节点可被条件跳过（抄 Maestro），因此不需要为每个分支单独包一层 `if`。

### 控制流
| kind | 关键字段 | 说明 |
|---|---|---|
| `sequence` | `steps[]` | 默认容器 |
| `if` | `condition: Expr`, `then[]`, `else[]` | |
| `switch` | `value: Expr`, `cases: {is, steps[]}[]`, `default[]` | 状态码分派常用 |
| `forEach` | `items: Expr`, `as: string`, `maxIterations: int`, `steps[]` | 数据驱动 |
| `while` | `condition: Expr`, **`maxIterations: int`（必填）**, `steps[]` | 上限必填，无默认值 |
| `repeat` | `times: int(≤1000)`, `steps[]` | |
| `parallel` | `steps[]`, `failFast` | 并发跑；引擎负责变量写入串行化 |
| `call` | `scenarioRef: id@version?`, `args: {..}`, `assignTo?` | 子场景 = 复用单元（抄 Karate `call` / Maestro `runFlow`） |
| `wait` | `condition: Predicate`, `timeoutMs`, `pollMs`, `onTimeout` | **见 §3，无 duration 字段** |
| `sleep` | `ms` | **存在但被 lint 警告**，逃生舱口用 |

### 变量与数据
| kind | 关键字段 |
|---|---|
| `set` | `assign: {varName: Expr}` —— 上游输出→下游输入的主要手段 |
| `extract` | `from: Ref`, `rules: [{var, path: JSONPath\|regex\|ariaText}]` |
| `table` | `rows: object[]`, `as`（默认 `'table'`）—— 内联数据驱动表（抄 Karate `table`） |
| `dataSource` | `source: {file\|mysql\|qdrant}`, `as`（默认 `'rows'`）—— 外部数据驱动 |
| `script` | `lang:"ts"`, `code`, `timeoutMs` —— 逃生舱口，跑在隔离沙箱（`isolated-vm`），**禁止 net/fs**，变量显式进出 |

### API
| kind | 关键字段 |
|---|---|
| `http` | `request: {method, url, headers, query, body, formData}`, `auth?: SecretRef`, `saveAs?` |
| `openapiCall` | `operationId`（或 `method+path`）, `docRef`, `pathParams, queryParams, body` —— **从 doc 解析 URL/schema 并做请求侧符合性校验**；这是"一句话导入 swagger"的落点 |
| `graphql` / `ws` | v2 再说 |

### Web
| kind | 关键字段 |
|---|---|
| `navigate` | `url`, `waitUntil` |
| `act` | `intent?: string`（自然语言，仅设计期用于编译定位器）, **`locator?: LocatorSpec`（编译产物，运行时用这个）**, `action: click\|fill\|select\|hover\|press\|scroll\|drag`, `value?: Expr` |
| `assertPage` | `kind: aria\|text\|visible\|count\|url\|title`, `expected` |
| `capture` | `mode: screenshot\|har\|pdf`, `on: "always"\|"failure"` |

### Android
| kind | 关键字段 |
|---|---|
| `device` | `require: {udid?\|model?\|androidVersion?}`, `leaseMs` —— **申请设备租约**（Redis 锁），后续步骤隐式继承 |
| `app` | `action: install\|launch\|stop\|clearData\|current`, `package` |
| `tap` / `input` / `swipe` / `key` | `target: LocatorSpec`, `value`, `mode: uiautomator\|scrcpy\|adb` |
| `assertUi` | `kind: exists\|text\|absent\|ariaYaml`, `target` |
| `watcher` | `rules: [{match, action:"click"\|"dismiss"}]` —— **步骤之间自动弹掉弹窗/权限/OEM 干扰**（抄 openatx `d.watcher`）。作用域是容器级，不是全局，保证可回放 |
| `logcat` | `filter`, `assertContains` |

### 通用
`assert`（结构化断言，见 §4）、`assertLlm`（语义判定，**不参与门禁**）、`db`（mysql 查询，`{sql, vars, assignTo}`）、`log`、`fail`、`noop`。

## 3. `wait`：把"等待"从时长改成策略

这是调研认定的第二个空白点（`docs/00` §4.2），所以给足设计。

```jsonc
{ "kind": "wait",
  "condition": {
    "anyOf": [                                    // 或 allOf / noneOf
      { "type": "httpStatus",  "ref": "step.orderCreate", "in": [200, 201] },
      { "type": "expr",        "expr": "$.step.q.result.rows[0].status == 'PAID'" },
      { "type": "dbRow",       "sql": "SELECT 1 FROM orders WHERE id=$id LIMIT 1", "expect": "row" },
      { "type": "uiPredicate", "target": { "by": "text", "value": "订单已完成" }, "state": "visible" },
      { "type": "uiIdle" }                        // Detox 式"app 空闲"门控
    ]
  },
  "timeoutMs": 15000, "pollMs": 500, "backoff": "exponential", "onTimeout": "fail" }
```

三条要点：
- **`dbRow` 条件是白送的差异化**（MySQL 已在栈里），而且解决的是"API 下单 → 异步落库 → UI 验证"这条最常见跨端链路的等待问题。
- `uiIdle` 对安卓尤其关键：动画没结束就断言是 flake 主要来源。
- IR 里**没有** `wait.duration` 字段。需要干等只能显式写 `sleep`，而 lint 会给 warning（`SLEEP_USED`）。

## 4. 断言：结构化优先，模糊默认，语义不参与门禁

```jsonc
{ "kind": "assert",
  "against": "$.step.list.resp",
  "match": {
    "status": 200,
    "durationMs": { "lte": 3000 },
    "jsonPath": {
      "$.data.list":      { "isArray": true, "minLength": 1 },
      "$.data.list[0].id":{ "matches": "^[0-9]{1,19}$" },   // ← 不写字面值
      "$.data.list[0].createdAt": { "isIso8601": true },    // ← 不写具体时间
      "$.data.total":     { "notNull": true }
    }
  } }
```

**模糊标记是默认，精确要 opt-in**（对应 Karate `#ignore`/`#notnull` 的存在理由）：引擎提供 `generators.shapeAwareEq(sample)` —— 从样本响应生成 matcher 时，id/uuid/timestamp/金额/浮点形态字段自动降级为类型/模式断言，而**精确相等必须在 IR 里留下 `exact: <literal>` 痕迹**，于是"AI 过拟合了一条字面断言"这件事在 IR diff 里肉眼可见。

语义断言独立且降权：
```jsonc
{ "kind": "assertLlm",
  "question": "页面是否显示用户已登录状态",
  "evidenceFrom": "$.step.home.aria",       // 必须给证据来源
  "requireEvidenceQuote": true,              // 模型必须回引原文 + 坐标
  "gatePolicy": "report-only" }              // 默认永不影响 pass/fail
```
两条硬规矩：① `assertLlm` 默认 `report-only`，要参与门禁必须显式改 `gatePolicy: "blocking"`（且 UI 上要二次确认）；② **同一个模型不得在同一步既执行又判定**（judge 用不同 model/prompt，不共享 scratch）。视觉模型倾向过度报告"存在"，所以否定断言（"对话框没出现"）一律走结构化路径。

## 5. 表达式与变量空间

三套语法，各有明确边界（**别用一套隐式字符串插值打天下**，否则未定义变量检测与来源审计无从下手）：

| 语法 | 用途 | 例 |
|---|---|---|
| **JSONPath** (`$.`) | 取单个值 | `$.step.login.resp.data.token` |
| **JSONata** | 计算/变换/聚合（比 jq 更适合嵌入，纯函数、无副作用、有浏览器实现） | `$sum($.step.list.resp.data.list.($.price))` |
| **TS 沙箱** | 逃生舱口（`script` 节点） | 只能显式 `input`/`output` |

变量作用域（内层遮蔽外层，退出即销毁）：
```
run.inputs                    # 上层输入（外部传入，类型化）
  ← scenario.inputs           # 场景自身输入
    ← forEach.as / call.args  # 迭代与子场景
      ← step.exports          # extract / set / saveAs 产出
run.outputs                   # 显式声明的下层输出（子场景返回值 / 报告顶层字段）
env.<name>                    # 只读，运行时按 env_revision 解析
secret.<ref>                  # ⚠ 只能被引擎解析，永不进入 Agent 上下文
```

**`secret.*` 的机制要保证**：变量空间对 Agent 暴露时，`secret.*` 解析为不透明占位符（引擎在发请求那一刻才替换成真实值）；`runs`/`trace`/`llm_calls`/日志全部按字段名规则在**存储时**脱敏。理由很硬：**Agent 能读到密钥，就能把它 echo 进生成的用例正文里提交上去。**

## 6. LocatorSpec：把 LLM 变成一次性"定位器编译器"

`docs/00` §5.1/§5.2/§5.8 的落地物。**一份 ARIA 快照同时干三件事**：模型的世界观、断言对象、自愈指纹。

```jsonc
"locator": {
  "intent": "点击右上角的提交按钮",          // 设计期意图，运行时不用
  "primary":  { "by": "role+name", "role": "button", "name": "提交" },
  "fallbacks": [
    { "by": "testid",  "value": "submit-btn" },
    { "by": "css",     "value": "form > button[type=submit]" },
    { "by": "anchor",  "near": "合计", "side": "right" }     // "Total 右边那个" 抗 DOM 重构
  ],
  "fingerprint": {
    "ariaSubtreeSha": "sha256:…",           // 子树变了才触发自愈（避免陈旧命中）
    "textExpected": "提交",
    "bboxHint": [0.82, 0.05, 0.09, 0.04],   // 归一化，仅提示不做断言
    "recordedAt": "…"
  },
  "confidenceGate": 0.85,
  "maxCostUsdPerResolve": 0.02
}
```

**优先级阶梯（便宜 → 贵，逐级走，置信度达标即停）**：

```
1 testid / 人工钉住                      0 cost      ← 最便宜也最被忽视：让 app 侧加 data-testid
2 记录 CSS + text + aria 指纹加权打分 ≥ 阈值   0 cost      (Testim 式多属性指纹)
3 anchor「在 X 附近」                      0 cost
4 a11y role+name                         0 cost
5 缓存的 LLM 选择器（用前校验）              0 cost hit / 1 call miss
6 observe() 重新枚举候选                    1 call      ← 设计期产物被复用的地方
7 Set-of-Mark 视觉（编号框，要"第 17 个"）     1 vision call
8 纯视觉坐标                                1 vision call  ← 标记为「不可回放」，永不进 CI
```

配套三件不可省：
- **陈旧命中校验**（比 miss 更危险）：用前验 exists + visible + 文本/嵌入相似度；`ariaSubtreeSha` 变了立即失效。否则改版后"成功"点了错的元素。
- **列表近重复保护**：要求唯一性 + 打分差值（否则每行都 0.97，静默选错）。
- **自愈 = 软失败 + 审校队列**：步骤标记 `healed`（可见、不算绿）→ 要求一次未自愈重跑才毕业 → 提 old→new 定位器 diff 给人审。**静默自愈生产"绿色构建点错按钮"**。同时 `locator_stats.heals` 排名就是你的维护积压清单——把"AI 不靠谱"变成"定位器 #487 本周自愈 31 次，点一下钉住它"，这是能卖人的指标。

安卓侧对应物：`by` 支持 `resource-id` / `content-desc` / `class+index` / `text`，指纹用 **uiautomator hierarchy 子树**（安卓的 a11y 树类比）。a11y 树为空的场景（Flutter/canvas/Unity）降级到模板匹配（Airtest 式）或 `appium-flutter-finder`。

## 7. 静态闸：IR 能被机器把关的全部收益

`engine lint <ir>` —— AI 生成的 IR 必须先穿过它：

| 规则码 | 检查 | 级别 |
|---|---|---|
| `ASSERT_FREE_STEP` | 零断言且无下游 `extract` 消费者 → no-op 步骤 | **error** |
| `ASSERT_FREE_SCENARIO` | 整个场景无任何断言 | **error** |
| `SLEEP_USED` | 用了裸 `sleep` | warning |
| `LOOP_UNBOUNDED` | 循环缺 `maxIterations`（schema 已必填，防手工绕过） | **error** |
| `VAR_UNDEFINED` | 引用未定义变量（含作用域解析） | **error** |
| `DEPENDENCY_CYCLE` | `call` 依赖成环 | **error** |
| `LITERAL_OVERFIT` | 精确相等断言命中 id/uuid/时间戳形态字段 | warning（提示改模糊） |
| `HARDCODED_SECRET` | 疑似密钥字面量（正则 + 熵） | **error** |
| `RESOURCE_LEASE_MISSING` | `adb` 步骤前无 `device` 租约 | **error** |
| `TEARDOWN_DIRTY` | 有写操作但无 `teardown`/GC | warning |
| `CROSS_TARGET_MISSING_WAIT` | API 写 → UI 读之间无 `wait` | warning |
| `STEP_BUDGET_EXCEEDED` | 预估 `maxCostUsd` 超项目上限 | warning |

再加**覆盖增量预览**（直接打击过度生成，`docs/00` §6.1）：新增场景前先算"这些用例新增覆盖了哪些 `接口 × 错误类别 × 参数等价类` 组合"，若增量为 0 就提示"建议合并/删除"。同类用例还能用 Qdrant 用例指纹去重。

## 8. 双向同步怎么不翻车（P2）

IR 是唯一真相，**不做 TS 源码 AST 反解**（那是"双向同步"最经典的自杀路径：一旦源码能写 IR 表达不了的东西，两份真相就开始漂移）。做法：

```
TS SDK  = IR 的类型化 builder。 .build() → IR（唯一产物）
          builder 链本身可由 IR 机械还原（每步一一对应，无语法糖分支）
可视化表 = IR 的表单视图（JSON Schema 驱动 + 少量手写复杂节点编辑器）
流程图   = IR 的只读投影（复杂嵌套降级为折叠块，不承诺画布反解）
Monaco   = IR 的 JSON 文本视图（逃生舱口）
```

推论：**TS SDK 能力天花板 = IR 能力天花板**。这是有意为之 —— 任何新能力先加 IR 节点再加 builder，防止"只有 SDK 能写、GUI 看不见、lint 管不到"的暗物质用例。IR 里的 `script` 节点是**唯一**不透明块（内部是代码），对它单独处理：GUI 显示为只读代码块 + 显式 `input`/`output` 契约，diff 时按内容 hash 呈现。

## 9. IR 片段：三端共享变量空间（终局验收用例）

```jsonc
{ "schemaVersion":"1", "name":"API 造订单 → APP 验证展示", "mode":"script",
  "targets":["api","android"],
  "inputs":[{"name":"sku","type":"string","default":"SKU-1"}],
  "body":[
    { "kind":"device", "require":{"androidVersion":">=12"}, "leaseMs":300000, "id":"dev" },
    { "kind":"watcher", "id":"w", "rules":[
        {"match":{"text":"允许"},"action":"click"},
        {"match":{"textContains":"以后再说"},"action":"click"} ] },
    { "kind":"app", "action":"clearData", "package":"com.acme.shop" },
    { "kind":"app", "action":"launch", "package":"com.acme.shop", "id":"launch" },

    { "kind":"openapiCall", "operationId":"createOrder", "docRef":"shop-api@v3",
      "body":{"sku":"$.run.inputs.sku","qty":1}, "id":"mk",
      "assert":{"status":201,"jsonPath":{"$.data.orderId":{"matches":"^ORD-[0-9]{8}$"}}} },

    { "kind":"wait", "id":"settled",
      "condition":{"allOf":[
        {"type":"dbRow","sql":"SELECT 1 FROM orders WHERE id=$.mk.resp.data.orderId","expect":"row"},
        {"type":"uiIdle"} ]},
      "timeoutMs":15000, "pollMs":500, "onTimeout":"fail" },

    { "kind":"tap", "target":{"intent":"底部「我的」标签"}, "id":"mine" },
    { "kind":"tap", "target":{"intent":"「我的订单」入口"}, "id":"orders" },
    { "kind":"assertUi", "id":"verify", "kind":"text",
      "contains":"$.mk.resp.data.orderId",
      "before":{"kind":"capture","mode":"screenshot","on":"failure"} }
  ],
  "teardown":[
    { "kind":"openapiCall", "operationId":"cancelOrder", "args":{"id":"$.mk.resp.data.orderId"} }
  ],
  "config":{"timeoutMs":120000,"maxCostUsd":0.05,"concurrencySafe":false} }
```

这条就是 `docs/00` §4.1 认定的第一空白点：**现有平台上写不出来，因为它们的 API 模块和移动端模块没有共享变量空间。** 在 IR 里它只是一句 `$.mk.resp.data.orderId` —— 差异化的成本极低，这正是该优先做它的原因。
