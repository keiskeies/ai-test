# 1C 演示手册（业主版 · 25 分钟）

> 目标：亲眼看一遍 1C 新增的那条链——**建元素 → 拼一条 UI 用例（命令列表）→ 真浏览器调试
> → 正式执行进报告中心 → 报告里逐命令看结果与截图 → 把这条用例当一步拖进场景混着跑**。
> 全程离线可演示：被测页面是仓库自带靶场的 UI 页（`http://127.0.0.1:9999/ui/login`），
> 不需要任何 API Key、不需要外网，浏览器用的是 Playwright 自带的 chromium。
>
> **与 1B 手册的关系**：装环境那套（§0-§4）与 1B 完全通用，跑过 1B 的机器只需补 §0.2 的
> 浏览器安装，然后直接从 §5 开始。1B 的「必须起 Celery worker」这条在 1C 同样必须——
> UI 用例的**正式执行**走的也是 worker（§5.8）。

## 0. 前置

### 0.1 与 1A/1B 相同的部分

MySQL 8.x + Redis 7.x、Python 3.12（`backend/.venv` 已就绪）、Node 22 + pnpm 10（`web/`）、
`backend/.env` 配置——**逐条照 1B 手册 §0 做，一字不改**（Redis 在 1C 仍是硬依赖：
它既是 Celery broker，也是执行事件总线）。

### 0.2 1C 多出来的那一件：浏览器（约 1 分钟，只做一次）

```powershell
cd web
pnpm exec playwright install chromium
```

- **为什么这条要在前端目录跑**：后端 `playwright==1.65.2` 与前端 `playwright-core@1.65.1`
  的 chromium revision **是配对的**（两边都指向 chromium-1255），装一次两边共用同一个
  `~/AppData/Local/ms-playwright` 缓存。版本配对由 `backend/tests/test_ui_deps.py` 逐字比对
  两个 `browsers.json` 钉住（R97）——**别把后端的 `playwright==1.65.2` 改成 `>=`**，
  改了某天就会去下第二份 chromium，而界面上只会显示「浏览器启动失败」。
- 装没装成功，最直接的验法是 §5.7 点一次「调试」：起不来会明说
  「浏览器启动失败（检查 chromium 是否已装，或配 TP_UI_BROWSER_CHANNEL=chrome/msedge
  用系统浏览器）」，并把这条用例的每条命令标成「浏览器未启动，未执行」，不会假装跑过。
- **机器上装了 Chrome/Edge 又不想下载 chromium**：给后端进程设 `TP_UI_BROWSER_CHANNEL=chrome`
  （或 `msedge`），执行核改用系统浏览器。两条路都通，演示用哪条都行。

## 5. 演示路径（25 分钟，照着点）

> 每节末尾的「你会看到」都是**在真浏览器里量出来的判据**（演示库 + 真 worker）。
> 对不上就跳 §7 排查。下面的数字（行数、徽标、毫秒）是本轮实测值，你重跑可能差几十毫秒，
> 认「事实」不认「死数字」。

### 5.1 元素库：资产长什么样（3 分钟）

左侧「UI 测试」→「元素库」。

你会看到：左树两个节点——`全部元素` 和 `UI 演示`，后者徽标 **5**；右边列表 **4 行**
（工作台标题 / 登录页口令框 / 登录页账号框 / 登录按钮），底部写「共 4 条」。
**徽标 5 而列表 4 行不是坏了**：徽标是「这个模块下未回收的**元素 + UI 用例**合计」
（那条演示用例也在这个模块里），鼠标移到徽标上有一行说明写着这件事。列表只列元素，
所以有用例时徽标必然比行数大（选中某个模块后底部会变成「共 N 条（选中模块）」）。
列是：名称 | 定位方式（彩色徽标，`id` 绿 / `css` 蓝 / `xpath` 紫 / `text` 青 / `name` 橙）|
定位表达式（**超长会省略，hover 有全文和一个复制按钮**——定位表达式经常长到读不完）|
关联用例数 | 更新时间 | 操作。搜索框打「登录」，列表立刻剩 3 行，底部跟着变「共 3 条」。

### 5.2 新建一个元素，然后试着删一个正在被用的（4 分钟）

1. 右上角「新建元素」：名称填 `订单表慢行`，类型下拉只有 **5 种**（`id / css / xpath / text / name`），
   选 `css`，表达式填 `#late-row` → 创建。行立刻出现在列表里（如果左树选中的是 `UI 演示`，
   它会归到那个模块下，徽标 +1）。
2. 找到 `登录按钮` 那一行 → 点回收（垃圾桶图标）→ 确认。

你会看到：弹的不是「删成功」，而是**「删除被拦截：还有 UI 用例在用这个元素」**，
里面逐条列出**是哪条用例、第几步**（本轮实测：「演示：登录工作台 第 4 步」），
并写明「先解引用再来」。点「知道了」，那一行还在原处，库里也没动。
**这条硬拦在回收和彻底删除两个出口都有**——物理删除会让引用它的用例永久指不到定位目标。
3. 换一个没被引用的（刚建的 `订单表慢行`）：回收 → 它从列表消失 →
   点左树上方「回收站」切进回收站视图 → 「恢复」→ 切回来它又在了。
4. 在回收站里对它点「彻底删除」。

你会看到：弹窗要求**逐字输入元素名**才能点确认——多一个空格都不行
（本轮实测：填 `订单表慢行 ` 带个尾空格，按钮仍是灰的）。服务端同样硬校验，
绕过界面直接调接口也一样被拒。

**顺手演「模块删了元素不陪葬」**：新建模块「登录页」→ 在它下面建子模块「表单」→
子模块里建个元素 → 把「表单」回收 → 在回收站里「彻底删除」它。
提示语是「已彻底删除 1 个模块，**1 个元素转为未分类**」——元素还在，只是归到未分类。
如果那个模块里还挂着 UI 用例，这句会连着说第二件事
（「…，1 条 UI 用例转为未分类」），谁也不会被静默吞掉。

### 5.3 UI 用例列表 + 命令列表编辑器（4 分钟）

左侧「UI 用例」→ 点「演示：登录工作台」进详情。

你会看到：列表六列——名称 | 优先级 | 启用 | 最近结果 | 负责人 | 更新时间，
底部写「共 1 条 · **「最近结果」只记正式执行（调试是过程，不回写结论）**」；
负责人那一列是**名字**（「演示项目管理员」），不是 uuid。
**「启用」这一列要说清它现在算什么**（本期口径，别当成开关演示）：它是蓝图 §11.5.4 点名的
列表列，读的是库里的 `enabled`，但**界面上没有任何地方能改它**（详情页没有这个开关），
执行链也**不看它**——实测把它 `PATCH` 成 `false` 之后 `POST /run` 照样建 run 照样跑。
所以本期它是「后端有这个字段」的如实展示，**不是「停用就不会被跑」的承诺**。
要不要让「停用」真的挡住执行（以及要不要给列表一个开关），留给业主裁（D7）。
详情页顶部是 `用例名 | 优先级▾ | 环境▾ | 保存 | 调试`，下面是命令列表，6 行：

```
1  打开      打开 ${base_url}/ui/login
2  输入      输入 demo → 登录页账号框
3  输入      输入 demo123 → 登录页口令框
4  点击      点击 登录按钮
5  断言文本  断言文本 工作台
6  等待元素  等待元素 css:#late-row
```

每行 = 序号 + 图标 + 命令名 + **关键参数摘要**（引了哪个元素、输了什么、断言什么，
不用展开就读得出这条命令在干什么）。点行展开参数区；行右侧 `···` 菜单里是
「在这一行后插入… / 复制（duplicate）/ 复制到剪贴板 / 粘贴到后面（剪贴板为空时禁用并写明为空）/
删除该行」；
工具条上有「+ 添加命令」「按命令名筛选（筛选态禁拖）」、一个「剪贴板: 粘贴(N)」按钮
（**剪贴板为空时这一组根本不渲染**——它不是系统剪贴板，刷新即清空，界面也这么写），右侧一个脏标记
（「与库一致」/「有未保存修改」）。拖一行换序、加一条命令，脏标记立刻亮，
**不保存就离开不会被偷偷存掉**。

### 5.4 参数区：元素从库里选，也可以就地建、就地定位（3 分钟）

展开第 2 行（输入 demo 到账号框）。

你会看到参数区有这几样：命令 id（灰的、旁边写着「id 不可改」——它是运行记录里对行的钥匙，
改了历史报告就找不到对应命令）、类型▾、
**定位方式二选一（`元素库` / `就地定位`）**、参数值（这里是 `demo`）、超时（ms）、
**失败继续**勾选。选「元素库」时是一个可搜索的下拉（每一行和选中态都显示成
`登录页账号框` + 灰色小字 `id:account` 这种带定位提示的样式）；**你在这条命令上选中过
元素之后**，它下面才会出现一排「最近使用」（记在浏览器本地，换台机器或清缓存后第一次
来是空的——它不渲染，不是坏了），旁边还有一个**「就地新建元素」**入口：
名字和定位表达式当场填，建完直接选中，不用离开这条命令去元素库转一圈。
选「就地定位」则出现类型 + 表达式两个框——第 6 行 `等待元素` 用的就是这个
（`css` + `#late-row`），它故意不进元素库：那条是这一条用例独有的等待点，
进库反而是垃圾资产。

### 5.5 五种命令现在还做不了，界面上不假装能做（1 分钟，讲给评审听）

1. 点「+ 添加命令」下拉，搜「上传」「下载」「切frame」「切窗口」「处理弹窗」。

你会看到：**搜不到，一条都不出现**——插进去就是一条存不了的命令，所以它不进可插入清单。
2. 反过来：在已存在命令的参数区把「类型」下拉点开，再搜「上传」。

你会看到：这次它**出现但是灰的**，标签写着「上传（要到 1C+ 批次才开放）」，
悬停有原因（文件选择 / 下载目录监听 / frame 与窗口句柄生命周期 / 原生弹窗处理各需要独立机制）。
两个位置的口径不一样是刻意的：**新命令不给选，老数据里如果混进来了要看得见它坏了**
（保存会被后端 422 拒，界面同时列本地预检问题）。同理，定位方式就是 5 种，
**没有第 6 种**——蓝图 §4.4 表列 5 个、§6.3 写「六类型」自相矛盾（R100/D2），
一期按表做，第 6 种请业主点名（候选 `placeholder`）。

### 5.6 调试：真浏览器跑一遍（3 分钟）

1. 什么都不改，直接点顶栏「调试」。

你会看到：底部面板升起（默认高 300，边缘可拖 120~60vh），先写
「真浏览器正在跑（**无头** Playwright 打靶场，一轮几秒到十几秒）……」，
逐条命令出状态与耗时，最后一条 `等待元素` 约 **3.4 秒**——那 3 秒是靶场定时器
真把 `#late-row` 插进 DOM 的时间。面板顶部有一条说明：
**「调试跑的是已保存的命令序列」**，草稿有改动时会写「本次发起前已代为保存」。
2. 面板标题行有「查看报告」，右侧一个「运行中 → 通过」的状态标和总耗时。

你会看到：点它**直达这一次运行的报告**（`#/reports/<run_id>`，那一行触发列写 `✎ 调试`，带空格）。
注意它和「报告中心列表默认能不能看到它」是两件事：列表**默认过滤掉调试**，
右上角打开「含调试」开关后这些行才出现（触发列都是 `✎ 调试`），直链则随时打得开。
**调试是过程不是结论**，通过率不能被试出来的东西污染（1B §6.3 同一条）；
想按触发来源单独筛，列表右上「触发」筛选里有「调试」这一项。

**这里有一处与蓝图不同的地方要说在前面**：蓝图和 1B 的调试语义是「跑屏幕上那份草稿」，
而 UI 用例的调试入参只有 `{project_id, case_id}`——**跑的是库里已保存的序列**。
前端的兑现方式是：草稿脏了先保存再跑，并且**在面板和 toast 里都写明这件事**，
不静默代存、也不演「跑了没存的东西」。

### 5.7 正式执行：界面上没有「执行」按钮，这是口径不是漏做（3 分钟）

**先把这句讲清楚再演示**：UI 用例详情页顶栏只有 `环境 | 保存 | 调试` 三个按钮，
**没有第四个「执行」**。蓝图 §11.5.4 与本计划 T17 点名的就是这三件（R119）。
所以要跑出一条**正式运行**（`trigger=manual`，进得了报告中心）有两条路：

**路 A（推荐，顺带演混合场景）**：把这条用例当一个步骤放进场景里跑（§5.9）。

**路 B（直连接口，给评审看后端事实）**：

```bash
curl -X POST http://127.0.0.1:8320/api/v1/ui-cases/<用例id>/run \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"project_id":"<项目id>","case_id":"<用例id>"}'
```

你会看到：回 `{"run_id":"…","status":"queued"}`，几秒后「报告中心」多一行
「演示：登录工作台 / ▶手动 / 通过 / 100% / **步骤 6** / ~3800 ms / 本地靶场」。
用例列表的「最近结果」也跟着变绿（**只有正式执行回写这一列**）。

**不许在这里摆一个假「执行」按钮**（§13 纪律 1）。要跑就是这两条真路。

**一个必须知道的坑（worker 没起会怎样）**：`run` 接口探的是 **Redis broker 通不通**，
不是「有没有 worker 在听」。Redis 起着、worker 没起时，接口照样回 `200 queued`，
然后**那条 run 永远停在「排队中」**（本轮实测过：投完不开 worker，12 秒后仍是 queued；
起 worker 后 4.4 秒跑完）。看到 queued 不动，先去看 §4.2b 那个进程在不在——
**这是唯一的出路**：界面上没有「撤销这条 run」的按钮（取消那颗只在场景编辑器里、
且只在本地这轮正跑着的时候出现），后端取消接口也只是**插一面旗**，
执行侧在步骤边界读到旗子才落终态，worker 没起就没人读旗（实测对它发取消回 `200`，
状态仍是 `queued`）。所以别把取消当清道夫：**把 worker 起来，它接走后自己会停在「已取消」**。

### 5.8 报告详情：一条 UI 运行长什么样（4 分钟）

报告中心 → 点开那条 UI 运行。

你会看到三栏：

## 6. 三个「为什么长这样」

**6.1 为什么只有无头，界面上没有「有头」开关**
执行核默认 `headless=True`（配置项 `TP_UI_HEADLESS`），**界面上没有开关**（D4）。
理由：有头模式在一台跑着 worker 的机器上意味着「凭空多出一个会抢焦点的浏览器窗口」，
定时任务更没人在屏幕前看着；而业主真正想看的「跑到哪一步了」由 §5.8 报告里的
**逐步截图**给。要真看界面，把靶场页面自己开着对照即可。不做假开关。

**6.2 为什么 UI 命令不能单步重跑（而 1B 的场景步骤可以）**
1B 的单步重跑靠的是「从这一步落库的快照重建上下文，重发一次请求」——
HTTP 是无状态的，重建得出来。UI 命令的上下文是**浏览器此刻的状态**（在第几个页面、
登录了没、DOM 里有什么），一条命令的快照重建不出那个现场。
所以 UI 报告的「失败步骤重跑」对命令行是灰的，只有场景步骤能点（R103）。
**宁可少一个按钮，不给一个跑了结果不可信的按钮。**

**6.3 为什么 UI 用例页没有模块树（元素库有）**
元素的天然组织维度是「页面/区域」，一棵树值得；UI 用例在 1C 只有一种组织需求——
按场景找。后端其实**支持**给用例挂模块（`module_id` + 那棵树就是第三棵树），
但本期详情页没有「改归属」的入口，列表页也没有左树，所以**种子里那条用例的模块归属
在界面上看不到也改不了**（只有徽标会把它算进去，见 §5.1）。
这是本期口径，不是缺陷藏起来；要不要给 UI 用例配一棵和元素库同款的树，留给业主裁。

## 7. 常见问题

**Q：点调试报「浏览器启动失败」。**
A：chromium 没装（§0.2 那条命令），或改设 `TP_UI_BROWSER_CHANNEL=chrome`/`msedge` 用系统浏览器。
它不会假装跑过：那条用例每条命令都会标「浏览器未启动，未执行」。

**Q：正式执行的 run 一直停在「排队中」。**
A：worker 没起（§5.7 那条坑）。`run` 接口只探 Redis，探不出「有没有人在听队列」。
把它起起来是唯一出路——界面上没有撤销这条 run 的按钮，取消接口也只是插旗，没人跑就没人读旗。

**Q：点场景「执行」报 503 executor_unavailable。**
A：这个才是「broker/worker 没起」的显式报错（1B §6.2 同一条），照 §4.2b 起进程。

**Q：徽标写 5，列表只有 4 行。**
A：正常。徽标是「元素 + UI 用例」合计，列表只列元素；hover 徽标有说明（§5.1）。

**Q：删元素被拦，可我找不到是哪条用例在用它。**
A：拦截弹窗会列出来（含第几步）。如果你没有 UI 用例的读取权限，它只报数量不报名字，
并明写「你没有 UI 用例的读取权限……请让有用例权限的同事解引用」——数量照报、明细隐瞒是刻意的。

**Q：报告中心最上面那条 UI 运行怎么是「已取消」？**
A：那是本轮取证留下的真行（一条投出去没人接、后来被 worker 接走时已带取消旗的 run），
留着当 §5.7 那个坑的实物教材。它的形状也顺便演了「取消在步骤边界生效」：
命令树里 `d1` 标 **已取消**、`d2`~`d6` 标 **跳过**，通过率 0%、耗时 310 ms。
注意概览卡那行统计是「**过 0 · 败 0 · 跳 5 · 错 0**」——**它不写「取消 1」**，
所以四个数加起来会比命令数少 1（少的那条就是 `d1`），这不是坏了，是这行统计目前只画四档；
已取消不等于一行都没跑，跑过的步骤该留就留（同 1B §5.6 那条）。
你按 §5.7 重跑会看到它上面压一条新的「通过」。

**Q：报告中心看不到刚才的调试。**
A：设计（§5.6）。开右上角「含调试」，或去「运行记录」。

**Q：改了前端源码页面没变。**
A：preview 吃的是 `dist`，改完要 `pnpm build`（开发模式 `pnpm dev` 同样要设 `TP_BACKEND`）。

**Q：跑 pytest 时 celery 那条 golden 用例超时。**
A：~~你为演示常驻的 worker 把测试的任务抢走了，停掉再跑（§5.12 / R118）。~~
自 1D T0 起这条答案过期：队列已按 `TP_ENV` 分道（D10），演示 worker（`tp.dev`）领不到
pytest 投的 `tp.test`。若还超时，先看 Redis 是否可达、worker lane 是否匹配——不再是抢队列。
