## 一、这一刀的边界：只做「用例本体」，评审**不做**

127 端点是**两件事**的合计：用例本体（约 89）+ 用例评审（约 38）。本切片**只做用例本体的最小闭环**，
评审整块推后，理由不是工作量，是**依赖方向**：

- 评审的承重结构是「用例 ↔ 评审 的关联行 + 行级状态 + 结论历史」（MS 侧取证见
  `backend/.tmp/d-case-review/ms-survey.md` §A/§B：一条用例可同时在任何多个评审里，主表那个
  `review_status` 是**全局单值**，靠「刷成更新时间最晚的那条关联」消歧）。
  **没有用例本体就没有评审**。反过来不成立。
- MS 自己那三个「没接上的环」**全在评审侧**（取证 §C）：快照归档表全仓零 insert、
  `ARCHIVED` 状态零写入方、评审 status 四态的**唯一推导器在异步事件里按关联行计数重算**
  （聚合与事实表漂移是设计内风险）。**这一格我们目前没有地基去复刻，也没有必要复刻它的病。**

**明确不做**（登记，不是遗漏）：评审、脑图（依赖用例库且 MS 用独立组件）、需求关联（MS 走插件）、
跨类型用例/缺陷关联、附件与文件库、前后置关系图、关注人、收藏、AI。

**「收藏」这一条要特别记一句**：MS **不存在收藏**（backend + frontend 两遍 grep `favorite`/收藏
零命中），关注人即全部。我们这边同样零命中。所以以后任何人提「给用例加收藏」时，
**那是原创项、不是「跟 MS」**——这条口径与 §3 对 UI/ADB 那 50 端点写死过的那条同类。

## 二、GPLv3 边界（本刀自查过）

MS 侧取证只取**语义与数据结构**，表名/类名/目录一律自拟。已核过的红线：
MS 的功能用例主表叫 `functional_case`（+ `_with_blob` / `_blobs` / `_review` / `_review_case`
等一系列），**我们不复用这些名字**；本刀实际表名在 §三 定。MS 的自定义字段是**经典 EAV**

## 三、我们这边的地基实测（MS 取证看不见的另一半）

只读现查（本轮，不是记忆）：

| 依赖 | MS 侧 | 我们侧实测 | 结论 |
| --- | --- | --- | --- |
| 模块树 | 用例有**专用**模块树（与评审树是两棵） | **已有 4 份同款**：`api_module` / `scenario_module` / `ui_module` / `adb_module`（各模块 `models.py` 现读 `__tablename__`），且各带一份 `module_services.py` | **可复用形状**，第 5 份照 `ui_module` 长法写，不要试图合并四份（合并会动已交付面） |
| 模板 / 自定义字段 | 承重：`template_id` **必填**，EAV 值表，列表页每页多 3~4 条查询，最脏的读路径是 SQL 内 `concat('custom_single-', field_id)` 子查询（非 sargable） | **全仓零命中**（`grep -rln 'custom_field\|template_id' app/` 只命中两处无关文本） | **本刀不做**。没有模板系统就别假装有用例模板 —— 那是 §六 1「有 schema 没写入方」的原地复刻 |
| 附件 / 文件库 | 11 端点，独立子域 | 零 | 不做 |
| 评审 | 见 §一 | 零 | 不做 |
| 环境 | 用例本体无环境列 | 我们**已有** `env` 模块（D181 用过） | 用例本体**不挂** env（执行时环境是计划关联行的事，D183 步 2 已定；两者别混） |

**这张表就是「最小闭环为什么这么小」的答案**：MS 那 89 条用例端点里，一大半挂在我们**根本没有
地基**的子系统上（模板/EAV、附件、关系图、脑图、需求、导入导出任务）。硬接的后果不是功能少，
是**造出一批永远为空的列和永远 404 的入口**，那正是判据 1 与 §13 纪律 1 双双禁止的东西。

## 四、第一刀的形状（一个可提交的最小刀）

1. 迁移 **0026**（本轮**不占**；§三 表名定了、写路径想清了再占，别先占号再想形状）+ 自拟表名的
   用例本体表：随机 id + **项目内 num**（MS 是这个形状：随机主键 + 项目内递增编号，
   编号是人看的、id 是给机器看的，两者不可混用）、`ref_id`（版本族初始行）与 `version_id`
   **本刀不做**（见 §五 那条「MS 自己的多版本行没接上」）、`status`（normal/回收站）、
   标题、优先级、备注、模块外键、创建/更新人 + `TimestampMixin`。**逐列答得出「谁写、谁读」**。
2. CRUD 四服务 + 回收站两条（进回收站 = 置标志位、恢复 = 改回、硬删 = DELETE；
   **不建独立回收站表** —— MS 没有，回收站只是 `deleted` 标志位上的一个视图查询）。
3. 模块树第 5 份 + 徽标计数（口径照 D47-b：徽标与列表同刀改，不许「徽标写 3 列表出 7」）。
4. 页码制列表（D47-b 全套形状：只做 `current`、不挂 `cursor`、双参 400、越末页空 items + 真 total、
   两制共用同一条排序表达式）。
5. 权限位：新位组自拟，**必须有一条真角色 403 用例让位名在 `details.perm` 里自己报出来**
   （D183 步 1/2 两轮实测：权限矩阵**结构上证不了位名**，加行不等于守护）。

## 五、MS 自己没接上的环 —— 我们**必须明确不做**或**必须补上**的

取证 §C/Top-3 的三条，逐条给口径（这三条的价值是：**别把 MS 的半成品当成规格**）：

1. **评审快照归档表**：DDL、压缩拦截器、删评审时 DELETE 它都齐了，**全仓库零 insert**。
   → 我们不做评审，自然不做它。但这条记下来当反面样本：**结构齐全 + 有删除路径 ≠ 有写入方**。
2. **`ARCHIVED` 状态**：枚举里有、DTO 里承诺有、能当筛选项（连测试都有），**主代码零
   `setStatus(ARCHIVED)`**；且 DDL 注释里还多造了一个连枚举都没有的「已结束」态。
   → 口径：**状态列的每一个取值都要有写入方用例**，取值集合从枚举里抄不算数。
3. **`public_case`**：请求字段是 `String`、实体是 `Boolean`，属性拷贝**静默跳过** ⇒ 永远 false，
   而前端模型却在用它。
   → 口径：**类型不匹配的静默丢弃是谎 UI 的上游**。我们这边同类风险的检查点是「出参字段名与
   入参字段名靠人记」的写法 —— `create_model` 那套投影正是为它存在的（D183 步 2 已核过因果，
   别再写回「create_model 丢 extra=forbid」那个假病因，勘误在台账第六十轮）。

**第 4 条是我自己从取证里推出来的、比上面三条更影响本刀设计**：MS 的**多版本用例行**
（同 `ref_id` 多 `version_id`）**找不到生产创建入口** —— 复制路径把 `ref_id` 重置为自身，
多版本行只存在于测试种子数据里。所以：
**本刀不做版本族**。要做得先回答「一份用例的第二版从哪个操作里诞生、旧版怎么仍可被历史报告引用」，
那是独立一刀、且要先有报告（D183 步 4）当地基。**在没有创建入口的列上建表 = 判据 1 现场复刻。**

## 六、判据（本刀自用，逐条要有用例）

1. 没有一列「有 schema 没写入方」（§五 三条 MS 教训的合计）；每张新表每列答得出谁写谁读。
2. 回收站三态（进 / 恢复 / 硬删）各有用例，且**硬删不可恢复**这条要变异自证。
3. 编号 `num` 的项目内唯一性与「id ≠ num」要各钉一条：拿 `num` 当主键用、或跨项目撞号，
   都必须红。
4. 页码制全套照 **D47-b §四 判据 1–7**，不重述、不简化；含「先自证种子数据有区分度」那条前提用例。
5. 权限位名的守护用**真角色 403 + `details.perm`**，不用矩阵行（理由见 §四 5）。
6. 每条守纪律的断言变异自证，且**判定器必须报出红掉的是哪条用例名**，判定以**汇总行**为准
   （台账 61 §三：`-q` 要配 `-rf`、conhost 下先剥 ANSI，否则明确被杀会被报成 SURVIVED）。
7. 每张变异表 `tee` 到 `backend/.tmp/d185/<name>.log` 并在账里点文件名 —— `**/.tmp/` 被
   `.gitignore:20` 挡着，**「只有 git 是证据」盖不住夹具与判定**；没落盘的跑数与没跑过不可区分。
