## 一、这一刀到底在改什么

MS 的列表页脚是 `{current, pageSize, total}` + `showPageSize/showTotal/showJumper`：能跳页、能换
每页条数、能说「共 N 条」。我们全是**键集分页**（`app/core/errors.py` 的 `paginate`/`paginate_desc`，
`limit(size+1)` 探下一批 → `next_cursor`，从不数全表），前端一律是「加载更多」把页拼起来。

差别不是 UI 丑，是**两类能力压根没有**：跳到第 5 页、以及「共 137 条」这句真话。
我们现在的页脚只有 `hasMore` 时能说「本页取到 N 条（单页上限 200，后面还有没取的）」。

## 二、为什么两种并存而不是把游标改掉

键集只能往前走：下一批的前提是「已知上一批的末位游标」，「跳到第 5 页」没有这个前提。
换成 OFFSET 的代价要写明白——深页变慢，且并发插入会让页与页之间重叠/漏行。
所以**加一条页码路径，不动游标路径**：21 处构造点、20+ 个列表接口的响应一个字节都不变。
`total` 走 `Page.total: int | None = None` + `_dump` 仅在非 None 时写键，就是这个意思
（凭空多出 `"total": null` = 单方面给一堆没人评审过的接口改契约）。

## 三、切的顺序（每步一个可提交的最小刀，单测自证，最后统一跑全量）

| 步 | 内容 | 为什么这个顺序 |
| --- | --- | --- |
| 1 | 核心：`paginate_page` / `count_of` / `Page.total` / `_dump` 的 total 键 | 不碰任何页面，加法式的，先落 |
| 2 | `report_list` 挂页码模式（`current` 参数 + total 回传） | **报告中心是第一个真页码页**：它的每个筛选项都已经是服务端 query 参数，服务端分页不会说谎 |
| 3 | 前端共享页脚控件（档位 20/50/100 + total + 跳页）+ `reports.tsx` 接入 | 控件先共用一份，别每页各画一个页脚 |
| 4 | `api.tsx`：模块 + 关键词下推到服务端，再接页码 | 见下节，这步最重，单独一刀 |

**第 4 步为什么不能提前**：接口管理页是「一次拉 200 条 + 本地 `visible` 过滤（模块子树 + 关键词）」。
在它还在本地过滤时挂上页码，会得到一个**说谎的页脚**——第 3 页显示 2 行而脚注说共 300 条。
必须先把过滤下推，页码才有真 total 可画。

## 四、判据（每步都要过，不接受「看起来对」）

   否则翻页与游标翻页会给出不同顺序。

### 这一刀的五条实测前提（前三条本轮现跑，第四、五条补跑，都不是推断）
1. **`离线` 的 SQL 谓词是 `IS NOT TRUE`，不是 `= false`**（MySQL 8.4.13 真库现跑，
   七行真值表）：`json_extract(last_state,'$.online')` 对「列本身为 NULL / 空对象 /
   缺 online 键」交出的是 **SQL `NULL`**，对 `false`/`null`/数字 `1` 交出 `'false'`/`'null'`/`'1'`
   且 `= true` 均为 `0`。所以：
   - `= true` 只对 **JSON true** 那行是 1；对 NULL 的那些行是 **NULL**（不是 0）——
     直接拿 `NOT (= true)` 当「离线」会把这些行**整批漏掉**（`NOT NULL` 仍是 NULL，不为真）。
   - 正确的离线谓词是 `(json_extract(...) = true) IS NOT TRUE`，实测覆盖
     {NULL 列, 空对象, false, null, 数字 1, 缺键} = 全算离线，只有 JSON true 不算。
   - 这**恰好等于**前端现在的判据 `row.last_state?.online !== true`（严格不等，
     数字 `1` 也算离线）——下推不改变现有筛选行为，这是这刀不引入行为漂移的前提。
2. **锁键的宿主是 `serial`，不是主键 `id`**。`adb_lock.occupied()` 的形参名叫 `device_id`，
   但**每个调用点传的都是 `d.serial`**（`device_services.py:179/198/292`、
   `debug_services.py:634/646`）。批量版若照形参名用 `d.id` 去拼 `lock_key`，
   每个键都 miss → **所有设备一律显示「空闲」**，而且不报错。这条必须有专门的用例钉住
   （拿 serial 建锁、列表按 id 排序返回，断言那一台仍然是「占用」）。
3. **`occupied` / `idle` 不可能是 SQL 谓词**（Redis 不在同一个存储里），所以「按 state 筛」
   不能只加一个 WHERE 就交给 `paginate_page` 数 total。落法（**这是我设计的，不是业主说的**）：
   `offline` 走 SQL 谓词；`occupied` / `idle` 需要占用读数 —— 服务端先把 SQL 层筛完的
   **全集**取回、用**一次** `mget_keys` 批量读锁、在 Python 里筛完再切页 + 数 total。
   两种取数的 ORDER BY 必须是同一个表达式（判据 5：本页 `AdbDevice.id`），
   否则页码与筛选会给出不同顺序。**宁可全集取回也不能给假 total**：
   全集超过硬上限时按「total 不可知」处理（`total=None` → 前端页脚整块不渲染），
   绝不允许「只数了这一页」冒充「共 N 台」——那正是 §三 明令禁止的说谎页脚。
4. **`bus.mget_keys` 可用**（本轮现跑实测，此前**零调用方、零直测** —— 一个没被任何测试跑过
   的助手，正是「批量占用」整块设计的地基，所以我先测它再让代码押上去）。探针
   `backend/.tmp/d183/mget_probe.py` 六条全 OK：`set_nx` 写的键 `mget_keys` 读得到
   （两边都过 `channel()` 的 `tp.` 前缀，**前缀对称**）；缺键交 `None`（这就是「空闲」的判据，
   不是抛、不是空串）；**逐位与入参对齐**且等长（批量占用靠下标把 holder 配回设备，
   错位＝张冠李戴）；重复键各占一位不塌；空入参 → `[]`。
   顺带排掉一个真会静默生效的雷：`mget_keys` 对取回值做 `str(v)`，若 client 不是
   `decode_responses=True`，那会交出 `"b'token'"`（repr）而不是 token —— 不报错，
   只是 holder 永远是错的字符串。实测两条注入路径都带解码：`init_bus()`
   （`eventbus.py:153` `from_url(..., decode_responses=True)`）与锁测试的
   `FakeAsyncRedis(server=..., decode_responses=True)`（`tests/test_adb_lock.py:42`），
   所以 `str(v)` 现在是 no-op。**这条不是「代码没问题」的结论，是一条会静默生效的前提**：
   将来谁加一条不解码的注入路径，holder 就读成 repr 而全链路无异常。
   （另记一处对不上的地方：`tests/conftest.py:1` 的 docstring 写着「+ fakeredis」，
   而该文件第 23 行其实把 `TP_REDIS_URL` 默认指到**真 Redis** `db.internal.test:16379/6`；
   fakeredis 只在 `test_adb_lock.py` 这类自己 `init_bus(client=...)` 的文件里用。
   不在这刀里改它，但按这份 docstring 以为「测试不碰真 Redis」是会判错环境的。）
5. **「离线」压倒「占用」，且 `serial` 不是唯一键**（本轮现查前端真值 + 模型约束，
   前提 1 只解决了「怎么判离线」，没解决「三档怎么排」）。
   - 前端唯一判据 `cardStateOf`（`web/src/pages/adbDevices.tsx:58-62`）：先 `online !== true`
     → 离线，**再**看占用。而 `execution/adb_lock.py:7` 的 docstring 明写锁键
     「软删/离线设备仍占位」——「离线但锁还在」是**常态**（run 跑到一半设备掉线、TTL 未到期），
     不是边角料。⇒ 三档必须是 `offline` = 非在线；`occupied` = **在线且锁持有**；
     `idle` = **在线且锁未持有**。把 `occupied` 实现成「锁存在」会把界面上写着「离线」的设备
     选进「占用」结果，不报错，只是筛选与卡片各说一套 —— 正是本刀要消灭的说谎。
     配套总账用例：**三档各自的 total 相加 == 不带 state 时的 total**（互斥且穷尽，漏任一档即红），
     外加一条「离线 + 有锁 → 只出现在 offline」。

### 子树这一刀的**边界**（我裁的，不是业主说的，写清来源）

- **工务纪律四条（前两条上轮立，后两条本轮步 5d 新踩；性质都是「证据可能已经不是证据」）**：
  1. **`core.autocrlf=true` + 仓里没有 `.gitattributes`**：子代理按文本模式写文件会把整文件
     LF→CRLF，而 git 读盘时归一化，于是 `git status` 只显示你真正改的那几行、**换行尾事故被
     藏在空 diff 里**。本轮 `adb_test/schemas.py` 就这么整文件翻成了 CRLF（HEAD 是纯 LF），
     代理还自述「该文件历史上就是 CRLF」——**是错的，HEAD 实测纯 LF**。查法：取 `git show
     HEAD:<path>` 与工作区各自的 `count(b"\r")` 对比；修法照前面那条纪律——按字节写回，
     不用 `git checkout`（纪律禁）。**任何编辑/变异工具动手前先读目标文件的实际行尾。**
  2. **同仓并行时，盘上的核心文件可能正被别人的变异夹具改着**。本轮读到 `core/errors.py`
     里有一段 `if (current-1)*size >= total: current = 1`——那是与判据 4 正面相反的钳位，
     HEAD 里没有，也不是我写的。那一刻我若照它跑测试，得到的「绿」或「红」都不属于我这次提交。
     规矩（本轮起执行）：**跑测试前后各取一次所依赖 `app/core/*.py` 的 sha256**，与
     `git show HEAD:` 的哈希对齐才算这次跑数有效；对不齐就停下，别把别人的 mutant 当被测代码。
  3. **守护跑不到 ≠ 守护守住了**（本轮步 5d `aa3b63f` 踩的）。一条断言若写在会被无限回路
     饿死的位置，表现是**整份文件挂死**而不是报红：`act()` 冲不干净微任务链，而 vitest 的
     用例超时自己也是个宏任务、被同一条链饿死，于是那条绊线**一行都没执行过**。这种洞比
     没有断言更坏——断言就写在文件里、看起来在守，实际永远不参与判定。规矩：**每条「靠计数」
     的守护，都要现跑一次「让被守的事情真的发生」的变异，确认它红、且红得带汇总行**；
     只看到「测试没报这个」就断定「这个没发生」，就是把「跑不到」当成了「跑过且没问题」。
     配套：长任务一律 `> log 2>&1` 再读；超过预期时间当作**信号**去查而不是接着等——
     本轮那 600s 不是慢，是回路。
