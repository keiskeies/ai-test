## 三、四处**主动不跟 MS**（我裁的，依据是取证里的死路，不是偏好）

1. **状态机在写路径真校验**。MS 的边表**只用来渲染下拉框**，写入时从不比对

   不是"字段格式错"）。这条是**改良**，要在文档里写明它比 MS 严，别让人以为是复刻漏了。

   于是 5 张子表 + 对象存储全成孤儿。我们这条路径必须显式列出要删的每张表，并被用例钉住。
4. **不做 MS 那套 `deleted` BIT 位**。我们自己的先例是 `status` 列两态
   （`adb_test/models.py:28-29` `STATUS_NORMAL/STATUS_RECYCLED`，我现读；
   列表排除 `case_services.py:120` 的 `status == (RECYCLED if payload.recycled else "normal")`，我现读；
   `grep "deleted\|is_deleted\|trashed"` 全仓 0 命中，我现查）。
   **跟自己的先例，不跟 MS 的形状** —— 同族一致性比"像 MS"重要，且 `plan.archived` 已经是业务态
   不是回收站（代理称，与我读过的「归档是终态」判据一致）。
   > **步 1 落地勘误（同日）**：这条**照做了但只做到一半** —— 那四条表的 `status` 只装
   > 回收站**一个轴**，缺陷有**两个轴**（工作流 + 回收站），一列装不下两个轴。

## 四、表与常量（**含同日勘误：原拟 4 张表 → 只建 2 张**）

先给勘误，因为它改了本节结论；结论之后的表格是被勘误**修正后**仍有效的部分。

本节原写「4 张表，`defect_status` 每项目建行」。**这条我现在自己否了**，理由是现查的三条事实：

1. **本仓的词表一直是源码常量，不是表**：`testplan/schemas.py` 的
   `PLAN_DISPLAY_STATUSES = ("not_started", …)` 与 `LINK_RESULTS = ("none", …)`（我现读），
   前端词表由 `web/src/shared/runVocab.test.ts` 用 `readFileSync` 抠后端源码对表 ——
   **这条路已有护栏**，比"表 + 没人编辑"强。
2. **全局表由启动期同步填**（`main.py:23-27` 的 `run_bootstrap` / `sync_perm_points` /
   `seed_default_model`；`perm_point`、`role_template` 都是这张形状），
   而且 —— **全仓 27 个迁移里没有一个做过 INSERT**（唯一 DML 是 `0014_run_record_v2.py:42`
   一条 UPDATE，我 grep 现查）。
3. 于是「每项目建行」的回答是：**存量项目的行谁来插？** 迁移里插 = 无先例的 DML；
   启动期回填 = 又造一个同步器；项目创建钩子 = 项目创建路径在 `iam`，跨模块改它不属于本刀。
   **三样都是为一张"一期没人能编辑"的表付的机械成本**，而 判据 1 问的正是「谁写这列、谁读它」。

**改成**：`defect_status` / `defect_transition` **不建表**，状态词表与边表都是
`schemas.py` 里的常量（`DEFECT_STATUSES` / `DEFECT_TRANSITIONS`）。
§三 第 1 条那条**改良**（边表既渲染也校验）**与存哪里无关**，照样成立：
写路径拿常量比对边，非法转移 409。

⇒ **0027 只建 2 张表：`defect` + `defect_case_link`。**

**升级路径写清楚**（免得失传）：若业主将来要「每项目自定义缺陷状态」（MS 有这个能力），
那是**另一刀**：加两张表 + 一个启动期 seed（照 `sync_perm_points` 形状）+ 状态编辑端点，
且那一刀必须自带「删状态项时先查谁还引用着」—— MS 正是没做这一步才留下一堆悬空状态
（取证 §G 第 7 条）。**前端词表那份常量届时改读端点，`runVocab.test.ts` 那套手法照搬。**

下面表格里的列口径仍然有效（`defect` / `defect_case_link` 照用），
`defect_status` / `defect_transition` 两张**降级成常量**，`is_start` 语义变成
`DEFECT_STATUSES[0]`（新建默认态），`is_end` 变成常量集合 `DEFECT_END_STATUSES`。
