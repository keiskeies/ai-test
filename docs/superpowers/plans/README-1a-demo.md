# 1A 演示手册（业主版 · 20 分钟）

> 目标：亲眼看一遍「建接口 → 建用例 → 调试通过 → 运行记录留痕」这条主链路，
> 以及 Pilot 在同一条链路上的两种收场：全自动建好并调试通过、只读模式下被门挡住。
> 全程离线可演示：三个出厂假模型不需要任何 API Key。
>
> 与 S0 手册的关系：S0 讲「一个注解五路同生」的骨架，本手册讲「测试资产真的能用」。
> 装环境那段（§0-§4）完全通用，已经跑过 S0 的机器可以直接跳到 §5。

## 0. 前置

- MySQL 8.x 与 Redis 7.x：直连现网实例，或仓库根目录 docker compose up -d mysql redis。
- Python 3.12（backend/.venv 已就绪）、Node 22 + pnpm 10（web/）。
- 后端命令一律在 backend/ 目录执行；Windows 用 backend/.venv/Scripts/python.exe。

配置写在 backend/.env（不入库；模板是**仓库根目录**的 .env.example，复制过去改）：

```ini
TP_ENV=dev
TP_DB_URL=mysql+asyncmy://root:<密码>@db.internal.test:3306/testpilot?charset=utf8mb4
TP_REDIS_URL=redis://:<密码>@db.internal.test:16379/6
TP_SECRET_KEY=<32位随机串>
TP_BOOTSTRAP_ACCOUNT=admin
TP_BOOTSTRAP_PASSWORD=             # 留空=首次启动随机生成并只打印一次；也可自己设一个
```

## 1. 端口：先避开 Windows 的保留段（30 秒，Windows 用户必读）

```powershell
netsh int ipv4 show excludedportrange protocol=tcp
```

- 这条命令列出 Hyper-V/WinNAT 抢占的端口段。**7999-8098 经常整段被占**，
  所以 uvicorn --port 8000 会报 [winerror 10013]（不是权限不够，是端口不属于你）。
  本项目演示统一改用 **8320**；Linux/macOS 用 8000 也没问题，下面会标注哪里要改。
- e2e 用的是 8321 / 靶场 9999 / 前端 5173，都已避开保留段，不用管。

## 2. 建表（约 1 分钟）

```powershell
cd backend
.venv\Scripts\python.exe scripts\migrate_dev.py   # 幂等，0001→0017，并打印当前/目标版本
```

- **用这个脚本而不是 `-m alembic upgrade head`**：它多打印当前版本与目标版本，
  而且它就是 §7 那六道门禁里的第六道（pytest 每轮新建临时库，全绿也照不出演示库滞后）。

## 3. 起靶场（被测系统，约 30 秒）

另开一个终端，在仓库根目录执行：

```powershell
backend\.venv\Scripts\python.exe backend/scripts/target_app.py
```

- 靶场 = 迷你商城 API：POST /login（demo/demo123）、GET /order/{id}（要 Bearer tk-demo）。
- 自检：http://127.0.0.1:9999/healthz 返回 {"status":"ok"}。
- **调试真的会发 HTTP 到它**，所以徽标上的 200 不是假的；靶场关了演示会退化成「请求失败」，
  那也是真实结果——两种状态在运行记录里都好看（§5.6）。

## 4. 灌演示数据 + 起平台（约 2 分钟）

```powershell
# 4.1 种子（可反复执行，只补缺不覆盖手工改动）
backend\.venv\Scripts\python.exe backend/scripts/seed_demo.py

# 4.2 后端（cwd=backend）
cd backend; .venv\Scripts\python.exe -m uvicorn app.server:app --port 8320

# 4.2b 执行 worker（另开终端，cwd=backend）——1B 起场景执行走 Celery worker（D5），不开它
#      场景执行会 503 executor_unavailable（这是设计：不静默降级）。Windows 必须 --pool=solo。
cd backend; .venv\Scripts\python.exe -m celery -A app.worker:celery_app worker --pool=solo -l info

# 4.3 前端（另开终端，cwd=web）：preview 跑的是构建产物，改过源码要先 pnpm build
cd web; pnpm install; pnpm build; $env:TP_BACKEND="http://127.0.0.1:8320"; npx vite preview --host 127.0.0.1 --port 5173 --strictPort
```

- **`--host 127.0.0.1` 不能省**：vite preview 默认只绑 `localhost`，而 Windows 上 `localhost`
  常常只解析 IPv6——那样下面让你开的 `http://127.0.0.1:5173` 会直接连不上（本机实测：
  `127.0.0.1` 拒绝连接、`localhost` 才通）。

- 种子会建出：项目「演示商城」→ 全局变量 base_url/token → 环境「本地靶场」→
  模块「交易链路/下单」→ 3 个接口 → 3 条用例（1 条纯继承、1 条绑数据集、1 条登录冒烟）→
  数据集「订单参数集」→ **1B 演示场景**「演示：登录-取token-轮询查单-断言」（4 步）→
  3 个出厂假模型 → **两个演示成员**：
  demo_ro（只读）与 demo_pm（项目管理员），口令都是 Demo@12345。
- 前端：http://127.0.0.1:5173 → `admin` / §0 里 `TP_BOOTSTRAP_PASSWORD` 的那个值登录。
- TP_BACKEND 只影响前端把 /api 代理到哪个后端；不设则默认 8000（见 §1，这里必须设）。

## 5. 演示路径（20 分钟，照着点就行）

> 每一节末尾的「你会看到」是判据：对上了就说明这一层是通的，对不上直接跳 §8 排查。
> 演示账号：`admin` / §0 里 `TP_BOOTSTRAP_PASSWORD` 设的那个值（系统管理员）。

### 5.1 建项目（1 分钟）

1. 登录 → 「项目与工作台」→ 右上角「新建项目」→ 名称随便（例如「演示商城」）→ 创建。
2. 种子已经建过一个「演示商城」，**演示建议直接用它**（后面 5.2-5.6 的数据都在里面）；
   新建这一路只是给业主看「新建项目后我是项目管理员，可以拉人」。

你会看到：**顶栏左侧（TestPilot 标志右边）的项目标签**切成所选项目。
左侧菜单的留白按批次标注，**不做假按钮**：
「场景编排 / 报告中心」随 1B 已开放（可以直接点进去看，1B 的演示路径见
[README-1b-demo.md](README-1b-demo.md)），「元素库 / UI 用例」随 1C 已开放
（演示路径见 [README-1c-demo.md](README-1c-demo.md)）；还灰着的是后面批次——
设备管理 / ADB 用例 = 1D，定时任务 / 通知渠道 = 1E，
MCP 服务 / Skills = 二期，测试计划 = 三期。

### 5.2 项目全局配置：base_url 只写一次（2 分钟）

1. 「接口管理」→ 环境框右侧齿轮 → 「项目全局配置」Tab → 全局变量。
2. 里面应有两行：base_url = http://127.0.0.1:9999、token = tk-demo → 保存全局变量。

你会看到：一句提示「全局配置对所有环境生效；环境里同名变量会覆盖这里」。
这就是 §7.5 的分层变量：**主机地址写在项目级，接口里只写 
`${base_url}/order/1`**，
以后换测试机只改这一行，几十个接口跟着搬家，一个都不用手改。

### 5.3 模块 + 建接口（3 分钟）

1. 左侧模块树已有「交易链路 / 下单」；点「＋」再建一个自己的模块练手。
2. 右上角「新建接口」：接口名「我的第一个接口」，路径 /order/1，
   URL 填 `${base_url}/order/1`，请求头加一行 Authorization: Bearer `${token}`，
   「断言」Tab 加一条 状态码 = 200 → 保存。

你会看到：
- 左栏「用到的变量」实时亮出 base_url / token 两个标签（悬停说明取值来自所选环境）——
  还没保存就知道这个接口依赖哪些变量，而不是跑挂了再回头找。
- 断言为空时编辑器提示「无断言，调试只发请求不校验」：**没断言的调试永远绿，那是假绿**，所以主动提醒。

### 5.4 调试：真的发一次请求（2 分钟）

1. 抽屉右上「调试」。

你会看到：状态码 200、绿色「断言全过」、响应体/响应头两个 Tab 可展开；
关掉抽屉后，列表里这一行的「最近结果」徽标变成 200（悬停显示「✎调试 · 耗时 ms」）。
徽标来自 GET /runs，是真记录，不是前端记的。
若把断言逐条停用到一条都不剩（D78 的启用开关），这里会变成灰色「未校验」——
请求发出去了但什么都没校验，面板不许把它演成绿色「断言全过」。

### 5.5 用例 + 数据集：一份接口跑多组数据（4 分钟）

1. 点任一接口行 → 详情抽屉 → 「用例」Tab。**每个接口种子各给一条用例**（不是一进抽屉就两条）：
   「查询订单」下是「数据驱动」（绑了数据集、覆盖 URL），「登录获取令牌」下是「登录冒烟」（全继承）。
   想看两种形态同屏，就在这两个接口之间来回切一下。
2. 「新建用例」：名称「我的用例」，数据集选「订单参数集（**3 行**：oid=1/2/3）」→ 保存 →
   列表点它右侧「调试」。

你会看到：
- 用例表有「覆盖」（没覆盖就是蓝标「**全继承**」，有覆盖就把覆盖了的项点名出来，
  如「**URL**」「URL/参数」——它报的是**覆盖了哪几项**而不是数量，因为「覆盖了 3 项」
  不如「覆盖了 URL/参数/请求头」来得可直接）、「数据集」、「追加断言」（几条）、「可执行」四列——
  **可执行=缺 URL 的黄标**是防呆：变量没配全的用例，在跑之前就告诉你跑不了，而不是跑出一屏红。
- 绑了数据集的用例，调试取数据集首行做变量。
- 「**引用**」列在**数据集页**（左侧「数据集」），不在用例表里：它显示有几个用例绑着这个数据集，
  大于 0 的数据集删不掉（防止把别人的用例抽空）。

### 5.6 运行记录：所有跑过的都在这（2 分钟）

1. 左侧「运行记录」。

你会看到：刚才每次调试各一行（触发方式渲染成「✎ 调试」，带一个空格），
状态下拉按生命周期给六项：**排队中 / 运行中 / 通过 / 断言失败 / 请求失败 / 已取消**
（「断言失败」和「请求失败」是分开的两种红——一个是断言没过，一个是请求根本没发出去，
跟 1B 画布上橙/红分色同一个道理）；
点一行开详情，渲染与调试面板同一套（同一份快照，不存在「详情和调试长得不一样」）。
**接口被彻底删除后，它的运行记录仍然在、仍然能展开**——历史不追删，
subject_name 是当时存的快照名（§6.7）。

### 5.7 Pilot 全自动：建接口 → 建用例 → 调试通过（3 分钟，本场压轴）

1. 「Pilot 试验台」→ 项目选「演示商城」→ 模型选 **演示假模型（建接口→用例→调试）**
   → 模式「全自动（FULL）」→ 点「开始会话」。
2. 输入框随便写一句（假模型按脚本回放，写什么都行；建议写：
   「帮我加一个查询 1 号订单的接口，建条用例并调试通过」）→ 发送。

你会看到（离线假模型，不需要任何 Key）：
- 先出一条 THINKING，然后三个工具调用逐个亮：api_definition_create → api_case_create → api_debug，
  每个都带「ok ✓」和产出链接，点链接直接跳到那个接口（生产物是带链接的，不是一段文字）。
- api_debug 的结果是 通过 200——**AI 不只是写了个接口，它自己跑通了**（调试与人工点「调试」走的是同一条链路、同一套权限、同一条审计）。
- 结尾 USAGE（输入/输出 token）与 RUN_END status=DONE。
- 回「接口管理」：新接口「查询订单1号」就在列表里，徽标 200；用例「已支付订单」挂在它下面。

### 5.8 Pilot 只读：同一个模型，同一句要求，被门挡住（2 分钟，最说明问题的一分钟）

1. 模式切「只读（PLAN）」→ 模型换 **演示假模型（只读被拒）** → 开始会话 → 发同一句话。

你会看到：工具结果是一条 ok ✗：

> 当前为只读（PLAN）模式，写类工具被拒绝。请改用只读工具完成任务或提示用户切换模式。

- 关键认知：**这不是模型「自觉」，是平台拒绝执行**。同一个 api_debug 在 PLAN 下就是过不去，
  模型再怎么想写也写不了。AI 的权限边界长在服务端，不长在提示词里（§9.4）。
- 中间的「询问（ASK）」模式是第三种收场：写类工具会挂出**审批卡**，卡片停在「等待审批」。
  **但 1A/1B 没有页面审批通道**——审批门（approve/deny 端点与按钮）按蓝图 §14 属**二期**
  （原文：「写/破坏性工具与三档权限模式 + 审批门」）。这一段能演示的是**门确实把请求拦住了**：
  会话挂在 WAIT_APPROVAL，写不下去；你此刻能做的只有点「中断」收回，或切 FULL 模式重试。
  照着这一段点「批准」会等到一个不存在的按钮（ledger R69：这句原先写的是「审批卡等你点」，
  把手册变成了假承诺——演示路径必须业主能亲手跑通，§13 纪律 1）。

### 5.9 只读成员视角：同一个平台，两套界面（3 分钟）

1. 退出 → 用 **demo_ro / Demo@12345** 登录（演示只读，项目成员 READONLY）。
2. 「接口管理」→ 调试按钮、新建按钮、删除按钮都不在；「数据集」「运行记录」能看。
3. 试试 URL 直接敲 /#/settings（菜单里这一项叫「系统设置 → 项目与成员」）→
   只剩「项目成员」一个 Tab，「审计日志」「平台用户」都不在；
   用它的 token 调 POST /api/v1/api-definitions → 403 insufficient_permission。

你会看到：不是「点了报错」，而是**按钮根本不渲染**——看不见就不会点错。
再用 **demo_pm / Demo@12345**（项目管理员）登录：能建接口、能加成员，
但「系统设置」里的「平台用户」「审计日志」两个 Tab 对它同样不出现（项目管理员管项目，不管平台）。

底层只有一句话：每个人的权限集由服务端下发（READONLY 模板是 `*:read`，
在项目里再叠一条 `-system:*` 把平台域挡掉，见 `iam/roles.py` 与 `project_services.PLATFORM_DENY`），
前端只负责照渲染，不自己猜角色。

### 5.10 回收站与「彻底删除」（2 分钟，收口）

回收站有三类资产，出口不一样，讲清楚这三条差别最能在评审时建立信任：

1. **接口**：行右侧垃圾桶 → 放入回收站；左侧模块树底部切到回收站视图。
   回收站里两件事：「恢复」原样回来（徽标也在）；「**彻底删除**」要求**逐字输入接口名**才放行。
   差一个空格按钮都是灰的；确认后接口和它的用例一起物理删除，**同名接口立刻可以重新创建**——
   软删的行原本会永久占着 uq_apidef_project_name，没有这个出口同名接口就再也建不出来。
2. **用例**：接口详情「用例」Tab 右上角也有回收站开关。回收一条用例 → 进去点「恢复」它就回到列表；
   再回收 → 「彻底删除」同样要逐字输名。用例只有回收没有出口是不可接受的：
   手滑一次就得找人改库捞数据。回收站视图里「新建用例」会收起，计数徽标也不跟着墓碑数变。
3. **模块**：模块树里删除会连子孙一起进回收站。彻底删除一个模块时，
   弹窗会明说「其下接口不会被删，会变成未分类」——**模块是收纳方式，接口是资产，删收纳盒不该烧掉里面的东西**。
   确认后回执告诉你删了几层模块、几个接口转为未分类；列表里那些接口仍然在，只是不再属于任何模块。

顺带一个能体现「守门人是谁」的细节：**根层级的模块名，数据库唯一键根本管不住**
（MySQL 的唯一索引不判等 NULL，而根模块 parent_id 就是 NULL），
所以同层级查重只能由应用层做——包括拦住那些还躺在回收站里的同名模块，
否则树里会长出两根一模一样的名字，用户无从分辨哪根是有用的。

> 要再演示一遍 §5.7 的 Pilot 全自动，先把「查询订单1号」彻底删掉，
> 否则 Pilot 会如实报「接口名已存在」。

## 6. 换成真实模型再跑一遍（可选，5 分钟）

1. 「系统设置」里没有模型入口（三个 Tab 是项目成员 / 平台用户 / 审计日志）——
   **模型配置中心的界面在 1E 批次**，现阶段两种接法：
   - 起服务时给默认模型：backend/.env 里设 TP_MODEL_SEED_BASE_URL（OpenAI 兼容网关地址）
     与 TP_MODEL_SEED_NAME（可选 TP_MODEL_SEED_API_KEY），重启后自动落一条名为
     （D130：此前 seed 直读 os.environ，`.env` 从来没被读到过，这句指引从未生效；
     现已改走 `get_settings()`，.env 写了就生效）
     `seed-<模型名>` 的默认模型配置（两个必填项缺任何一个就什么都不落，不报错也不静默建半条）；
   - 用接口：POST /api/v1/model-cfgs（name/base_url/model_name/api_key…），随后
     POST /api/v1/model-cfgs/{id}/probe 可以当场验一次连通性（它打的是
     `GET {base_url}/models` 并回填 probe_result；配错别留着演示）。
2. 回试验台，模型下拉换成真实模型，重复 §5.7 与 §5.8。

真模型下值得盯的三点：
- 它有没有先读再写（工具箱按**权限**过滤，不是按模式过滤：只读成员 demo_ro 登录后
  `GET /api/v1/agent/tools` 回 **19** 个工具，全是 `effect=read`；同一个项目 admin 拿到 **61** 个。
  写工具压根不在只读成员的清单里，模型看不见也就调不到）；
- 出错时它是不是把工具报错原样收场，而不是编一个成功；
- USAGE 的 token 数与 §5.7 假模型的 666/88 对个照，心里就有成本预期。

> 那句「**尚未配置默认对话模型，请先在模型配置中心添加**」是服务端
> `POST /api/v1/agent/sessions` 在**既没选模型、库里又没有默认 CHAT 模型**时抛的 422
> （`agent/routes.py`），前端把它原样 toast 出来——不是界面里写死的一句话，也不是坏按钮。
> 按 §4.1 灌过种子的库**不会**遇到它：种子里「演示假模型（离线回放）」就是 `is_default`。
> 真会看到它，说明模型被删干净了，或者你换了个没灌过种子的库。
> 另一个容易看错的点：模型下拉只对系统管理员出现——`model:cfg:*` 是平台权限，
> 项目管理员拿 /model-cfgs 是 403，前端据此**隐藏选择器**并回落到平台默认模型
> （`pages/bench.tsx`），这不是缺功能。
> 而「模型配置中心」的**界面**确实还没做：1A 交付的是服务端 CRUD + probe 与权限位，
> 界面在 1E。这不是缺漏，是排期，业主版演示请直接用出厂假模型。

## 8. 常见问题

**Q：uvicorn 报 [winerror 10013] / 端口无法绑定。**
A：Windows 保留段，见 §1。换端口后别忘了同步设 TP_BACKEND，否则前端一直连旧端口，
表现是「页面能打开但接口 502/500」。

**Q：调试 401「缺少或错误的令牌」，但 URL 是对的。**
A：token 是环境层变量。检查三处：所选环境（列表右上角下拉）→ 环境公共请求头是否有
Authorization: Bearer `${token}` → 变量 token 是否为 tk-demo。
顺手确认靶场还活着（/healthz）。

**Q：调试显示「请求失败」而不是状态码。**
A：靶场没起，或 URL 里的 base_url 指向了别处。「请求失败」是诚实状态，会原样进运行记录。

**Q：Pilot 建接口报「接口名已存在」。**
A：同名接口（含回收站里的占位）已存在。改名，或按 §5.10 把旧的彻底删除后重跑。

**Q：回收站里的东西挡住了新接口/新模块同名。**
A：这是刻意的——防止误删之后又被同名覆盖，恢复出来两份不同的东西。
接口报的是「接口名在回收站占位，请先恢复或改名」，模块报的是同层级那句；出口都是先恢复、或彻底删除。
（模块这条尤其重要：根层级模块名数据库唯一键管不住，全靠应用层拦。）

**Q：某列/某按钮不见了。**
A：先看当前账号权限（右上角头像里能看到账号）。写按钮对 READONLY 一律不渲染，
这是设计而不是 bug；要演示写链路请用 admin。

**Q：改了前端源码但页面没变。**
A：preview 跑的是 dist 构建产物，改完要 pnpm build；开发模式用 pnpm dev（同样要设 TP_BACKEND）。
