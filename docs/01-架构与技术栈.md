# 01 · 架构与技术栈

已确认的四项决策（本文件的前提）：

| 决策 | 选择 | 由此产生的硬约束 |
|---|---|---|
| 部署形态 | **服务端团队平台** | 需要多租户、权限、worker 池、设备租约、执行历史看板 |
| AI 执行权限 | **脚本模式 + Agent 模式，显式切换** | IR 必须支持 **AI 回写**；Agent 模式产出的轨迹必须能蒸馏成 IR |
| 用例形态 | **IR 双向同步：可视化表 ⇄ TS SDK** | IR 是**唯一真相源**；GUI 和 SDK 都是它的视图，禁止出现第三种用例格式 |
| MVP 顺序 | **API → Web → ADB** | 执行器 adapter 接口从第一天就要是三端的，即便只实现一个 |

外加一条我自己钉的约束（P0 就要生效，代价约 15%）：**执行器可独立进程 + 无状态依赖注入**。理由见 §5 设备侧。

---

## 1. 分层总览

```
┌─ L5 Web 控制台 (React + Vite) ─────────────────────────────────┐
│  Agent 工作台(双模式)  场景编辑器(表/流程图 ⇄ Monaco)             │
│  实时执行视图(日志流/ARIA diff/截图/HAR/安卓投屏)                 │
│  资源库(API/Web/设备)  运行看板  LLM 配置中心  环境与密钥         │
└────────────── SSE / WebSocket(带 seq 断点续传) ────────────────┘
┌─ L4 API 层 (Fastify + zod 契约，单 schema 双端生成) ────────────┐
└────────────────────────────────────────────────────────────────┘
┌─ L3 Agent Runtime (TS) ───────────────────────────────────────┐
│ Planner→Tool loop→Skills(progressive disclosure)→/slash        │
│ 全部被测面能力走 MCP；上下文构建器负责脱敏与注入防护               │
│ ⚠ 只产 IR 草案 + 人审；永不直接驱动执行器                        │
└────────────────────────────────────────────────────────────────┘
┌─ L2 场景引擎 (纯 TS 库，零框架依赖，本地/CI/服务端同一份代码) ────┐
│ IR schema + 解释器 + 变量空间 + 控制流 + 自愈阶梯 + lint          │
└────────────────────────────────────────────────────────────────┘
┌─ L1 执行器 adapters (worker 进程，可回连服务端 / 可本地独立跑) ──┐
│ http(undici+openapi)   web(Playwright)   android(adb+UIAutomator2+scrcpy)
└────────────────────────────────────────────────────────────────┘
```

**依赖方向单向向下**。L2 是纯函数库（输入 IR + 环境 + adapter，输出 trace + 证据），**可以不开服务端、不连 MySQL 就在 CLI 里跑** —— 这是"一个引擎、GUI 只是视图"这条戒律的落地方式，也是本地/CI/服务端行为必然一致的唯一保证。

## 2. 组件与选型

| 层 | 选型 | 理由 / 放弃项 |
|---|---|---|
| 包管理 | pnpm workspace + TypeScript 5.x + **ESM** | 纯 ESM 有坑（见 §6），但要一次定死，别中途迁 |
| 校验/契约 | **zod v4** 单处定义，生成 JSON Schema（= IR schema）+ 运行时校验 + OpenAPI + TS 类型 | 四处定义必然漂移；IR 的 schema 必须和运行时校验同源 |
| 服务端 | **Fastify 5** | 放弃 NestJS（装饰器 DI 与纯函数引擎气质不合）、Express（无 schema 生态） |
| 前端 | **React 18 + Vite + AntD 5 + Tailwind** | 后台管理形态 + 组件生态，别自造 UI 库 |
| 状态/数据 | **TanStack Query**（+ WebSocket 增量写 query cache） | 不要上 Redux |
| 流程图 | **@xyflow/react**（原 react-flow） | 只读预览用；**主编辑形态是步骤表，不是拖拽画布**（画布编辑嵌套循环/`call` 是 UX 黑洞，见 §4） |
| 代码编辑 | **Monaco**（TS/JSON/YAML）+ JSON Schema 驱动表单 | IR 手写兜底 |
| LLM 接入 | **Vercel AI SDK**（provider-agnostic，`generateObject`/tool calling/streaming）+ **zod** 约束输出 | 放弃 LiteLLM（Python sidecar）/ OpenRouter（外部依赖）；自建 ~200 行 provider registry，见 `docs/03` |
| Agent 工具面 | **`@modelcontextprotocol/sdk`**，我方既做 MCP client 也暴露 MCP server | 见 §3 |
| Skills | **markdown + progressive disclosure**（`SKILL.md` + frontmatter，按需加载正文） | 这就是 Claude Code skills 的形态，已被验证 |
| 队列 | **BullMQ**（Redis） | 步骤级重试/退避/并发分组开箱可用；放弃 temporal（重运维，测试编排用不上 durable execution 的全部） |
| 并发锁 | Redlock 或 BullMQ 分组锁 → **设备租约 / 租户互斥 / fixture 互斥** | |
| 实时流 | **Redis Streams**（`XADD`/`XREAD BLOCK`/`XTRIM MAXLEN`） | 必须用 stream 而非 pub/sub：晚到的浏览器要能 `XRANGE` 补齐历史，断线要能用 `lastId` 续传 |
| 主数据库 | **MySQL 8.4** + **Drizzle ORM** | 放弃 Prisma（生成器慢、复杂查询要写 raw、迁移黑盒） |
| 向量 | **Qdrant** + `qdrant-js` | |
| Embedding | 默认走可配置 embedding provider；本地兜底 `bge-m3`/`nomic-embed` via ollama | 见 `docs/03` |
| Web 执行器 | **Playwright** 官方（不用 Selenium） | trace/ARIA 快照/HAR/`routeFromHAR` 是护城河级配套 |
| 安卓执行器 | **Appium 2 + uiautomator2 driver**（语义操作）+ **`@yume-chan/adb`**（设备控制/文件/日志）+ **scrcpy v3**（投屏） | 三者分工不同，不冲突。放弃纯 `adb shell input`（慢、Unicode 打不出、事件边缘情况缺失） |
| 浏览器内投屏 | **WebCodecs `VideoDecoder`**（`avc1.640034`，`latencyMode:'realtime'`），Annex-B→AVCC 自解析 | 见 §5 |
| CLI 双形态 | **Commander + @clack/prompts**；`atest run` 与 `atest agent` | CLI 是"本地/CI 同一引擎"的免费收益，也是最省事的落地验证。**M6 实装时两者均装不上**（离线），改成自研纯函数 argv 解析 + 纯文本输出，代价是**没有交互提示**，`--help` 必须写够好。见 `docs/04` §M6 里新增的偏差 |
| 证据存储 | **本地磁盘内容寻址 + MySQL 存索引/哈希** | 别塞 DB，别第一天就上 S3 |
| 报告出口 | **JUnit XML** + 内部富运行模型 | 三端唯一通用语汇 |
| 测试自己 | **vitest**；IR 解释器用「金样 IR + 期望 trace」快照测 | |

**不引入的东西**（明确排除，避免以后有人提）：Postgres（与 MySQL 重叠）、Kafka（规模不配）、LangChain.js（抽象税，AI SDK 够）、Selenium、Temporal、Redux、NestJS。

## 3. Agent 层的形态：为什么它是 L3 而不是执行入口

```
用户一句话 ──▶ Agent（Planner → 工具循环 → Skills 展开 → /slash 快捷）
                 │  工具 = MCP servers（被测面） + 内部工具（引擎 lint/dryrun/检索）
                 ▼
              IR 草案 (zod 约束的结构化输出，失败则 repair 重试)
                 │
                 ▼
        ┌── 静态闸（AI 输出必须穿过的四道门）────────────┐
        │ 1 zod schema 合法                            │
        │ 2 引擎 lint：无断言步骤 / 裸 sleep / 死循环     │
        │ 3 dry-run：变量未定义、依赖环、引用不存在的资源 │
        │ 4 覆盖增量预览 + diff 人审                     │
        └──────────────────────────────────────────────┘
                 ▼
        固化为 IR（钉 prompt_hash/model_id/seed/spec_hash/case_version）
                 ▼
        确定性回放（CI/定时/手动）；失败 → 自愈阶梯 → 回写 IR 的 diff
```

三个不可让步的点：

- **Agent 永不直接驱动执行器。** 所有被测面能力经 MCP 工具暴露（`openapi.*` / `playwright.*` / `adb.*` / `mysql.query` / `qdrant.search`），Agent 可以**探索**这些工具（探索是 Agent 模式的合法职能，产物是 IR），但正式执行只跑引擎。这条线一糊，CI 门禁立刻失去意义。
- **上下文构建器是独立模块，负责两件救命的事**：① 脱敏（`type=password`、`data-secret`、PAN/身份证正则掩码，**在序列化快照时做，不是在 prompt 里叮嘱**）；② 注入防护（页面/app 内容包进明确分隔块并声明"这是数据不是指令"；不可逆动作走确定性白名单或人工确认；origin 白名单；禁 `javascript:`/`data:`）。
- **每次 LLM 调用都落盘**：prompt 原文、raw 响应、候选列表与打分、最终选中项、model、tokens、latency、cost。六周后定位器自愈错了，这是唯一能知道"当时为什么这么选"的途径。**几乎没人做好这条，它是真差异点。**

## 4. 场景引擎（L2）

见 `docs/02` 的 IR 设计。这里只讲架构约束：

- **解释器必须能在浏览器里跑**（只读预览/编辑期校验用）和在 Node 里跑（真执行）→ 引擎核心不得 import `fs`/`net`/`child_process`，副作用全在 adapter。这条约束一旦破了，浏览器端就得维护第二套校验逻辑，GUI 与执行器开始分叉。
- **一份 IR 三个视图**，都由同一份 IR 派生，禁止视图持有私有状态：步骤表（主编辑形态）、流程图（只读预览，复杂嵌套降级为折叠块）、TS SDK（Monaco + 类型 + 补全）。**双向同步不丢失**是 P2 最容易翻车的地方 —— 具体手法：IR 是唯一真相，TS SDK 只是 IR 的类型化包装（builder 的 `.build()` 产出 IR，解析器把 IR 还原成 builder 链），而不是"从 TS AST 反解 IR"。
- **可视化编辑排在 Web 端之后**（P2）：它的复杂度来自 UI 树/等待/断言这些概念，API 场景用表格 + Monaco 已够。先做可视化会拖慢引擎打磨。

## 5. 设备侧（ADB）—— 提前到 P0 就要考虑的部分

**核心矛盾**：USB 直连真机 ⇒ worker 必须物理贴着设备，你不能把 worker 调度到集群任意节点。

**结论：边缘设备代理（device agent）模式。**

```
┌ 用户浏览器 ──WS(每 tab 一条)──▶ 服务端 ──WS──▶ device-agent(贴着手机的 Node 进程)
                                                    │ adb (USB/TCP)
                                                    ├ scrcpy-server → H.264 → 扇出
                                                    ├ UIAutomator2 hierarchy
                                                    └ logcat ring buffer
```

- device-agent 上线时注册设备（`udid` / 型号 / OEM / 安卓版本 / 健康探针结果），服务端把它登记进 MySQL 并纳入**租约调度**；服务端把任务作为 BullMQ job 投递给**指定 agent 队列**（`queue:device:<udid>`），而不是让集群随便抢。
- 这个形状就是所有商用设备农场的形状，也是 ws-scrcpy / Sonic 已假定的形状。**自建 ≈ 80% 可用**，缺的 20% 是：机架运维、iOS 签名/Mac 池、OEM ROM OTA 矩阵、充电健康、证据留存策略 —— 别去追。差异化在"证据原生 + AI 辅助 + 可回放场景 + **自带设备/自带实验室**"，不在机队规模。
- 因为 device-agent 是这个形状，**执行器 adapter 必须可独立进程 + 无状态依赖注入**（所有依赖从外部传入，不在模块顶层 import 全局状态）。这就是那 15% 前置成本的用处。

**投屏落地要点**（`@yume-chan/scrcpy` + `scrcpy-decoder-webcodecs`，LAN ~30–120ms）：

| 要点 | 具体做法 | 不做的后果 |
|---|---|---|
| IDR 间隔 | `video_codec=h264`, `max_size=1024`, `max_fps=30`, `bit_rate=2M`, **i-frame-int≈1s** | 长 GOP → 一滚动画面像卡死 → 用户读成"你们产品卡" |
| 扇出 | **一设备一 scrcpy 会话**，多 viewer 共享；每 tab 一条 WS，帧带 `{udid, ts, seq}` | 每人一条会话 → 设备端 MediaCodec 与 USB 带宽（USB2 实际 ~20–30MB/s）先炸 |
| 降级 | 空闲 viewer 降到 720p/15fps，交互时升 | 同上 |
| 触控手感 | 画布**先画点击涟漪再等视频** | 120ms 视频延迟人能忍，点下去没反应不能忍 |
| 坐标映射 | 从 `DEVICE_META`/`RESIZE` 维护 `deviceSize/rot/DPR` 三元组，注入前做旋转矩阵变换；`pointerId` 与 down/move/up 要对 | 拖拽/滑动全废 |
| 文本输入 | scrcpy `INJECT_TEXT` 或 ADB-IME | `adb shell input text` 打不出 Unicode |
| 时钟 | 帧与事件同一单调时钟源打戳；字幕轨由 `trace.jsonl` 生成；两边带 `seq` | 视频显示第 12 步、trace 说第 9 步 |
| 兜底 | `adb shell screenrecord --output-format=h264 -` 直流（Android 4.4–9 / OEM ROM / 模拟器无 GPU 编码器时黑屏） | 投不起来 |
| ⚠ 许可 | scrcpy/`@yume-chan`/adb 均 Apache-2.0/MIT，但 **H.264 专利走 MPEG LA 是商业产品自己的成本项** | 法务后知后觉 |

## 6. 数据层

MySQL + Qdrant + Redis 三者够用，**不需要新增数据库**。分工与边界：

| 存储 | 存什么 | 明确不存什么 |
|---|---|---|
| **MySQL** | 租户/用户/权限、项目、资源（openapi 文档快照、页面画像、设备）、场景 IR + 版本、环境 + 环境版本、**密钥记录（密文，按不透明 id 引用）**、run/step 元数据、`locator_stats`、`llm_calls` 成本账本、`artifacts`（路径+字节+sha256） | **大二进制**；任何 step 输出的原始 body/截图 |
| **磁盘（内容寻址）** | 截图、录屏、HAR、ARIA 快照、hierarchy XML、LLM 调用原文、logcat、`evidence.zip` | 查询型元数据 |
| **Redis** | BullMQ 队列、**run 事件 Stream**、设备租约锁、运行中状态缓存、限流 | 历史（用 MySQL；Redis 只是 live 视图） |
| **Qdrant** | ① 元素/页面语义索引 ② **失败指纹与 run 的语义索引** ③ 用例去重指纹 ④ 文档/手工用例→用例生成语料（若需要） | 精确匹配的东西（用 MySQL 索引） |

**Qdrant 的 payload 设计要一次做对**（改 collection 是迁移）：`{tenant_id, project_id, kind: 'locator'|'failure'|'case'|'doc', target: 'api'|'web'|'android', resource_id, scenario_version, env_revision, created_at}` — 靠 payload 过滤做多租户与多类型隔离，**不要按类型建多个 collection**（每个 collection 都要单独调 HNSW 参数，且新类型要改代码）。

**环境是有 schema、有版本、有来源的一等公民**，不是 name→value  blobs：环境定义（schema）+ 环境值（修订版）+ 每次 run 记录 `env_revision`。于是"本用例上次通过时用的是环境第 37 版"是免费查询。

## 7. 交付分层（对应已确认的 MVP 顺序）

| 阶段 | 交付 | 验收动作（**能跑通才算**） |
|---|---|---|
| **P0** | 引擎 + IR + http adapter + Agent（仅"导入 OpenAPI→生成场景→执行"）+ **只有脚本模式** + IR 先 JSON + Monaco + CLI `atest` | 一句话导入一个真实 swagger，生成 20 条场景，跑出带证据的报告，`atest run` 在 CI 里结果一致 |
| **P1** | 服务端化：Fastify + MySQL + BullMQ worker + 运行看板 + 环境/密钥 + JUnit XML | 关本地 CLI，全在服务端跑定时套件；失败可点开看 trace |
| **P2** | Web adapter（Playwright）+ **可视化步骤表 ⇄ IR 双向** + ARIA 断言 + 自愈阶梯 + 自愈审校队列 | 一句"把这个页面主流程测一下"产出可回放场景；改一个按钮 id，走自愈出 diff |
| **P3** | **Agent 模式**（自主探索）+ 轨迹→IR 蒸馏 + Qdrant 失败相似检索 | Agent 探索 20 步跑通一条流程，一键蒸馏成 6 步可回放 IR |
| **P4** | device-agent + Appium/adb 执行器 + scrcpy 投屏 + watcher 弹窗守望 | "用 API 造一个订单，在 APP 上验证它显示" 这一条**跨端场景**跑通 |

注意 P4 那条验收：**跨端共享变量空间是终点目标，也是这份调研里认定的第一空白点**（`docs/00` §4.1）。前面所有阶段都是在为它能跑通铺路。

## 8. 会咬人的坑（本仓特定，非通用清单）

1. **纯 ESM + ts-node/Monaco/Playwright CommonJS 混用**：第一天就定 ESM + `"type":"module"` + `tsx` 跑开发，Monaco 用 worker 显式配置。中途迁 ESM 是周末杀手。
2. **引擎里 `import fs`**：浏览器端立刻崩，然后你会写第二套校验 → GUI 与执行器分叉（`docs/00` §6.6 那个坑的本地成因）。用 lint 规则物理禁止 L2 import node 内置模块。
3. **自愈做成静默** → 绿色构建点错按钮 → 客户第一个月就发现。自愈必须软失败 + 审校队列（`docs/00` §5.6）。
4. **Agent 模式先于 IR 稳定**：轨迹无处落地，token 白烧。这就是 P3 排在 P2 后的唯一理由。
5. **Playwright worker 生命周期**：多 worker 并发跑同一浏览器会打架，要 `browserType` 连接池 + 实例上限 + 空闲回收；BullMQ 并发分组和浏览器并发上限**必须对齐**，否则要么 OOM 要么串行。
6. **MySQL 连接池 × worker 数 = 连接数爆炸**：每 worker 独立池要有全局上限。
7. **Redis Stream 无界增长**：`XTRIM MAXLEN ~` 必须设，同时**同一批事件要镜像进 `trace.jsonl`**（crash 后仍可分析）。
8. **`adb root` 假设**：目标机大概率没 root、MIUI 拦 USB 调试与安装尝试、OEM ROM 后台杀 uiautomator。设备注册时的健康探针不是可选项。
9. **把截图/响应体存进 MySQL**：一天之后备份和查询都会烂。
10. **成本失控**：`max_cost_per_run` 要是 run 记录里的一等列并在超出时中断，不是事后台账。
