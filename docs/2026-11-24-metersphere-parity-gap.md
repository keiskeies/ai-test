# MeterSphere 对照差距清单（2026-11-24 实测）

本清单以运行中的 MeterSphere 实例 `http://192.168.1.5:18000`（admin）为基准，
逐页只读采集后与本仓逐页核对。此前 `2026-11-20-metersphere-parity-audit.md` 的结论
主要来自源码/文档梳理，未做到实机逐页对照；本文件用来纠正这一个偏差。

- 本仓侧：按 `web/src/app.tsx` 路由 + 各页面源码逐列核对，行号见文中标注。

  「系统设置」未采集，因此本清单对这三块不下结论。

## 1. 可点击性（用户直接反馈的那类问题）

根因是 antd `Dropdown` 默认 `trigger=["hover"]`：点击不绑定打开动作 → 「点击无反应」；
悬浮时弹层随父组件重渲染反复挂载 → 「闪屏」。已统一改成 `trigger={["click"]}`：

| 位置 | 文件 | 状态 |
|---|---|---|
| 场景页「新建场景」 | `web/src/pages/scenes.tsx:597` | 已修，真机验证 |
| 模块树「更多」 | `web/src/api/ModuleTree.tsx:139` | 已修 |
| 脑图节点菜单 | `web/src/api/CaseMindmap.tsx:244` | 已修 |
| 列表模式「添加步骤」/ 行菜单 | `web/src/scene/ListMode.tsx:87`、`:248` | 已修 |
| 头像用户菜单 | `web/src/layout/shell.tsx:248` | 已修 |

真机验证（Chromium 1440×900、dpr=1）：点「新建场景」后菜单出现在按钮正下方
（按钮 bottom=171、菜单 top=175），完整在视口内；再点「空白场景」弹出「新建空白场景」。
此前自动化报的「菜单在 10403,6534 / 视口外」是自动化环境自身假象（960×632、dpr=1.25，
量到的是 antd 用于测宽的隐藏副本），不是产品缺陷。

**已补（D278）**：全站按钮/链接扫描完成——除上述 5 处外，其余候选均为
Dropdown/Popconfirm/Popover 的触发器（自动化把「触发器」误报成「按钮」），
未发现新的「点了没动静」入口。

## 2. 模块级差距（不是列宽问题，是整个能力缺）

| 项 | MS | 本仓 | 影响 |
|---|---|---|---|
| 性能测试 | 有独立模块（计划/报告/压测） | 无 | 整块缺失 |
| 标签体系 | 场景/接口/用例/计划都有「标签」列，可筛选 | 仅缺陷有 tags（`backend/.../defect/`） | 组织与检索维度缺一档 |
| 版本 | 列表有「版本」列 | `version` 只是乐观锁字段（`scenario/models.py:40`） | 不是同一个东西 |
| 场景多标签页 | 「场景列表」是可新建的标签页 | 单页 | 并行编辑多个场景受限 |
| 公共用例库 | 功能用例左树有「公共用例库」 | 无 | 跨项目复用缺 |
| 列表/看板切换 | 功能用例支持 | 只有列表 | 视图能力缺一档 |
