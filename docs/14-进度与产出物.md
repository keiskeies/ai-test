# 14 · 进度与产出物（截至当前 HEAD）

> 这份文件的写法约束：**每句"做了什么"后面跟一个能被打开的路径，每句"没做什么"直说没做**。
> 理由是本仓反复出现的那个缺陷类就是"看起来有防护，实际漏一个"（`docs/08` §3），

> 它比代码里的漏网更坏，因为下一个人是照着它决定做什么的。
>
> **本文刻意不钉测试例数。** 那个数每个 commit 都动，钉进来一小时内就过期
> （`docs/04` 里那句 `629` 就是这么烂掉的）。要数字：`npm test > /tmp/t.log 2>&1; echo $?`，
> 然后读 `# pass` / `# fail`。**别接管道再取 `$?`** —— 那取的是管道末端命令的状态，

## 4. 设计决策与**改变它们的证据**

只记"决策 + 什么证据让它成立或被推翻"。纯设计推导（没有反证的部分）在 `docs/01`–`03`，不重复。

### 4.1 Scenario IR 是唯一真相源，TS SDK 只做 builder

不做源码 AST 反向解析。理由不是"解析很难"，是**方向**：反解析会把"写法"变成真相，
于是同一语义的两种写法算出两个版本、格式化一次就产生新版本、lint 一改动指纹就漂。
现在的取舍是把规范化写进指纹算法本身（`ir/src/scenario.ts` 的 `canonicalScenario`），
四条规则各防一个具体事故：键排序但保留数组顺序、丢 `undefined` 键但不丢 `null`、
**不补默认值**（否则改一次 zod 默认值历史 `irSha` 集体漂移）、排除 `frozen`（生命周期状态不是内容）。
非有限数单独编码：`gen.with` / `trace.data` 这些逃生舱是 `z.record(string, unknown)`，
`JSON.stringify(NaN)` 产出 `null`，所以 `{min:NaN}` 与 `{min:null}` 会算出同一个 `irSha`
—— 探针确认过逐字节相同。**逃生舱正是该防的地方。**

> 本文件对上一轮的一处更正：我曾在 commit message 里写"改 `table.as` 的默认值会让历史
> `irSha` 集体失效"。**只对了一半**：zod 会把默认值填进 parse 结果，所以省略 `as` 的场景
> 指纹当时就已经带着 `"as":"row"`，改默认值一个字节都没动。代价被我写大了，
> 于是那一轮本该一起做的"改默认值"被推迟了一轮。错误不在结论而在**没跑一遍就报代价**。

### 4.2 引擎声明意图，adapter 应用方案（鉴权层的中心决策）

推翻的写法是引擎自己写 `headers.authorization = 'Bearer ' + secret(ref)`。三个后果里
决定性的不是架构洁癖，是**真值进了引擎内存** —— 于是它能通过任何一次
`keyContext`/`summary` 流到磁盘，而脱敏只按字段名与值形态补救，
`?api_key=abc123` 两条规则都不命中（值没有 JWT/AKIA/sk- 形态，字段名在 URL 里不存在）。
现在引擎只传不透明引用与身份名，值只在 `auth/apply.ts` 一处、发请求那一刻被取出。
这条同时兑现了「引擎能在浏览器里跑只读校验」（`docs/01` §8.2）—— 引擎不认识 Bearer/query/cookie。

配套的四条硬约束，每条都有测试：
- 配置文件**只收 `secret:<ref>`**，写明文密码不报错也能跑，直到有人把 env 文件提交上去（`auth/credentials.ts`）。
- 凭证取不到**就抛，不发没鉴权的请求** —— 裸发得到 401，而 401 在报告里的意思是"产品坏了"（`auth/apply.ts`）。
- oauth2 自己 `new` 一个不带 hook 的 client，让"给 token 请求再加鉴权"的递归**在结构上不可能**，同时仍透传 `fetchImpl`（SSRF allowlist 不能因为自建 client 就开口子）；token 值不进变量空间/证据/trace（`auth/token.ts`）。
- `auth-check` **只走 GET/HEAD**（诊断命令不许在流水线里产生业务副作用），结论五态不合并，
  且**500/404 算凭证被接受**（进到业务代码说明网关放行，报成鉴权问题会让人换一份好凭证继续 500 并以为新凭证也不对）。

### 4.3 缺陷类 (a)：「schema 有字段、执行侧没人读」—— 标题里不写次数

> **为什么标题里曾经写着"已十三例"，现在不写了**：那个数每轮都变、每轮都烂，
> 而**一个烂掉的计数比没有计数更坏** —— 它让人以为"这类一共就这些"，
> 而这一族本轮又添了两条（`docs/08` §3 那一行有明细与实测数据）。
> 权威清单在 `docs/08` §3 那一格里，本节只讲**为什么它值得单独立类**。
>
> **再说一句"本轮"**：这一节里**下面那一大段的"本轮"指的是接 `maxCostUsdPerResolve` 的那一轮**
> （本节标题以前写着"已十一例，第十一条本轮接上"，那个"本轮"就是它 —— 一份文档里
> 两个"本轮"指的是不同轮，读的人只能靠猜，所以改成显式说明）。
> 最近这一轮的几条（`expectNewPage`、`hoverThen`、四个 `ValueSchema` 位置、`formData`、`files[]`）
> **都不塞进下面那段叙述里**，各自登记在 §5 与 `docs/08` §3。

那十一条里最后那条 `locator.ts` 的 `maxCostUsdPerResolve` **本轮接上了**（引擎侧审预算），
但它换成了**这个缺陷类的第三个子类**，所以别把它读成"清完了"：
**接口上有字段、引擎里有判定、没有任何生产者** —— `ResolveResult.costUsd` 是本轮加的可选字段，
`adapter-web` 那一处真实的 `resolve()` **一行都没报它**（其余 adapter 压根没写执行侧）。
所以今天在生产里这条闸门**永不触发**，只是"报数就会响"。详见下面"第三个子类"那一节。
明细在 `docs/08` §3，这里只提**为什么它值得单独立类**：

- **症状会指错方向。** `scenario.inputs[].default` 没人读时，表现是"UI 里跑能过、CI 里必炸"，
  人第一反应是查 env 文件配错了。
- **有的实例是报告成功的。** `useIdentity` 只 `return {status:'pass'}` 什么都不切 ——
  权限矩阵用例（A 的资源 B 读不到）双方拿到同一个身份，表现为"权限测试全绿"。
- **更糟的一层：用例被丢了而报告显示它过了。** `parallel.maxConcurrency` 原来被读去做
  `slice` 的下标丢分支（`a53e161`），容器照样 pass、summary 说"并行 5 支"、覆盖率按分支数算。
  没有失败、没有告警、覆盖率还挺高。
- **本轮这一例的形状不一样：字段没人读，但有个常数顶在它的位子上。**
  `LocatorSpec.confidenceGate`（人写明"低于此值不算命中"）全仓 0 处读它，
  而两个调用点各抄了一个常数顶上去，**还抄得不一样**（解释器 `0.99`、`wait.ts` 的
  uiPredicate `0.5` —— 恰好是 schema 下限，最宽松那档）。
  前几条以"功能没生效"暴露，这一条以**结论方向错**暴露：
  写 `confidenceGate: 1.0`（"只接受完全匹配"）的人，在 0.99 上拿到 pass + 退出码 0（实测）。
  **有常数顶着比彻底没有更隐蔽** —— 行为看起来是"按置信度判的"，
  代码评审读过去也不会觉得少了一行。判据：字段注释里写着"低于/超过此值就怎样"的，
  去执行侧找那个"就怎样"，**找不到常数顶替就是缺失，找到了也要问一句它凭什么等于人写的值**。

因为这个缺陷类现在有**四个子类，得用四种办法防**（(d) 是本轮接 `wait{response}` 时撞出来的，见本节末）：

| 子类 | 判据 | 谁能答 |
|---|---|---|
| **(a) 压根没人读** | `npm run lint:fields`（机器，便宜） | 扫描器 |
| **(b) 读了但用错**（当成下标、走错分支、错单位） | **只有测试 + 变异检查** | `tooling/mutate/` |
| **(c) 读了、也判了，但没有生产者** | **两者都答不出**：扫描器看见"读过"，测试因为"缺数不拦"而绿 | 只有"跑一次真 adapter 看那个数进没进账" |
| **(d) 性质只在某一层显形，而测试全在另一层** | 上一层的测试**结构上**看不见它：假流永远连续、真浏览器永远跑不到第 5001 条 | 只有"在那一层写测试" —— 先问"这个性质破掉时，**哪一层**会红"，答不出就是还没测 |

(c) 是本轮接 `maxCostUsdPerResolve` 时**新撞出来的形状**，前两种办法都抓不到它：

- 扫描器把它算成"读过"（`locatorBudget` 是成员访问 + 名字唯一，强证据），并要求删掉豁免 ——
  **删了豁免就等于把"还没有生产者"这件事的最后一个记录抹掉**；
- `engine/test/locator.test.ts` 那 9 条用桩 adapter 报数，全绿。它们验的是
  "**如果**有人报数，闸门会不会响"，这个问题答对了也不说明有人报数；
- 我自己一度把这条当"做完了"，是因为看到测试 19 条全绿 ——
  是回头 grep `async resolve` 才看见**全仓只有一处真实现**（`adapter-web/src/ui.ts` 里 `UiExec` 的 `resolve`），
  而它返回的是 `{resolvedBy, rung, confidence, nonReplayable, handle}`，**没有 costUsd**
  （引用这里从前写的是 `ui.ts:100`，本轮 ref-lint 验过那一行早已是别的东西）。
  所以闸门今天**一次都不会触发**。

**(c) 后来又换了一个表面，而这次的载体是"对外 API"而不是 IR 字段**：`exit.ts` 的
`ABORTED = 10` 从写下那天起定义着、`CI_HINT` 印着"10 被中断"、`WORSE_ORDER` 给它排了序，
而**全仓没有一条路径返回它** —— 各包 src 里 `process.on`/`addListener` 零命中（对 HEAD 验过），
`runOptions.signal` 没有生产者。判据在（`gate.ts` 读 `report.aborted`）、码在（`EXIT.ABORTED`）、
消费方在（流水线照 `CI_HINT` 分流），**缺的正是"谁来返回它"**。完整故事与三处断点见 `docs/15` §3.7。

**这条值得单独记的不是缺陷本身，是我给它登记时犯的错**：我在三处注释里把它写成
"§4.3 的**第四种**形状"，又在四处写成"**第五种**形状" —— **同一个东西，两份不同的编号，
而两份都是错的**。§4.3 只有 (a)–(d) 四个子类，而它**结构上就是 (c)**：
"有名额 + 有判据 + 没有生产者"，只是载体从 IR 字段换成了对外 API。
`docs/15` §3.6 末段早就写着这条纪律（**"同一个缺陷类不等于同一个子类，
硬编号会让下一个人以为有一套五种防法"**），我写下那七处编号的时候没去读它。
现在那七处统一写成"子类 (c) 换到对外 API 这层上的复现（不另立编号）"。
**为什么会漂**：编号是**引用**而不是描述，写的人不需要知道那一族有什么；
写成描述（"契约有名额而执行侧没人兑现"）则任何人读到都能拿去和表对照。
**凡是往代码里写"第 N 个子类/第 N 例"，先跑一遍那张表看看它到底排第几** ——
与本节上面那句"记功之前先跑一条命令验证它真的报过"是同一条纪律，只是方向相反：
那条防的是给量不到东西的尺子记功，这条防的是给已有类目乱编序号。

处置（不是"补一行 `costUsd: 0` 让它齐"，那正好是 (c) 最坏的伪装 —— 一个假的零会把
"没有生产者"永久伪装成"生产者说免费"，从此谁也不会再问）：

1. `locator.test.ts` 里那条 **"adapter 没报 costUsd => 一律不拦"** 是**故意**的：
   现在没有任何 adapter 报数，若把 `undefined` 当成要拦的值，
   接上线的那一步就把**所有现存用例判红**，而下一个人的修法是把预算判据整段删掉。
   缺数只能当"没得审"，同时把"缺数"这件事记在下面这张表里，让它有个可查的归属阶段。
2. `ResolveResult.costUsd` 的注释里明写"**不要为了字段齐编一个小数**"。
3. `docs/08` §3 那一行从"执行侧没人读"改成"引擎侧已审，缺生产者"，归属仍是 P2.5。

`maxConcurrency` 那条扫描器**报不出来** —— 解释器确实读了它，只是用法是丢分支。
`confidenceGate` 是同一堵墙的**另一个方向**：它一旦被 `wait.ts` 读到，扫描器就把它算成"读过"
并要求删掉豁免（本轮扫描器自己报的，豁免已删），**于是"另一处用错常数"这件事从此更看不见了**。
所以这一族新增的守门人不是扫描器，是 `engine/test/locator.test.ts` 那一族
（`confidenceGate` / healed 同源 / `maxCostUsdPerResolve` 三组；**条数别抄在这里** ——
`node --test packages/engine/test/locator.test.ts` 一条命令就有，写死它它就会漂，
上面那三个扫描器数字就是这么漂掉 10 条的）。
**但它守不住 (c)**：桩 adapter 报数它就绿。所以每一族新加"闸门"时要分开问三句：
谁读它（扫描器）、读法错了会怎样（测试 + 变异）、**有没有人真的供这个数**（只有读真 adapter 的代码）。
扫描器的真实作用是把我**领到**那段代码（它把整个 parallel schema 拎出来让我逐字段过），
不是报告了那个缺陷。归因在 `9b09547` 里被更正过一次：给一把量不到东西的尺子记功，
下一个人就会照着那句去信它。**记功之前先跑一条命令验证它真的报过。**

扫描器本身现在是三级判定 —— **读过 144 / 判不出 233 / 未读 85（全部已豁免）**（共 462 字段，`npm run lint:fields` 一条命令就是现在的数；上面那句刚写的时候它是 142/230/88 共 460，**本轮 SQL 绑定那三条 `vars` 把它推动了**）。判不出比上一版多 3 的**具体三条**写在 `unread-baseline.json` 的 `_ceiling_comment` 里：`wait{dbRow}.vars` 与 `dataSource.source.vars` 进（引擎真读了，但 `vars` 这个名字现在在三个 schema 里各声明一次 → `declCount>1` → 只能判不出），而 `DbStepSchema.vars` **不是新增而是归因变差**（它先前算"读过"，被那两个同名兄弟挤出去）。

**这一格与上一轮那 +1 是同一个形状，三条 id 也都还在 baseline 的注释里、没被本轮覆盖掉**：
`expectResponse` 那两条也是"真读了但同名撞车"，而 `urlPattern` 那条是反方向 ——
以前没人读、现在 `wait.ts` 真拿它匹配，于是从"未读"搬进"读过"。

**净 +N 从来不是因为代码变差，是因为"没人读"变成了"读了但归不出"** —— 这两件事在数字上完全同形，所以只能靠把 id 列出来分辨（"测量变准了"与"测量变瞎了"在数字上长得一模一样，是这一节反复出现的那条纪律）。
上一轮那三个数（142/230/88）是接 `maxCostUsdPerResolve` 时实测的；
而这里此前写的是"读过 131 / 未读 100"，**它在本轮之前就已经漂了 10 条** ——
后面修掉的每一条缺陷都会把一条未读搬到读过，而没人回头改这句。
所以引用这三个数之前先跑那条命令，别把这里当实时源（这正是本仓对"注释里的数"的一贯口径）。

- **读过** = 有强证据（`.foo` 成员访问 / `{ foo }` 解构）**且**该名字全局只声明过一次；
- **判不出** = 只有裸词命中，或同名出现在多个 schema 里；
- **未读** = 一个命中都没有。只有这一级是扫描器能负责的。

关键是**别让"判不出"冒充"读过"**。起因是具体的：`as` 在消费者代码里有 200+ 处裸词命中
（全是 `x as Type` 的 TS 断言），用裸词判"读过"就把**真没人读**的 `table.as` 算成"读过"，
扫描器对它永久失明 —— 而我当时在 commit message 里写了"已登记进 baseline"，**那是假的**，
它根本没报。判不出那 229 条不逐条要求豁免（会淹没新增未读），改为钉**上限**并省略即失败。

**这条纪律本轮在两个地方漏了，漏的方向都是"催人删掉还在用的豁免"**（`report.html` 那一轮撞出来的）：

1. `classify()` 判"豁免过期"用的是"不在 unread 里"，而**不在 unread 包含两种意思**：
   有强证据说它被读了 / 只是扫不出。后者被当成前者，就会让人删一条仍然需要的豁免 ——
   删掉之后那条字段一旦落回 unread，报错写的是"新增未读字段"，
   没人会想到是自己刚剪的线。触发它是具体的：html 模板里的 `<meta name="viewport">`
   给 `EnvFingerprintSchema.viewport` 造了一处裸词命中。
   （同源的 `scenarioId` 那条走的是**改名**而不是改判据 —— `opts.scenarioId` 是**真** member
   强证据，改判据救不了它，只会让 `--evidence` 给出
   `BaselineSampleSchema.scenarioId <- html.ts` 这种指着不相干入参的假证据。
   曾考虑"强证据若只落在消费者自家 interface 键上就降级"，**实测会误伤 35 条**
   （`keyContext`/`artifactIds`/`costUsd` 这些真读了的都在里面），所以放弃。）
2. `collectTokens` 取字符串词跑在**原文**上，于是**注释里的引号词也算命中**。
   实测 157 个 token 只活在注释里，其中 5 个是 IR 字段名，于是
   `OperationSchema.amount` / `ScenarioVersionMetaSchema.ver` / `LocatorRuleSchema.role` /
   `DeviceRequirementSchema.requires` 四条**一行执行代码都没读过**的字段
   从 unread 掉进判不出而躲过门禁。**本工具存在的目的正是抓这一类，结果它自己被这一类糊住了。**
   最讽刺的是触发方式：为了躲开 (1) 里那个假强证据，我写了一段解释"为什么别叫 scenarioId"的注释，
   注释里带着那个词的反引号 —— **写注释把字段藏得更深**。

两条的共同点是**"测量变准了"和"测量变瞎了"在数字上长得一模一样**（都是某个桶少了几条），
所以判不出的上限从 233 收到 229 时，旁边必须写清是哪次修复动的、动了哪几条。
新增未读那 4 条**逐个核实过才进 baseline**（无 UiExec 实现、无版本表、全仓无 `'scroll'` 分发处），
没核实就登记等于把扫描器刚找回的可见性再交出去一次。

> **本轮又撞出一个子类，编号 (d)，因为它和前三种的抓法都不一样。**
>
> 接完 `wait{response}` 之后我按上一轮写下的自查动作去"跑真 adapter 确认有人供数"，
> 于是有了 `adapter-web/test/network.test.ts`（真 Chrome）。
> 它们全绿 —— 但**做变异检查时漏了两个**：
> 把缓冲的"淘汰最旧"改成"淘汰最新"、把绝对下标改成跟着数组长度走，**它们一条都没红**。
> 原因不是测试写松了：淘汰只在**第 5001 条响应**到来时发生，而一次 navigate 只有几条响应，
> 真浏览器测试**永远到不了那一层**。同理，引擎侧那批用的是假流，
> 而假流的切片**永远连续**，所以"游标按条数推进"这个错（我第一版就是这么写的）
> 也全绿 —— 它默认了"没人淘汰"这个 adapter 并不给的性质。
>
> 所以这一族的判据要加一句：**(d) 的修法不是把测试写得更狠，是把逻辑搬到能观察它的那一层。**
> 具体做法是把缓冲从 `session.ts` 里拎出来成 `response-buffer.ts`（纯逻辑测试 + 变异集
> `tooling/mutate/response-buffer.json`：抓到 5、另有 1 条**标了 equivalent** —— 那条是
> "把 5000 改成 4999"，没有任何形状能观测到具体数值，所以它**不该**被抓到；
> 我先前在别处把它写成"全部被抓到"，那是把 equivalent 记成功劳，属 §4.5 列的那类假账），
> 并给 `ObservedResponse` 加 `idx`（绝对下标由 adapter 带着走，

>

> 本机 Chrome 压根不产 status 0 的条目，所以删掉那个过滤，`network.test.ts` 也不会红。
> 这件事写在测试文件的注释里而不是抹平，理由与 §4.3 全篇一样：
> **一条"看着被守着其实没有"的性质，比一条明确登记为没做的性质危险。**

### 4.4 缺陷类 (b)：「测试通过的原因和它想验的东西无关」—— 它的测试侧镜像

九例（M6 四例 + 鉴权轮五例）。新形态的共性是**fixture 让两种不同实现算出同一个值**：
验"用解析结果 vs 直接用步骤声明的值"时，步骤声明了 `operationId` 的话两种写法算出来一模一样，
三条变异全部存活。**修法不是补断言而是换 fixture**，让两种实现必须给出不同结果。
本轮新增两例，都是"标题与内容无关"：

- `control.test.ts` 里一条测试标题写着「dataSource + table」，正文里**只有一个 table 加一个 assert**，
  压根没有 dataSource 步骤 —— 所以 `dataSource.as` 没人读这个真缺陷它一次也抓不到，
  而标题会让人以为这块测过了。
- 一条验"分支被 abort 掀翻"的测试第一版是**空的**：信号一上来就 `true`，
  第一个步骤的 `checkAbort` 就把 run 掀了、压根进不到 parallel，而断言照样成立。
  改成池子跑到中途才置位。

本轮 `report.html` 那一轮又添一例，形状是**输入压根打不到被测分支**：
白名单测试验"非法成员名不会变成链接"，判据写得很严，
但 fixture 只喂过一个合法 sha —— **近似名从来没进过白名单**，
把成员名的正则转义整段删掉，六条全绿。查下去发现更彻底：
`memberHref` 的成员名那一支**没有任何不可信输入能打到**（调用方要么带
`artifacts/` 前缀、要么喂 EVIDENCE_FILES 常量），于是"测转义对不对"在这**永远零覆盖**。
处置不是补断言也不是换 fixture（这条连可达输入都没有），而是**换构造**：
大正则换成 Set 精确相等，"忘了转义"这个失败模式整个消失。
同轮的 `htmlAttr` 变异存活是**如实的**（同样无可达输入），标 `expect:"equivalent"`
连理由一起留在 `tooling/mutate/html-report.json`，另有一条测试守
"属性位置不接收不可信文本"这个**构造性质** —— 将来谁把 `esc()` 用进属性位，
红的是那条。**测不到的东西要标成测不到，不要写一条打不中目标的测试冒充守住了。**

本轮 `expectNewPage` 又添一例，形状和前九例都不同：**"有没有"的断言永远看不见"多算了几次"**。
八条真浏览器测试每条问的都是 `after > before`，于是把计数判据从"只认 `targetCreated`"
放宽成"created 与 `targetInfoChanged` 都算"之后（一次开窗会加 **2**，因为子页面导航到真实 URL
那条 `targetInfoChanged` **也带着指回本页的 openerId**，实测），**一条都没红**。

这一例值得单独记，是因为**我从它推出过一个错结论并写进了两处代码注释**：
"改坏了而测试没红" ⇒ "那道过滤是冗余的"。前半句只允许推出**"测试不够"**，
它完全不能区分"这段代码没用"与"这段代码有用而我的断言看不见"。
后来是**探针**（不是测试）把真相打出来的，补了一条"一次开窗只加 1"的测试才真正抓住。

所以判据要加一句：**(b) 里"断言看不见"有一种隐蔽子类 —— 断言的**量纲**与被测性质的量纲不同**。
被测的是"计了几次"（计数），断言问的是"有没有增加"（布尔）。
这种错**不会因为把断言写严而消失**（`after > before` 已经写得不松了），
只能靠**问对问题**："这个性质破掉时，我的断言比较的那个量会变吗？"
`=== before + 1` 与 `> before` 差的就是这一个量纲。
顺带那条测试还顺手成为"扩展的 service_worker 被误计入"的对照 —— 一道测试同时守两个方向。

**判别办法**：(1) 变异测试当常规步骤；(2) 判据尽量交给**独立实现** —— JUnit 交给 CPython 的
expat、zip 交给系统 `unzip -t`，不要用自己的导出器验自己的写入器（那是循环论证）。

### 4.5 变异测试当常规步骤，以及 harness 的八个坑

`docs/08` 早就写着"变异测试当常规步骤"，但一直没成工具，每次手改代码试一遍，
代价是同一类坑反复踩 —— 共同点是**"看起来跑了而结论是假的"**：

1. `execFileSync` 在子进程非零退出时丢 stdout → 一次真的抓到被记成"无法判定"。
2. 跨包改 src 不重建，跑的是旧 dist → 真抓到被记成"未被抓到"。**最坏的一种**：
   它让人给一条没守住的断言补上"已验证"，而下一个人不会再去怀疑它。
   现在由 `mustBuild()` 机器判，不接受 spec 手填 `build:false`。
3. 锚点里中文变 mojibake 匹配不到而静默跳过 → **跳过与"未被抓到"意思相反**
   （一个是"这次什么都没测"，一个是"这条断言挡不住"）。现在单独报 `ANCHOR_NOT_FOUND`。
4. **变异过的 dist 会留在机器上**（比前三条隐蔽）：每个 case 只还原 src，
   而跨包 case 是在 src 改坏的状态下 build 的，跑完 src 干净、dist 还是变异版 ——
   下一个"同包不重建"的 case 读的就是它，**本次运行内的结论成串地错**。
   现场症状是"一条标 equivalent 的变异意外被抓到"，追进去发现是被上一条串了。
5. **破坏编译的变异产出的是 BUILD_BROKEN（无结论），不是"抓到了"。**
   变异必须写成**同形可编译**的改动。（我把 `walk(...)` 换成 `for...of` 时收尾 `});` 配不上对，
   编译直接挂 —— 那不能算抓到。）
   **同一个坑本轮又踩两次，而且两次我都以为自己在写一条正常变异**：
   ① `if (r.evalError)` 改成 `if (false && r.evalError)` —— TS 会对恒假条件把块内所有量收窄成
   `never`，于是里面那个 `s.onTimeout` 直接 TS2339，一条本来测"解释器不看这个字段"的变异
   变成没结论（改成 `if (r.evalError && r.polls < 0)`：同样恒假，但类型正常）；
   ② 把 `s.source.type === 'mysql'` 改成 `=== 'qdrant'` 来模拟"漏查一处 SQL 挂载点" ——
   看着比删整行更自然（qdrant 那一支本来就没有 SQL），但那样 `s.source.sql`/`.vars`
   在类型上压根不存在，又是 TS2339（改成**类型安全地删掉那一行**才问到真问题）。
   共同形状：**TS 的类型收窄会把"逻辑上等价的小改动"变成"编译不过的大改动"**，
   而它报回来的样子很像防护生效（确实也是一种防护），所以极易被顺手记成抓到。
   一条变异在写进 spec 之前先手跑一次 `npm run build`，比跑完整份再看到 BUILD_BROKEN 便宜得多。
6. **同一份工作树里跑两个驱动。** 两份驱动改的是同一份 `src` 与同一份 `dist`：A 施加变异 1、
   build、正在跑测试时，B 把 src 换成变异 2 并重建 —— A 那份测试读到的代码与 A 记录的变异无关。
   **它的红绿都还是真的红绿，只是不再回答 A 想问的问题**，所以这种污染不会以报错的形式出现。
   更坏的方向是**制造 caught**：A 看到红就记"这条断言已验证"，而让它红的可能是 B 的改动
   —— 文档里于是多了一条永远不会失效的"已验证"。
   **这条的教训本仓记过两次，两次都只写进注释，第三次还是同一个会话里我自己犯的**
   （后台一份、前景又一份，于是同一份 spec 交出 12/2 与 14/0）。
   现在改成"跑不起来"：`tooling/.mutate.lock.json` 单实例锁。
   **但同一轮立刻撞出这把锁的一个缺口：它拦的是"两个驱动同时改 src"，
   它管不到"外层那个 for 循环自己跑了两份"**（我为了后台跑扫描写了个 shell 循环，
   重复启动了两次）。被拒那一侧的行为是确定的：驱动 `process.exit(2)`，
   而且**拒绝时保留对方的锁**（`mutate.mjs` 里那句"覆盖掉别人的锁等于把并发问题藏起来"），
   所以第二份循环里每一份 spec 都会同样被拒 —— 而**"外层跑了两份"这件事
   从此不会再产生任何报错**，锁把并发挡住了，也就顺手让并发没有了症状。
   ⚠ **我一开始把这段记成"日志里只剩一份的结论、看起来却像正常跑完"，
   那是推断不是观察。** 回查时（日志被重定向在 `.scratch/`、而循环开头是 `: > log`，
   每次重启都清空）锁拒绝的行、重复的 `=====` 头部**一条都找不到** ——
   也就是说那个说法**从没能被证**。撑得住的只有代码层面的两件事：
   那个循环不读 `EXIT=$?`，被拒之后照样往下跑下一份 spec；
   而它确实写了 `EXIT=`，所以真要查是查得出的（17 行 `EXIT=2`），
   "看不出来"是我没去查，不是它藏了。
   收尾更糟：我在没弄清状态时 `pkill` 了整个进程组，
   其中一个是**正在施加变异时被杀的**，`src` 于是留下变异版
   （锁里那条 `inFlight` 与磁盘上的差异逐字节对得上）。
   那正是 `detectResidue()` 设计要抓的状态，**而这次是我亲手造的**。
   三条结论：**(1) 外层循环也要有自己的重入保护**（发现第二份就退出，绝不抢）；
   **(2) 清理一个自己不理解的状态之前先读它的锁与 diff** ——
   `inFlight` 字段在那次是现成的证据，我先动手才想起它存在；
   **(3) 外层不许把 `EXIT=2` 当"这一份跑过了"** —— 2 是"没跑"（用法错 / 锁被占 /
   现场有残留），把它计入总数就会交出一个从没跑过的"全绿"。
   这条现在是 `tooling/mutate-all.mjs` 里的硬停，不再靠人读日志（同一条 class (a)
   的另一个方向：**判据在，没人读，就等于没有**）。
7. **"还原完成"以前是相信 `finally` 的，现在是核对的。** `finally` 里写了
   `writeFileSync(path, original)` 不等于写成功了（磁盘满 / 格式化工具恰好在中间写一笔 / git 钩子）。
   现在每条 case 还原后**比对内容指纹**，不一致判 `RESIDUE` 并中止剩余条目，
   而且把没跑的条目**也写进结果表**（`NOT_RUN`）—— 否则一份 14 条的集子在第 3 条炸掉后
   表上只有 3 行，"跑了 3 条"与"一共 3 条、跑完了"扫一眼长得一样。
   配套还有一道**开跑前**的 `detectResidue()`：上一轮死在中途时，本轮读进来的 `original`
   **本身就是变异版**，于是"还原成 original"永远核对通过、每一轮都自认为干净，
   而全部结论是在变异版代码上跑出来的 —— 那种状态里 src 看着"就是原来的样子"、没有任何一处会报错，
   **必须换一个独立信号**才看得见。

8. **测试一条都没跑，而输出长得像"全绿"**（本轮补）。触发它的是**真浏览器测试**：
   `adapter-web/test/browser.ts` 在找不到 Chrome 时把每条变成 `test.skip`，
   而 node:test 对"全部跳过"给的是 **`# pass 0` / `# fail 0` / 退出码 0**。
   于是 `testRed` 是 false，于是判据记下**「未被抓到」= 这条断言挡不住** ——
   而真相是一条测试都没执行。这是本类缺陷的**第四个入口**
   （锚点没命中 / 编译不过 / 还原没干净 / **压根没跑测试**），
   也是四个里最阴的一个：**前三种都在输出里留下显式痕迹，这种留下的是"全绿"**。
   现在多一档 `NO_TESTS_RAN`，归进"没跑成"而不是"未抓到"。
   它影响的不只是判读，还有**整份 spec 的前置条件**：`new-page-web.json` 那五条
   在没有 Chrome 的机器上**一条结论都给不出**，这件事写在 spec 文件头而不是逐条重复。

   **写这道守卫的时候，守卫自己是坏的**，而且是被我给它的测试抓出来的：
   正则写成 `/(^|\n)# pass (\d+)/`，数字落在捕获组 **2**（组 1 是那个换行边界），
   而代码读的是 `[1]` —— `Number("\n") === 0`，于是**只要两行汇总都在就恒真**，
   连"7 条全过"都被判成"没跑测试"。改法不是更小心，是**换一种没有边界捕获组的写法**
   （`^…$` + `m`），让 `[1]` 只能是数字。记这条是因为它是本仓那一族缺陷的**正字反写**：
   **条件写得永远成立，而它看起来像在认真工作** —— 一条本该拦"假结论"的守卫
   自己就成了假的，且它伪造的方向是"什么都没跑"，会让人把一整轮真结论全部重跑一遍。

第 6、7、8 三条的判据都是纯函数（`decideLock` / `detectResidue` / `noTestsIn`+`classify`），测试在 `tooling/test/mutate*.test.mjs`：
纯函数测判定、`mutate.lock.test.mjs` 真起子进程测"驱动照做了没有"、
`mutate.specs.test.mjs` 拿**仓库里全部真变异集**回归误报面。
最后一份存在的理由是**误报与漏报的代价不对称**：误报的代价不是"多报一次"，
是**人学会无脑 `--force`**，那道闸门从此形同虚设（`detectResidue` 写的时候我自己踩出两个误报，
都是"每次运行都会误拦"那种，靠手写 fixture 想不到）。明细在 `docs/08` §3 的 (e)(f)。

### 4.6 并发下的作用域模型：从"静态拒"改成"每支一份局部作用域"

`VarSpace.frames` 原本是**整个变量空间共享的一条栈**，并发子步骤各自 `push`/`popTo` 同一条。
三条探针实测（不是推演）：

- 两支写同一个名字：同一份 IR，h1 先完成 → 断言 pass；h2 先完成 → **同一个断言 fail**。
  谁的 `vars.set` 后执行谁算，而那是调度顺序。直接破 M7 的"同一冻结场景跑 20 次断言一致"。
- 一支带 `forEach`、另一支提到同一个循环项名字：A 支的断言读到了 **B 支的循环项值**，
  B 支随后"变量未定义"（A 支的 `popTo(depth)` 把 B 支刚压的帧一起弹掉了）。
- **第三条，也是推翻上一版处置的那条**：A 支带 `forEach`、B 支 `set` 一个**它自己新声明**的名字
  （两支互不提到对方的名字）。B 那句 `set` 走到 `declare`，写的是**当时栈顶那一帧** ——
  而那一刻栈顶是 A 支的迭代帧。A 迭代结束把帧弹掉，B 写进去的值跟着没了：
  **B 报 `pass`、容器报"并行 2 支 pass"，而事后 `$mineOnly` "源未找到"。**
  同一份场景把 A 支换成 `sleep` 就一切正常，唯一的自变量是"有没有别的分支压帧"。

上一版的处置是 `parallelHazards()` **执行前静态拒**两条写法，并写明"这是盾牌不是功能"。
第三条漏判出现后有过一次真实的岔路：**再加一条判据**（一支压帧 + 另一支新声明名字）。
没这么做，两个理由：

1. 那条判据拒掉的正是"并发各自收集结果、parallel 之后统一断言"—— 并发最主要的用法。
   **闸每加宽一次，parallel 能写的形状就少一片**，而一个用不了的功能跟没有功能一样，只是多了个报错。
2. 加规则是在**追根因的下游**。根因是"帧栈只有一条"，而它可修。

**改成的做法**（`engine/src/vars.ts` 的 `forkBranch` / `adoptFrom`）：
**global 帧按引用共享，各支只给自己加一帧**。于是三条性质同时成立，而它们并不显然同时成立：

- 分支里**新声明**的名字落在本支帧里，别人看不见，也不会被别人的 `popTo` 弹掉；
- 分支里写一个**parallel 之前就已声明**的名字，照旧落到共享那一帧 ——
  docs/02 §5 推荐的累加器写法行为一个字节没改。**这条是实测出来的**：
  预先 `set mineOnly = 0` 之后同样的并发就不丢值了，所以合并判据只需区分"帧里有没有"；
- 步骤导出各支一份 Map，两支 `saveAs` 撞名从"谁后跑谁算"变成物理上不可能。

收尾合并在 parallel 容器做，**按分支声明顺序**并回**外层栈顶那一帧**（不是 global ——
parallel 常写在 `forEach` 里面，提到 global 等于让循环内的并发漏到循环外，
那是原缺陷的镜像：一个是值凭空消失，一个是值凭空活着出去）。
**用声明顺序而不是完成顺序**是 M7 确定性的前提：完成顺序会让同名由"谁先跑完"决定。

合并判据用 `has()`（**只看帧**）而不是 `knows()`（帧+inputs+env）。
理由是**并行必须与顺序同语义**：顺序执行时 `set token` 而 `token` 只在 env 里，
走的是 `declare`，遮蔽它；用 `knows` 就会跳过合并，于是**同一步写在 parallel 外生效、
挪进 parallel 里被静默丢弃** —— 同一份 IR 换个位置换语义，正是本仓那个缺陷类。
（这条不是推演：`tooling/mutate/scope.json` 里有一条专门把它换回 `knows`。）

**改造成本远低于上一版的估计**（原话说要贯穿"36 处 `vars.` 调用"）：
把闭包变量**改名**成 `rootVars`，再给 `runStep`/`runChildren`/`dispatch` 加
`vars: VarSpace = rootVars` 就够。**改名是关键那一步** —— 漏改的站点会读 `rootVars`
而编译不过，而不是静默读到共享作用域（那种 bug 的表现是"并发用例偶发失败、单跑必过"）。
`resolveValue` / `interpolate` 的 `vars` 是**必填、无默认值**，同一个理由：
给了默认值，"忘了用分支作用域"就编译得过去。

**闸因此收窄到一条判据**（两支写同一个名字），但**没有删** ——
隔离只解决了"运行中互不干扰"，没解决"收尾只能留一份"。
两支同名时先声明者赢是**确定的**，而**确定的错答案比随机的错答案更难被发现**，所以宁可拒。

**仍未闭环的两件事**：(1) 同名是拒不是有解；(2) 判据**路径不可感** ——
两支的 `if` 条件互补（`$flag` / `!$flag`）时运行时只有一支会写，合并也只有一份，
但实测仍然拒（lint error + 解释器 error）。**这一处过近似是明知故犯**：
要放行得证明两个表达式互斥，而 IR 里守卫是字符串；只认"字面量取反"那种最浅的形状
会做出一面**看起来像修复的盾牌**（作者写 `$flag` / `$notFlag` 照样被拒，
文档里却写着"已支持互斥守卫"）。放宽判据与收紧判据是同一回事，**做半截比不做更坏**。
代价可控（改名或拆 sequence，fix 文案就写着这两条），边界钉在 `ir/test/parallel-hazards.test.ts`。

判据与对照组在 `engine/test/scope.test.ts`（每个"拒"都配一条形状相近但必须**放行**的对照 ——
只测"会拒"的话，把 parallel 废掉的实现也能全绿），变异集 `tooling/mutate/scope.json`。
其中一条变异（"分支不加自己的那一帧"）**第一版全套 0 失败**：各支仍有自己的帧数组，
值不会消失，所以"原缺陷"那条看不见它 —— 补的判据是"一边写、另一边在**同一次运行中**去读"。
**隔离必须在过程中也成立，只在结束时成立不算隔离。**

### 4.7 「永不到达的分支不要留」

`parallel` 的 `failFast` 拉闸点原先在 `try`/`catch` 两边各写一次，而 catch 那一次
**今天压根到不了**（`runStep` 把除 `RunAborted` 外的异常全收敛成 error 结果）。
证据不是阅读，是一条**变异存活**：变异它测试不红。于是把实现改成单点，
而不是给死代码补一条测不到它的测试。**删掉永不到达的分支，比给一个"看起来有防护"
的东西配一条测不到它的测试诚实。**

同一条判据作用在扫描器上：掩码不配对时**整个对象跳过**，而不是在错范围里抽键 ——
抽出一个不存在的字段名，它会进 baseline、会被人当真字段去查。

### 4.8 「修好了」与「修好了且有人守着」是两件事

零迭代循环那一件（`while` 条件第一次就为假 / `forEach` 拿到空集合）里，
**实现做完之后 `npm test` 是 751/751 全绿的**，我差点把它读成"改动被现有测试覆盖了"。
它一条都没覆盖：把两侧留痕**同时**抹掉再跑，引擎 232 条**照样全绿**。

这不是"忘了补测试"那么轻。它意味着**我手上的绿并不区分"行为在"与"行为没了"**，
而这一轮的改动恰好就是加一个行为。所以顺序得反过来：先问"删掉它会不会有东西红"，
答不出就等于这条改动没有被任何东西守着 —— 与 §4.4 那条缺陷类同一个，
只是这次未覆盖的是**我刚写的那段**，不是我接手的那段。

补上之后 `tooling/mutate/loop-never-run.json` 里特意留了一条**只改预编译一侧**的变异，
用来区分两种本来会被混起来的失效：

| 失效 | 属性测试（"两种形态一致"） | 本轮新加的判据 |
|---|---|---|
| 只有一侧漏留痕（形态分叉） | 红（两边不等） | 红 |
| **两侧一起漏**（都静默，但仍然一致） | **绿** ← 这就是 751/751 那次 | 红 |

"一致"与"正确"不是一回事，而属性测试只买得到前者。

同一轮还当场删掉一条我自己刚写完的**恒过断言**：`assert.doesNotMatch(g.said, /全部通过$/)`
—— 门禁理由串永远以「（不算通过，也不算失败）」收尾，那个正则在实现对不对都恒不匹配。
它与 §4.4 那批"标题与内容无关"的测试是同一种东西，只是这次是本次会话新产的。

**同一个盲区本轮又交了一次学费，只是这次红在另一道门上**：我写的绑定测试带着 4 个类型错
（把桩 adapter 收到的表声明成 `Record<string, string>`，而 `DbExec` 端口是
`Record<string, unknown>`），而**这期间 `npm test` 一直是全绿的**。
原因不是测试写松了，是那道门压根不看类型 —— `test` 脚本走 `--import tsx`，
**tsx 只剥类型、不查类型**，类型检查全在另一道独立的 `npm run typecheck:test` 里。
所以"我这轮跑过 npm test 了"这句话**不包含**"我的测试编译得过"。
教训不是"下次仔细点"，是**门的清单要写全**：本轮之后我按
`build` → `lint` → `typecheck:test` → `test` → `mutate` 五道走，缺一道就有一段事实没人查过
（`build` 只覆盖 `src`，`test` 只覆盖运行时行为，两者都不覆盖 `test/` 目录的类型）。

### 4.9 归错对象的口径：机制是真的，名字是错的

`docs/14` 里躺着这句我写的口径，读了很可信：

> `writtenNames` 是**过近似**（对分支 JSON 取词，注释与同名字段都算），会误拒

它现在被当成事实引用了好几轮，而它是**归错对象**的。完整的经过（时间线来自 `git log -S`，
不是我回忆的 —— 我第一版把它写成"这个实现从来不存在"，那也是错的，查了才知道）：

| 时刻 | 发生了什么 |
|---|---|
| `2844da4` | `JSON.stringify(steps).matchAll(/[A-Za-z0-9_$]+/g)` **确实存在**，但在同文件另一个函数 `mentionedNames()` 里，服务第二条判据"一支压帧、另一支提到那个循环项名字" |
| 11-09 **19:16** `1933405` | 第二条判据退掉（`forkBranch` 从根上解决了），`mentionedNames` 一起删了 |
| 11-09 **19:18** `facc092` | 我写下上面那句 —— **两分钟后**，把刚删掉的那个机制记到了留下来的 `writtenNames` 身上 |

`writtenNames` 从来只读**声明的写入字段**（`assign` 的键 / `saveAs` / `assignTo` /
`as` / `rules[].var` / `outputVars`），不扫表达式、不扫值、不扫注释。

**为什么这类错比凭空编造难防**：整段时间里"这个文件里有 JSON 取词"都是**真的**，
所以我那句话不是无中生有，读代码也验证不出问题 —— 要验得去读**具体哪个函数**在扫，
而"这文件里扫过"这个印象已经足够让那句话通过阅读了。
**容易相信的描述会替自己免除验证**，而免除验证的方式是它有一半是对的。

**后果不是"文档有句错话"**：那句过近似是被当成**依据**引用的 ——
"闸报了就一定是真竞态"不成立这句本身对，但理由错了，
于是那个**真实存在**的过度拒止（两支 `if` 条件互补时仍然拒，见 §4.6(2)）
被记在一个已删除的机制上，下一个人会去改一个不存在的东西。

**判别办法**（本轮起）：文档里凡是写"它是怎么做的"的句子，都得指向一个**会红的测试**。
`ir/test/parallel-hazards.test.ts` 放行侧那五条就是这句话现在指向的东西 ——
把 `writtenNames` 真改成扫 JSON 取词，那五条**全部红**（实测新文件 10 条全红、
`write-sites.test.ts` 另红 2 条）。所以这句话现在不是"读起来对"，是"改了会红"。

**同一族的第四个成员**（前三个见 §4.4、§4.8，以及本轮 `docs/14` §3 那两处过期的 test 文件数）：
全部是我自己写进去的，不是从外部继承的。所以"读文档要核"这条纪律，
首先约束的是**写文档的那个当下**，而且**核对要用 `git log -S` 这种独立手段**，
不能靠"我记得我刚读过那段代码"—— 我刚才就是靠记忆写错了第二版。

### 4.10 「给可能挂死的调用加个超时」在纯 async 代码里不成立

写 `call` 环检测的测试时，我第一版给被测调用包了一个 `setTimeout` 兜底：
"两秒内没返回就算失败"。它**压根不会触发** —— A→B→A 的每一层都在 `await` 下一层，
全是微任务，微任务链饿死事件循环，计时器永远轮不到。
结果不是测试失败，是**整条测试线挂 300 秒等 harness 超时**，
而那次跑的是变异驱动，等于把一轮变异检查变成一次等待。

可靠的闸只能放在**递归的源头**：让注入的解析器自己被问超过 N 次就抛。
配套一条判据 —— **光看"报了错"不够**，兜底闸也会报错，两种情况下一步动作完全相反
（前者是平台正常拦住了环，后者是平台的环检测坏了）。所以那条测试真正断言的是
`解析器被问了 2 次`：正好两次（A 问 B、B 问 A，第三次被引擎挡下），
多于两次就说明是兜底在兜而不是检测在检。

同一件事在实现侧也成立一次：`call` 成环时**没有任何异常**，
`node` 只是不再返回 —— CI 里表现为"这条用例卡死到被 kill、日志零异常"。
"没有报错"从来不是"没有出事"的证据，这条在异步代码里比在同步代码里贵得多。

### 4.11 「装不上依赖」是被当成前提用的，而它只挡住了 npm 那一半

`docs/14` §5 里"Web UI 端执行侧"那一格原先写的是**没有 web 适配器包**，
理由继承自更早一轮的"npm registry 不可达，playwright/puppeteer 装不上"。
那句话**每个字都真**，但它被当成"所以 Web 端做不了"的依据在用 —— 而这是个跳步：
**不可达的是 npm，不是浏览器控制能力**。

本轮实测（一次性探针，无产物）：

- 机器上本来就有 Chrome for Testing（playwright 的缓存目录里，
  `chromium-1217/chrome-mac-x64/…`），另有 `chrome-headless-shell`。
- **Node 22 自带全局 `WebSocket`**。所以 CDP 客户端 = 起一个带
  `--remote-debugging-port` 的进程 + `fetch(/json/list)` + 一条 WebSocket，
  **零 npm 依赖**。实测跑通 `Page.navigate` / `Runtime.evaluate` /
  `DOM.getDocument{depth:-1}` / `Page.captureScreenshot`。
- `Accessibility.getFullAXTree` 由 **Chrome 自己算** role 与 accessible name。
  `docs/06` §2 把 `role+name` 定为首选定位方式、并且警告
  "模型算出来的 name 和 Playwright 算出来的可能不同" —— 用 CDP 这条顾虑直接消失，
  因为算 name 的是浏览器本身。

**所以"Web 端开工"的拦路石从"装不上依赖"变成了"要写代码"** —— 两者完全不同：
前者只能等环境，后者是正常工作量。这一条改变 §6 的排序。

**顺手记一个我自己踩的判定错误**（它比结论更值得留）：
探针里 `Runtime.evaluate` 取回"atest 中文"变成 `atest 涓枃`，
我第一反应是"WebSocket 帧按 latin1 解了，要上 `TextDecoder`"，
**并且当场改了代码去验**。改完**输出一个字符都没变** —— 我的判据没抓到任何变化，
如果我当时只看"现在绿了没"就会接着相信那个诊断。
真因是**裸 `data:text/html,<h1>中文</h1>` 这个 URL 里的中文没百分号编码**，
浏览器按非 UTF-8 解释；加 `charset=utf-8` 或 `encodeURIComponent` 就好。
把四种写法并排跑了一遍才看出来（裸 data URL ✗ / charset ✓ / 百分号 ✓ / 直接写 DOM ✓）。
教训：**改完必须确认"这个改动确实改变了观测值"**，否则"没变红"和"修好了"长得一样 ——
这与 §4.10 那条"光看报了错不够，兜底闸也会报错"是同一条纪律的另一头。
对平台的直接影响：将来写 Web adapter 时，"注入一段 HTML 当测试夹具"这条路
**必须自带 charset**，否则中文断言会静默拿到乱码并"通过"（比较双方都乱码时更是全绿）。

### 4.12 Web 端真跑起来之后：四个只有"接上"才能看见的缺陷

§4.11 把拦路石从"装不上依赖"改成"要写代码"之后，本轮真的写了代码并**接进 `atest run`**。
四个缺陷没有一个能在只写 adapter、不接 CLI 的情况下现形 ——
它们的共同形状是**两个半边各自正确、缝里漏**：

1. **证据归属长期住在兜底里**（`747f59d`）。真跑一次 Web capture，
   `evidence` 清单里写着 `stepId: "未归属:shot"`。`未归属` 前缀本来是留给
   "忘了带 id 的 adapter"的兜底标签，但因为 `perform` 返回 `void`、
   `saveArtifact` 的 id 没有任何通道回到 `StepResult.artifactIds`，
   它成了**正常路径的唯一标签**：每一张 Web 截图都被标成归属不明，
   而它明确知道自己属于哪一步。**兜底成了默认，就等于兜底在替一个缺失的接口背书。**
   修法是给 `UiExec.perform`/`DeviceExec.perform` 加 `PerformResult.artifactIds`
   —— **破坏性接口变更**，所以标题带 `!`。
2. **`ExecContext` 压根没有 `stepId`**（`1909317`）。`saveArtifact(kind, data, stepId)`
   要 stepId，而 UI adapter 手里没有任何步骤坐标 —— 只能自己编。
   编出来的 id 会进 `artifact.saved` 与 `StepResult.artifactIds`，
   于是证据包把 A 步的截图记在 B 步名下。**现在缺了就直接报错，不许编。**
3. **XPath 文本定位器的叶子判定写反了**（`5969289`，纯靠真浏览器抓到）。
   第一版写的是 `[not(normalize-space(text())!='')]`，读起来像"没有子元素"，
   实际语义是"**直接文本节点**为空" —— 于是
   `<button>提交订单</button>` **0 命中**，而**容器全部命中**：
   断言会去匹配 `<body>` 的文本，`contains` 永远成立，**假绿**。
   正确写法是 `[not(.//*[normalize-space()!=''])]`（"没有任何带文本的后代"）。
   测试同时**钉住新形式并禁止旧形式**（`assert.doesNotMatch`），
   否则改回去也能过。纯逻辑测试为什么抓不到：我测的是"生成的 XPath 字符串形状对不对"，
   而形状错的串照样是个合法字符串。
   （**这段我第一版把旧写法抄成了 `not(preceding::*//*)`** —— 一个代码里从没出现过的表达式。
   抄错了还写得很笃定，正是本文反复记的那条"注释/文档说一个代码没有的性质"。
   所以凡是本文引用具体代码形态，**先 grep 再落笔**。）
4. **`DOM.getDocument` 没调，nodeId 是 0**（同上，也是真浏览器才有）。
   CDP 的 nodeId **从 1 起，0 表示"引用一个未注册的节点"**。
   `queryXPath` 漏了先 `await root()`，于是 resolve 返回一个**看起来合法**的句柄，
   真正报错是在 `click` 那一步，报的是"**节点已失效，需重新定位**" ——
   一个把人引向"中途导航过"的诊断，而真相是"从来没拿到过节点"。
   补了 `validNodes()`（拒绝 ≤0）+ 首次查询即验句柄可用那条测试。

**另一条与 Web 无关但同形状的收获**：`EnvFingerprintSchema` 定义了**很久**、
全仓**没有任何构造点**，只有 `baseline.ts` 的 `envDiffForPerf` 认真读它三个字段
（`7673429` 补上）。这是 §4.3 类 (a) 的一个较新变体：**"有字段 + 有比较逻辑 + 没有生产者"**。
比"没字段"更隐蔽的地方在于比较那一侧写得很认真（还带"appSha 相同则不存在回归"这种推理），
读代码的人会以为这条链路是通的。发现它靠的是 `npm run lint:fields` 的**豁免过期提醒** ——
那条提醒通常被当成噪音，这次它是对的。

**还有一条纪律上的收获（我自己的）**：这一轮里我为了跑测试**同时开了两个 `npm test` 循环**，
而 `pretest` 是 `tsc -b` 写进各包的 `dist/`、测试又**正是从 `dist/` 导入**
（`node_modules/@atest/*` 是软链，`exports` 指向 `dist/index.js`）。
也就是说**并发跑测试的两个进程会一边重写对方的被测产物一边导入它**。
这很可能就是我先前记在 §5 的那条"`npm test` 偶发红、每轮条目不同"的机制之一 ——
注意它**不是产品缺陷，是我测量它的方式在制造它**。
所以这一条的教训与 §4.11 那条同源：**观测动了一下，先问是不是我自己动的。**

### 4.13 IR 报错终于说出字段名：为什么不能改用 discriminatedUnion，以及两处"宁可说不清"

`humanize()` 原先是 `err.issues.map(...)` 一行 —— 而 `StepSchema` 是 **39 支的 `z.union`**
（steps.ts 里 `StepSchema` 那一行；**引用一律用符号名不用行号** —— 这里从前写的是
`steps.ts:423`，而那一行如今讲的是别的事，行号是引用里最容易烂掉的一种），
zod 对 union 失败只给**一条** `invalid_union`，真信息全在
`issue.errors`（**每分支一组**）里。结果任何**步骤内部字段**写错，作者看到的是
`body.0 → Invalid input`：没有字段名、没有合法值。这条债在 `docs/08` §3 登记过
（当时写"未修"），触发它的是我自己：我在 `values.ts` 注释里写"会被拒并列出合法值"，
被 `engine/test/retry.test.ts:293` 那条测试当场证伪。

**修法选在 `ir/src/humanize.ts` 里事后反推判别键，而不是把 StepSchema 换成
`discriminatedUnion`** —— 后者是正解但**做不到**，而这次我是**重验过才接受的**：
steps.ts 里 `StepSchema` 上面那段注释说"用 union 是为了避开 zod v4 对递归成员的类型不变性限制"，
单独搭一个最小递归 schema 编译过一遍：

- **运行时能跑**：`z.discriminatedUnion('kind',[Leaf, Seq-with-z.lazy])` 构造成功，
  还能报出 `Invalid discriminator value. Expected 'leaf' | 'seq'`；
- **编译期不行**：`z.lazy` 把判别值信息擦成 `_zod.propValues: PropValues | undefined`，
  于是既不能赋给 `ZodType<Step>`，`z.infer` 出来的联合还**失去窄化**
  （`if (s.kind==='leaf') return s.v` 编不过）。

也就是说换 schema 要用一串 `as` 换一条错误文案。**注释是对的，但它在
"运行时也不行"和"类型不行"之间没分清楚** —— 而只跑一下试试的人会得出
"能换啊，注释写错了"这个反向结论。所以这里把两半都记下来。

**反推的判据**：各分支**共同**在某个 depth-1 键上因字面量/枚举失败 ⇒ 那个键就是
事实上的判别键（这正是 discriminatedUnion 的语义，只是从 issue 里事后恢复）。
两条**宁可说不清也不猜**的底线，各有一条测试钉着：

| 情况 | 做法 | 为什么不选另一头 |
|---|---|---|
| 候选分支恰好 1 个 | 下钻它 | —— |
| 候选分支多个 | 明说"说不清是哪一种" | 挑第一个 = **编造**"你想写哪种步骤"，报错会指着作者没打算写的字段说"缺少 xxx"，他补完又报缺下一个 |
| 所有分支都在判别键上失败 | 说"`kind` 不是合法值，可取 …" | **这条我第一版当歧义排除了**，于是 kind 拼错/没写全落进兜底话术 —— 那正是新手最常犯、最需要一句话的错 |
| 没有判别键共识 | 取"issue 最少的那一支"（写得越接近合法报得越少），**仅当最小值唯一** | 并列最小时下钻等于猜字段名 |
| 以上都不成立 | 如实说"与全部 N 种形态都不匹配，无法指出具体字段" | 把 162 条分支级噪音倒给人不叫"信息丰富"，叫没人会读完 |

**前后 measured**（`/tmp/humanize-probe.mjs`，11 个真实坏 IR）：
点名出错字段 **2/11 → 10/11**；列出合法值 0/3 → 2/3（第三格的分母项就是下面那个 LiteralSchema 口子，它不属于 humanize 能修的范围）。
变异检查：**退回旧实现后 11 条里 8 条转红**（另 3 条是回归护栏与"畸形输入"那条，
后者由去掉空数组守卫单独触发，也验过）。**这个文件的判据形状是刻意的**：
凡"只要报个错就成立"的断言（`assert.throws`、`errors.length>0`）一条都不写 ——
那些在旧实现下也是绿的，等于没测。

**这一轮我自己在这件小事上连错四次**，都值得留着，因为它们全是同一类：

1. **探针的 fixture 打不到被测分支**（两次，在**一个 20 行的探针**里）：
   我先用 `tap` + `op` —— `tap` 压根没有 `op` 字段（`op` 属 `OperationSchema`）；
   再用 `set` + `vars` —— `SetStepSchema` 用的是 `assign`。
   两者都被 `strict()` 在**步骤层**拒掉，`ValueSchema`/`OperationSchema` 那层从没进到。
   这是 §4.4 那个"输入压根打不到被测分支"的缺陷类**在我自己写的量尺里复现**。
2. **量尺用 `text.includes(字段名)` 判"点名成功"**：`op` 这一格报了 OK，
   命中的其实是 `Unrecognized key: "op"` 里的子串。**一把会误报成功的尺子比没有尺子更坏。**
   改成词边界正则。
3. `pickBranch` 第一版要求判别键出现在**所有**分支的抱怨里 ——
   而真正匹配的那个分支恰恰**不抱怨** kind，于是候选恒为空，全部落进兜底。
4. 把"所有分支都在判别键上失败"当歧义排除（见上表第三行）。

**顺带修掉的一处继承错误**：`values.ts` 与 `docs/08` 那两格都写着
"28 支 / 直接下钻会得到 173 条 issue"。**实测是 39 支、162 条分支级 issue，
且 39 个分支全都提到 retryOn**（不是"其中 39 条"）。
两个数看着都对，但"28 支里 39 条"这种说法内部就矛盾 —— 而这两处注释的作用恰恰是
**让人不必重测**，所以数字错了比没数字更坏。已按实测改正。

**量这一轮还顺手撞出一个口子**（当时未修，**本轮已修**，见 §6 第 11 条）：`ValueSchema` 含
`LiteralSchema`，而它包含 `record(string, Literal)` —— 于是**任何 JSON 对象都是合法字面量值**。
后果实测过：`assign: {a: {pathh: '$.seed'}}`（把 `path` 拼错一个字母）**通过 schema**，
`resolveValue` 原样返回那个对象（`{path:'$.nope'}` 反而会抛"引用未定义"）。
也就是说**拼错引用键 = 静默把一个引用当成一个字面量对象存进变量空间**。
不是 schema 写坏了：引擎按"只含保留键 `{path}`/`{expr}`/`{gen}`（`gen` 可带 `with`）"
在运行时判引用是刻意的，收紧 schema 会杀掉合法的普通对象。

**当时那段还写错了一件事，本轮改正**：它引 resolve.ts 的注释说这道闸是防
"`{"path": "src/a.ts"}` 被误判成引用"，而**单键恰恰过不了闸**（闸的条件就是 `keys === 1`），
它只挡两键的写法。实测：`{path:'src/a.ts'}` 是 `set=error`（PathError：引用必须以 `$` 开头），
`{path:'src/a.ts', lang:'ts'}` 才是 `set=pass` 的字面量。也就是说 IR 的约定一直是
"**这三个键名是保留的**"，不是"这三个键名随便用" —— 注释与事实不符，已照实测改掉
（判据本身没动；动约定会牵动所有已冻结场景的 irSha，那是另一件事）。

   - 复现出**单实例也红** => 那是真缺陷（最仍候选：事件循环饿死让 `setTimeout(abort)` 迟到），
     上锁只会把"偶发红"变成"偶发红但没人再报告它" —— 那是**用降噪冒充修复**。

   **本轮又攒到两次观测**（`n=2`，别当成结论）。一台干净的机器上（`ps` 里没有别的 node /
   headless chromium）跑整仓 `npm test`，各红 2 条，**全在真 IO（chromium）上**：

   | 第几次 | 红的是哪两条 | 单跑 | 干净重跑整仓 |
   |---|---|---|---|
   | 1 | `network.test.ts`「状态码是从真响应里来的」（26.7s，同文件其余 5.5–10.5s）<br>`e2e.test.ts`「同一场景跑 20 次：断言结论逐次完全一致」第 6 次退 **5** | 6/6 绿、24/24 绿 | **1069/1069 全绿** |
   | 2 | `network.test.ts`「请求被中断时流里干干净净」<br>`ui.test.ts`「被遮罩盖住的元素立刻报错」 | 6/6 绿、16/16 绿 | **1084/1084 全绿** |

   **`n=2` 里值钱的是"红的那两条换了"**：第 1 次和第 2 次**没有一条重合**。
   这排除了"某一条用例自己太脆"，指向的是**"真 IO 这一类在负载下会漂"**。
   修法方向因此也不同：不是去给某一条加超时/重试（那是逐条降噪），
   而是先回答"这一类该不该跟纯计算用例跑在同一个并发度下"。
   —— 但这仍然只是**形状**，不是结论：两次都不知道自己跟谁抢的（见下面那句坦白）。

   第 1 次那两条的形状仍然单独记一笔：
    - `adapter-web/test/network.test.ts` 那条"状态码是从真响应里来的"，报 `没看到 /api/query：[]`，
      单条耗时 **26.7s**（同文件其余各条 5.5–10.5s）—— 队列排到它时页面那侧已经等不到请求了；
    - `cli/test/e2e.test.ts` 那条**准确形态**（同一场景连跑 20 次、断言结论逐次完全一致），
      第 6 次退 **5**，而报错正文自己写着"1 个步骤**出错**（不是断言失败）：`c[env-unavailable]`"。

   **两条单跑都绿**（network 6/6、e2e 24/24），**第二次整机重跑 1069/1069 全绿**。
   这次观测值钱的不是"绿了"，是**红的那条的形状**：flake 治理那条测试**没有**报"20 次结论不一致"，
   它报的是"其中一次没测成"。也就是说它把 `env-unavailable` 当成了不一致的一种如实交出来，
   而不是把它当成"某次断言挂了"去复述 —— **这正是它该有的行为**（`docs/08` §3 那条"error 意味着没测成，
   先修环境，此时 fail 的结论也不可信"是同一条口径）。治理 flake 的测试在负载下自己变成 flake 时，
   仍然指对了方向，这是**判据**对，不是**运气**好。
   ⚠ 但方向仍然只到这里：**两次我都不知道那次红是谁跟谁抢的**（机器上没有我能指认的并发进程，
   而"没有我能指认的"不等于"没有"），所以它既没证实"并发 => 红"，也没证实"单实例也红"，
   只添了两条**形状记录**：负载敏感的那几条**全在真 IO + 长耗时上**，而且**会换人**。
   下一步照旧是"连续单实例跑 N 次统计"，不是"上锁"。
   **还有一条便宜的下一步该先做**：给那几条真 IO 用例各记一个耗时基线，
   红了的时候先看"是不是全员变慢"还是"只有那一条慢" —— 前者说明机器在抢，后者说明用例自己有问题。
   这一条**不需要上任何锁**就能把两个分支分开，比我之前列的那些都要便宜。
8. **注释与文档里的 `文件:行号` 引用 —— 本轮做完了：一条会红的命令 + 全仓指针逐条过一遍。**
   原先这一条的标题是"要清一遍 …剩下的没动"，并**逐条列出了没查的指针清单**。
   那个清单现在删掉了，理由值得记一句：**清单本身就是这条检查跑出来的全部剩余违规** ——
   一段写着"这些行号大概不对"的文字，既不是证据也不是闸，而它占的位置正好是"已经查过"的位置。
   现在清单由 `npm run lint:refs` 现给（已并进 `npm run lint`，红了走不掉）。

   **它的判据只有一条**：指针落点附近那一小段，和引用者嘴里说的东西，有没有一个词对得上。
   对不上 = 那一行早已是别的事。这是行号引用坏掉**唯一能被机器看见**的形状，
   所以**红基本可信，绿只说明"没有一条落在明显无关的代码上"** ——
   差一两行、或指向同一段里另一件相关的事，它看不见。
   候选词多到"任一命中等于没命中"时判 `weak` 并**照样计入退出码**：
   实测一条写在 Markdown 长表行里的坏指针（同一格上千字、窗口捞出两百多个候选词）被判成活，
   而同一个坏指针写在普通注释里（候选 9 个）就被抓到了 ——
   报成活等于**让文档的排版替坏指针作证**，而"看着精确所以没人怀疑"恰恰是本类缺陷的原形。

   **检查器自己的绿也是挣来的，不是声称的**：那份自测里嵌了一套变异扫，
   把判据分支逐个改坏、要求这套测试逐个变红（形状照搬 `classify()`，五档"没跑成"分开报）。
   它第一次跑就抓到五条**活着**的变异，全落在"候选词怎么取"上 ——
   也就是说 `ref-lint.mjs` 文件头那几条"先错过一次才改对"的说法，当时**只写在注释里**：
   把窗口半径改成 0、把停词表清空、把整词边界去掉，自测照样全绿。补了夹具才是全杀。
   ⚠ 而"补了夹具才是全杀"这句话我原本打算只写在这里 —— 那就是本条开头批评的那种写法，
   所以扫本身留在测试里，每次 `npm test` 真跑一遍。
   顺带一条：**从测试里 spawn 子进程必须删掉 `NODE_TEST_CONTEXT`**（继承过去子进程就不往 stdout 打 TAP，
   于是"跑了几条"恒为 0）。这套扫第一次跑就是这么红的，而它**本来可以安静地全绿** ——
   如果我把那个 0 读成"未被抓到"而不是报错，二十来个变异会全部记成同一个结论。

   **查出来的东西不止是排版**（这才是本轮的收获，改指针本身只是入口）：
   `gate.ts` 里为 `orphanFails` 那一支给的**两句理由，实测后都不成立** ——
   ① 「`RunAborted` 那条路径会在外层 catch 里再追一条 `__run__` 的 error 叶子」**不追**，
   那句 push 外面套着 `if (!aborted)`，而 `RunAborted` 恰恰 aborted 为真；
   ② 「每一处容器 fail 旁边都有一条替它背书的叶子 fail」也不对：
   `parallel` 的收尾合并**不看那一支是 fail 还是 error**，一律记 `status:'fail'`，
   于是"一支断言会过 + 一支压根跑不起来"给出的正是"容器 fail、叶子一条 fail 都没有"。
   **退出码今天仍是 RUNTIME**（`errors.length` 那一段先返回），所以**没有假绿**，
   变的是"为什么红"的解释。但**保护那一段的从此只是两个 return 的先后顺序** ——
   那是实现细节，不是设计。已补一条跑真引擎的测试钉住"**码是谁给的**"
   （`gate-real.test.ts` 里"折叠成容器 fail"那条：钉 RUNTIME + 点名真正没测成的那一步 +
   **不**点名 orphanFails 那句），所以把两个 return 调换顺序会立刻红，而不是安静改判。
   同时把"容器自己报 error 的可达形状"从两条更正为**三条**（第三种是 `if` 的
   `condition` **语法错**；而"引用不存在的变量"给的是 pass —— 未定义按假值走 else，
   原来那句"求值抛错"照字面写根本造不出这个形状）。明细在 `docs/08` §3 那一行。

   **同一趟还查出两处"把已删掉的行为当现状写"**（这类比坏指针更坏，因为它是**肯定句**）：
   `lease-lifecycle.test.ts` 的块头写着"parallel 的分支共享同一个租约槽"，
   而它下面的测试断言的正是**每支一个槽**；`docs/15` 那张 P4/P6 表格里两格 `pass`
   描述的是 b6be057 已经删掉的回退。两处都改成"改动前实测"并标了时点。

   **刻意没顺手改的一件**：`forEach` 的 `items` 求值成一个**已定义的标量**时，
   现在的行为是"迭代一次并且过"。改它会把今天绿着的用例变成 error，属磁盘格式旁边的行为变更、
   要配迁移说明，所以**登记在 `docs/08`**（三个候选口径列在那儿）而不是这一轮偷偷定一个。

9. **探针引用没有永久落点 —— `ref-lint.mjs` 的第二道规则。**

   **症状**：注释与文档里写"实测（`.scratch` 下某个 `probe-x.mts`）"，而那个目录被 gitignore 了
   （§3.1 那张表旁边就写着原因）。于是**clone 下来的人打不开那个文件**，
   那句"实测"在仓库之外不可验证，而且它**永远不红** ——
   第一道规则看不见它（探针路径后面没有冒号行号），人也不会回去核。
   本轮在 `HEAD` 那份干净树上量过（`git archive HEAD | tar -x -C /tmp/h && node -e …checkProbes('/tmp/h')`）：
   非测试文件里 29 处引用，**18 处没有 clone 得到的落点**，2 处本来就点了名，
   其余是"改前实测"与"未决"那两类；`src/` 那一侧是 10 处里 6 处没落点。
   ⚠ 这一条在本轮写过两次、两次都是错的：第一版写"17 处、没有一处点名落点"，
   17 是**没收紧窗口时**的数，而"没有一处"是我扫完 `src/` 就推广到全仓 ——
   两个数都是估的，不是量的，而"没有一处"这种全称句错起来特别像那么回事。
   第二版改成 30/3，那也是量完之后又改了 `PROBE_RE`（见下面 ⑤）没回来同步的数。
   **要数字就跑上面那条命令**；这两个数写在这里只为了说明"当时的判断错在哪"，
   不是为了给你当基线。
   那 2 处是**真**点名了（收紧窗口后照样过，不是宽窗口捞来的假 ok）——
   所以收紧窗口新抓出的那 8 条与它们是两批东西，下面 ① 也只说那 8 条。
   规矩照旧：**要数字就跑那条命令，别抄这里的**。

   **判据（三条出口，缺一条就报）**：① 同一个块内点名一个 **clone 得到的**落点
   （`xxx.test.ts` / 变异集里那条 case / `docs/08` 那样的登记文档）；
   ② 明说这次量的是**改前**；③ 明说这件事**至今没修**。
   ② ③ 分两档不是分类癖，是**下一步动作**不同：一种去看那条测试就行，
   另一种压根没有测试可看（钉一个没实现的语义，测试就替错误设计背书）——
   合成一档的话，报告上"另有 N 条改前实测"会**谎报**第二种的存在情况。

   **写这道规则的过程中，检查器自己先被抓到四种错**（这才是本轮真正的产出）：

   ① **窗口能穿透块，判据就退化成恒真。** 先按 ±10 行开窗口跑出来一片 ok，
   其中两条的窗口里捞出 21 个 / 14 个测试文件名 —— 那等于"这附近提到过某个测试文件"就算作证，
   而任何一段写得够长的技术说明都会提到测试文件名。
   改成**块边界截断**（标题行 / 表格行 / 代码围栏 / 空行）之后，
   原先判 ok 的那批里有 8 条在块内点不出名字。逐条看过，去向分两种：
   三条本来就写着"改前实测"（免检仍然成立，只是**靠宽窗口才看到那个标记**），
   另外五条是真没有任何落点、本轮逐条补了测试名。
   所以准确的说法是"这 8 条的 ok **都不是块内证出来的**"，
   不是"这 8 条都该报红" —— 后一种写起来更干脆，但它是假的。
   这跟第一道规则里 `weak` 那一档是同一个病，只是这次长在新规则上。

   ② **免检边界比被免检的东西松，检查就反过来替坏引用作证。**
   「…豁免理由**原先**写的是 X」是一个表格单元格的结尾，下一行才是讲**当前行为**的小标题 ——
   软换行把两者粘成"一句"，那个"原先"就给一句描述现状的实测发了免检牌。
   这就是第一道规则里 `isPast` 真错过的那一次的**同族**，只是换了个方向。
   修法是给切句加块级硬界（见上一条 ①），两者是同一处改动。

   ③ **「原本」这类词不能进免检表。** 它命中的那一处是「我**原本**以为会看到 X，探针给的是 Y」——
   修饰的是**作者的预期**，不是那次测量的时间。那一处照样该免检，但理由是另一件事
   （那句还写着"把缺陷写回后跑"，量的是**刻意重新引入的缺陷**），所以补了 `写回` 这一类、删了 `原本`。
   留着 `原本` 的话，"这里原本还发过一条事件，实测（探针 X）"会拿到免检牌，而它说的可能是现状。
   **一张发错的免检牌比一张漏发的牌贵** —— 漏发的那张人会来问，发错的那张没人会再看。

   ④ **探针能给自己当落点。** 有条笔记引用的是 `.scratch` 下一个就叫 `vacuity.test.ts` 的探针，
   而目录那段前缀因为"末尾要有 `/`、后面接的却是 `vacuity`"压根没被匹配上，
   于是**探针靠自己的文件名给自己发了张永久落点的证明**。
   现在裸主名认（那才是人的写法），但 `.scratch/`、`/tmp/` 起头的一律不算，
   而且报告里**指名道姓**——"你点的这个本身是 gitignore 掉的"比"没找到落点"有用得多。
   同一条禁令顺手盖住另一种：**登记文档引用探针时点自己的名也不算**
   （docs/08 里那一行不能替自己作证，那正是本轮要抓的东西换了个写法）。

   ⑤ **解释规则的句子自己会被判成引用。** 收紧到"必须带扩展名"之前，
   `probe-` 那段前缀会匹配上 README 与 `docs/15` 里**讲解这条规则本身**的两处 glob 写法
   （`.scratch/probe-*.mts`）。README 那一处还判成了 `skip:measured-past` ——
   因为那句话里出现了"改前实测"四个字，而它们是**作为被讲解的词**出现的。
   一张靠巧合发出去的免检牌，正是 ③ 里说的那种比漏发更贵的东西。
   修法与 `REF_RE` 要求"扩展名紧贴冒号"是同一条**范围划界**：
   引用指的是"某个具体文件"，`probe-*` 讲的是形状。
   夹具里**同文件并列一条真引用**，并断言判定落在**第 3 行**而不是第 1 行 ——
   只断"抓到一条"不够：真那条没匹配上、glob 那条匹配上了，长度同样是 1，结论正好反过来。

   **顺带清掉两处"看着在管、其实不管"**：一处是永远不生效的跳过项
   （`.json` 压根不在扫描扩展名里，注释却写它挡住了 `tooling/mutate/*.json` 的探针路径），
   一处是**两个一模一样的正则字面量**（只差 flag）——
   现在共用一份**源字符串**，因为逐行 `.test()` 那份绝对不能带 `g`
   （带 `g` 每调一次推进 `lastIndex`，同一行问第二次答案不同，那是"每两轮错一次"）。

   **上面那 18 处逐条处理完**：17 处补了落点、1 处补的是"改前"两个字。
   落点是**读过那条测试、确认它真的覆盖这一句**才写上去的 ——
   点一个不覆盖的名字比不点更坏：它让一句不可验证的话**看起来**可验证，
   从此再没人回去核（本轮就差点把 `lang.test.ts` 那条"两种真相分得开"
   安到一句讲的是"缺 adapter 时只查一次"的话上，两者不是同一件事）。
   另有两处**改的是文字而不是引用**：一行我自己的注解误写在捕获输出的围栏里（见本节末），
   一处是标题与探针引用隔了一个表格、把落点挪进同一节才算数。
   `forEach` 的 `items` 指向标量那一格**没有测试可指**（它登记的就是"未决、本轮不修"），
   走的是出口 ③，这也是 ③ 存在的唯一理由。

   **这条规则自己也被扫了一遍**：变异扫加了一批针对探针规则的 case，
   其中"块界失效""探针自证""免检放宽到邻句""未决并进改前"这几条都有对应夹具。
   元测试做过一次：删掉某个夹具，扫**恰好点名**对应那条变异为存活 ——
   也就是说这批"全杀"不是空的（第一道规则当年就是靠这一步才发现五条活着的）。

   ⚠ 已知管不到的地方：围栏**里面**的探针输出不判（那是捕获的现场，不是作者的断言），
   所以本轮顺手把一行**误写进围栏里**的自己的注解挪了出来 ——
   那行写的是"lint 对同一形状不报"，而那个探针打印的是 lint 的 JSON 结果，
   **这句话是我加的，不是它印的**。混在一起的话，围栏里的东西就分不清哪句是现场了。

10. **落盘序列化会把"没有这个字段"写成"字段值是字符串 `undefined`" —— 本轮修；顺带补上 `--version-id` 那条从没验过的接线。**

    **两件东西是从一次"核对登记表"里掉出来的**，不是计划内的：本轮开头我去核 §6 第 1 项
    到底做没做（结论见上面那条），顺手把 §5 那几行"明确没做"逐条 grep 了一遍。
    `versionId` 那一行写的是"证据包里**如实是 `undefined`**" —— 而 grep 到 CLI 时看见
    `provenance: { versionId: str(a, 'version-id') }`，也就是说**用户能给版本号**。
    那行登记说的"undefined"是**不传的时候**，而它没说不传的时候磁盘上长什么样。
    **就是顺着这个"没说什么"往下挖了两步**，掉出来两件事：

    **① CLI 那个开关从没被验过有没有接通。** 判据不是读代码猜的：把 `commands.ts` 里那句
    赋值整句换成 `{ versionId: undefined }`，重建后**整包 CLI 测试全绿**。
    （**故意不写"173/173"这种数** —— 我当时量的确实是 173，但本轮就往那个包里加了一条测试，
    那个数现在对不上任何人的工作树了。它是一次**一次性测量**，不是可复查的基线；
    要复查就跑上面那个实验：注释掉 `e2e.test.ts` 里 --version-id 那条，同样的红会再出现一次。）
    而 store 层**有**一条测试钉住 `provenance.versionId -> manifest`
    （`evidence.test.ts` 的「manifest 记录 frozen 与 provenance」，我第一遍以为它覆盖了整条路）。
    **两头各绿一半、缝在中间**：那条测试喂的是内存里的 `{versionId:'v7'}`，压根不经过 argv。
    这个开关从 `d90e9e1`（M6 那一份）起就在 `--help` 里，从来没人跑过它到底通不通 ——
    本仓那个缺陷类（"上半截很完整、下半截没人接，而绿色测试一片"）**第 N 次**原样复现，
    这次的形状特别值得记：**两个半成品测试合起来给人一种"这条路有测试"的错觉**。
    修法是一条跑真 CLI 的成对测试（`e2e.test.ts` 的「--version-id 真的进到证据包清单里」）：
    传了要到盘上，**不传时那一栏要整栏缺着**（不能补 `"v0"`/`""`/`0` ——
    编默认值会把"调用方没说"伪装成"平台说这是第 0 版"，而 P1 版本表要拿它当主键）。
    变异集 `tooling/mutate/disk-presence.json` 的 V1/V2 各钉一头。

    **② 顺着"不传时长什么样"量下去，量到脱敏那一趟会把"没有"改成"有"。**
    不传 `--version-id` 时，磁盘上的 `manifest.scenario.versionId` 是**字符串 `"undefined"`**，
    不是缺键。根因在 `redactForDisk`：`undefined`/`function`/`symbol` 三类一起走 `String(v)`。
    同一趟还污染 `trace.jsonl`（实测那一份跑完的 trace 里有 **4 行**带字符串 `undefined`，
    含 `"status":"undefined"` 与 `"durMs":"undefined"` —— 拿 `durMs` 做聚合的脚本拿到的是
    字符串拼接，不报错、静默算错）。

    **判据**（这条不是"我觉得应该删掉"，是**与裸 `JSON.stringify` 逐一对齐**）：
    磁盘上的东西最终由 stringify 写，消费者（服务端 run 表、看板、`jq`）按它的语义读，
    所以脱敏这趟**不许改变"有没有"**。`evidence.ts` 里那句"写一个 undefined 字段与不写，
    在 JSON 里等价"**对裸 stringify 成立、对经过这一趟的 manifest 从来不成立** ——
    一句写在注释里的性质，实现早就推翻它了，而它旁边就是靠这句性质做的分支决策。

    **第二处后果是量出来才想到的，也是这次最值钱的**：被测响应体里**真有一个值是字符串
    `"undefined"` 的字段**（JS 后端把 `String(undefined)` 塞进字段是常见病灶），
    与"这个字段压根没有"**在磁盘上同形**。而"上游没返回这个字段"与"上游返回了 'undefined'"
    恰恰是排查这类问题唯一有用的区分 —— 脱敏本来是防泄密的，结果它把故障现场抹平了。
    这一条不在我原先的设想里，由 `.scratch/probe-redact-undefined.mts` 的量场当场抓到；
    永久落点是 `packages/engine/test/redact.test.ts` 的
    「"响应体里真有一个值是字符串 undefined 的字段"与"这个字段没有"在磁盘上必须区分得开」。

    **顺带把一处顺序修对了**：`SECRET_KEY_RE` 那一支原本在递归**之前**，
    所以一个**压根没填**的 `token` 会打出 `«secret:未暴露»` —— **凭空造出一条密钥痕迹**，
    排查的人会去查"这个 token 哪来的、是不是泄露了"，而真相是这里从来没值。
    现在是"先递归 → 再判没值 → 最后才谈脱敏"。**顺序这种判据最容易只钉住结果、钉不住次序**，
    所以变异 R7 是**整块换序**（不是删一行），它红的正是那条密钥测试。

    **两条我这轮自己写错、被当场抓住的**（都留在代码/测试注释里）：
    - 第一版把三类 JSON 带不走的值改成 `return UNSET`（一个模块私有 symbol）就直接往外返回。
      我写的注释说"记号不许逃出本模块"，**而代码正在让它逃出去**：`JSON.stringify` 对 symbol
      的处理恰好与 undefined 一模一样（对象丢键、数组记 null），所以**那一组按 JSON 形状比对的
      断言全都照样绿**；而漏出去的记号在真正的调用点上是会**抛**的 —— `${symbol}` 直接
      TypeError，于是"字段缺失"从"报告里多一个字符串"升级成"报告生成崩掉"（`report.ts`/`html.ts`
      里到处是模板串）。补的判据是**插值**那两条（`assert.equal(\`${x}\`, 'undefined')`）：
      元测过，删掉出口收口那一步，**只有这两条能红**。
    - 第一版在对象分支里**又列了一遍**"哪些类型算没值"，两处条件一模一样的结果是
      `if (r === UNSET) continue` **永远走不到**。我想给它加计数打印来证明走不到，
      而引擎禁止 import node 内置模块 —— **`console` 直接编译不过**（分层闸替我抓的）。
      改成判据只有一处，于是那一支变成唯一出口、可达、有变异盯着（R4）。

    **测这一轮的**：`packages/engine/test/redact.test.ts`（6 条，主判据是"与裸 stringify 对齐"
    而不是抄一份期望形状 —— 抄形状只排除一种错法）、`e2e.test.ts` 新增那条、
    变异集 `tooling/mutate/disk-presence.json`。条数别抄在这里，
    跑 `npm run mutate tooling/mutate/disk-presence.json` 就有；
    里面 **R8 是照列的等价变异**（`String(v)` 与 `v.toString()` 都是"存在的值换个写法"），
    **R3/R4 的说明别读快**：它们在 **JSON 层面与正确行为同形**（stringify 自己会丢 symbol 键、
    把数组里的 symbol 记成 null），红是红在"记号漏进函数返回值"被 `deepEqual` 抓到 ——
    我第一版把 R3 标成"长度这个信息没了"，那是**没验证就写上去的假因果**，改掉后才跑的。

    ⚠ **本轮明确没碰的两件**（都记在这儿，因为它们都是"改完之后的新缺口"，不是老账）：

    1. `{ token: undefined }` 现在整栏消失，这意味着"这个字段本来该有密钥、但装配漏了"
       与"这个场景压根不用密钥"在 manifest 里**也不可区分**了。
       我选了"没值就别说它有"（造出密钥痕迹更坏：它会让人去查一件没发生过的事）。
       真要区分，正路是 CLI 那条"缺密钥跑之前就告警"的路（`e2e.test.ts` 里已有那条），
       **不是让脱敏层去猜哪个键"应该有值"** —— 那是把"字段名像密钥"当成"这里承诺过有密钥"。
    2. **响应体里的函数与 symbol 现在也从磁盘上消失了**（实测：`{hook: ()=>1, ok: 1}`
       落盘只剩 `{"ok":1}`；改动前是 `{"hook":"()=>1","ok":1}`）。
       这是"与裸 `JSON.stringify` 对齐"这条判据的**直接推论**（stringify 本来就不写它们），
       但代价要说清：一个函数出现在响应体里，本身就是"把服务端内部对象漏进序列化"的信号，
       而改动前那一行 `"()=>1"` 是**唯一能看见这个信号的地方** —— 现在它和"这个键没有"同形了。
       **本轮仍然选对齐**，理由与上面那条同一条：证据包是给人下载的东西，
       把函数源码写进去既可能泄露实现、又不是那份对象的 JSON 编码；
       而这个信号的正确出口是**引擎在落盘前就报一条 lint/事件**（"响应体里有不可序列化的值"），
       不是靠脱敏层顺手把源码抄进磁盘。**那条报没做**，因为它要决定"在哪一层判"
       （adapter 收到响应时？store 落盘时？）而这两处的取舍我还没有实测依据。


11. **引用/生成器写错的三种"看着没事"的失效 —— 本轮修；顺带把形态判据从三处手抄收成一处。**

    **起点是 §5 那一行老账**（"引用写错键名会静默变成字面量"），登记时只写了 `pathh` 一种形状。
    本轮按登记给的治法去做之前先量了一遍，**实际有六族写法在静默**，其中一族比登记的更坏：

    | 写法 | 改前实测 | 为什么坏 |
    | --- | --- | --- |
    | `assign:{row:{pathh:'$.x'}}` | set=**pass**，存下的是那个对象 | 登记的这一种。引用没生效，但变量"非空"，肉眼看得出来 |
    | `{gen:'uuidd'}` / `{gen:'uuid '}` / `{gen:'UUId'}` / `{gen:'intt',with:…}` | set=**pass 而变量是空的** | **比登记的那族坏**：下游 `notNull` 才响，报的是"$: 期望非空，实际为空" —— 那句读起来像**被测系统返回了空数据**，排查方向就此从用例指到被测系统 |
    | `{gen:'widget', size:'L'}`（本意是业务对象） | set=**pass 而变量是空的** | 业务对象被 `gen` 分支**整个吞掉**，连 `size` 都没了 |
    | `{gen:'int', widh:{min:1}}`（`with` 拼错） | set=pass，存下的是那个对象 | 生成器整个没了 |
    | `{expr:'1 +'}` | set=**error** | 这族本来就是响的，不在缺口里 |
    | `{path:'$.nope'}` | set=**error**（"引用未定义"） | 同上。对比才看得出：**键名写错是唯一的哑错法** |

    **根因不是"少了个 if"，是同一件事抄了三份**："哪个键把对象变成引用/表达式/生成器"
    这件事写在 ① `ir/values.ts` 的三个 `z.object`、② `engine/resolve.ts` 的
    `typeof o.path === 'string' && Object.keys(o).length === 1`、③ lint 若要报近邻还得再抄一遍词表。
    **`gen` 那一支的键数条件就是第二份抄漏的**，而它**不能照抄** `path` 的 `keys === 1` ——
    `{gen:'int', with:{min:1}}` 是合法的**两个键**。这正是"两份写得很像的规则"的代价：
    看着是漏写，其实是不能照抄，而注释里没写为什么。

    所以修法是**收成一处**：`ir` 新增 `isValueForm()`，允许的伴随键直接从
    已写好的 `schema.shape` 上派生（`gen` 有 `with`、另两种没有），
    运行时与 lint 同问这一个判据。生成器种类清单同理：`GEN_KINDS` 现在同时是
    schema enum 与引擎校验的来源（以前 enum 写死 14 个词、`switch` 另写 14 个 case，
    分叉时 schema 收下而 `default:` 返回 undefined —— 就是上面那一格）。
    落点：`packages/ir/src/values.ts`、`packages/engine/src/resolve.ts`、
    `packages/engine/src/lint.ts`（`RESERVED_KEY_REWRITE`），测试
    `packages/engine/test/value-forms.test.ts` + `lint.test.ts` 那一组，
    变异 `tooling/mutate/value-forms.json`。

    **静态闸那一半刻意留了误报护栏，而且是活的**：`RESERVED_KEY_REWRITE` 报的是 warning，
    三条形状**每条都带第二条件**（键名近邻只是词汇巧合，值也得像那个形态）。
    起因是规则写完**当场实测到的两个误报**：
     - `{gen:'widget', size:'L'}`（合法业务对象）被报成"种类 widget 不存在" —— 修法是
       改问 `isValueForm(obj) === 'gen'`，与运行时同一个问题、同一个答案；
     - `{gen:'uuid', width:100}` 被报成"`with` 拼错" —— 本平台测的是界面，
       `width`/`height` 到处都是，而 `width` 与 `with` 只差两个字母。
       修法不是给 `width` 开特例，是补第二条件"值必须是对象"，判据来自 schema
       （`GenValue.with` 是 `z.record(...)`，真的 with 值本来就是对象）。
    误报的代价从来不是"多一条黄字"，是大家把 lint 关掉、`lint.ts` 里其余二十几条一起失效。
    **"合法 IR 不会被这条规则报"这个性质没写成注释里的一句结论**，写成了一条会扫
    **真 schema** 的测试（`lint.test.ts` 里「IR 的正牌字段名没有一个撞在近邻面上」，
    用它自己那条自检防"名单为空时恒通过"）—— 因为近邻判据每放宽一档，
    上一次的扫描结论就自动失效，而注释不会红。

    **本轮自己错的四处**（都是"看起来防了、其实没防"，与 §4.7 同族）：
     1. **对照组挑的值没有区分度**：`{len:'abc'}` 那格本意是钉"首字母相同"这道防误报条件，
        但 `abc` 本来就不像任何生成器种类，第二条件先拦住了整条 ——
        于是把首字母条件整个删掉，测试**照样全绿**。变异集 R8 就是这么活下来的。
        换成 `{len:'uuid'}`（值踩上形态特征）才有区分度：报不报这时才只由那一支决定。
        同一条错在 R9 又犯一次（变异改的是 `path` 支的条件，对照组只有 `expr` 的）。
        **教训**：一条"两条件同时成立才报"的规则，每个条件都要有**另一条件已经成立**的对照组。
     2. **给 `GenKindError` 覆写了 `this.message`**，于是 `VarError` 里那条
        "varName 为空就不拼后缀"的分支**永远看不见**这个类 —— 一条到不了的防护分支。
        变异集 R5 把它改回无条件拼接，测试全绿。改成整句话从 `super()` 一次给进去之后才被抓到。
     3. **测试里写了规则契约之外的用例**：`geean` 与 `gen` 差**两位**，本来就不该报，
        我却写了条"必须命中"。这种用例红了会诱人去放宽判据（白白把误报面放宽一档），
        而实际该改的是测试。**先量判据的实际行为再写期望**（`.scratch` 那三份近邻探针就是干这个的）。
     4. **`echo` 骗了我一次**：`npm run typecheck:test 2>&1 | tail -5 && echo ok`
        里 `tail` 的退出码永远是 0，于是类型检查红了而屏幕上写着 ok。
        之后一律 `cmd > /tmp/x.log 2>&1; echo "=$?"`。
        （这不是新缺陷类，是我在**同一轮里**踩的：`npm test` 1231 全绿那次，
        类型检查其实是红的 —— 绿色测试与类型检查是两道闸，一道过不代表另一道过。）

    **顺带量到的一条**：`PathError` 与 `ExprError` 在解释器里落到
    `cause=env-unavailable` —— 用例自己把 `$.` 路径/表达式写坏了，报出来是"环境不可用"。
    当时把它当成"下一轮的事"记进了 §5，**而那一行本身记错了体量**（只记了一个位置，
    实际是五处），下一轮就是下面的第 12 条。


12. **"这一步为什么失败"这件事没有一处定义 —— 本轮收成一处；顺带把兜底那格从"编一个像样的假答案"换成"没归因"。**

    **起点是 §5 那一行**（"`PathError`/`ExprError` 被归成 `env-unavailable`"）。登记时的读法是
    "两个类漏登记，补两行即可"。**量下来不是**：那条判据**抄在五处，五处互相矛盾**。

    | 抄写点 | 改前的写法 | 同一个 `PathError` 得到 |
    | --- | --- | --- |
    | `interpreter.ts` runStep 主 catch | `instanceof AssertionFailure → product-bug`、`VarError → case-stale`、**其余 env-unavailable** | `env-unavailable` |
    | `interpreter.ts` `when` 守卫那一句 | **无条件** `'env-unavailable'` | `env-unavailable` |
    | `interpreter.ts` 等待求值报错那两支 | **无条件** `'env-unavailable'` | `env-unavailable` |
    | `wait.ts` 求值那一族 | `instanceof VarError` 才外抛，其余**吞成字符串** | 到不了判据 |
    | `assertions.ts` 断言路径 | `instanceof PathError → 'case-stale'` | **`case-stale`** ← 与上面四处**相反** |

    于是**同一条写坏的 `$.` 路径，写在 `assert` 里是"用例过期"、写在 `set` 里是"环境不可用"**。
    实测的改前/改后（`.scratch/probe-cause-precheck.mts`，真引擎 + `git stash` 做的 A/B）：

    | 位置 | 改前 | 改后 |
    | --- | --- | --- |
    | `assign:{r:{path:'nope'}}` | `error` + `env-unavailable` | `error` + **`case-stale`** |
    | `assign:{r:{expr:'1 +'}}` | `error` + `env-unavailable` | `error` + **`case-stale`** |
    | `wait` 条件 `{expr:'1 +'}` | `error` + `env-unavailable` | `error` + **`case-stale`** |
    | `assert` 的 `jsonPath` 路径坏 | `error` + `case-stale` | 不变（它本来就是唯一判对的那处） |
    | 没接 `adapters.db` 的等待 | `error` + `env-unavailable` | **不变**（这一族一个字节都没动） |
    | 没配 `baseUrl` + 相对地址 | `error` + `env-unavailable` | **不变** |
    | 真·等满超时 `onTimeout:'fail'` | `fail` + `env-unavailable` | **不变**（登记 §5，见下） |

    **为什么动手前先量**：登记里"补两行"的说法如果照做，会漏掉 `wait.ts` 那条吞异常的路
    （登记里压根没提它），而那条恰好是**四种写法里唯一到不了判据**的。
    更值得记的是第五处：`assertions.ts` 早就判对了，说明**"这件事有人想错过"不成立** ——
    同一条规则在同一个包里被两个人想过两次，得出相反答案，而两边都写了自己的那份。

    **本轮真正买到的不是那四个格子，是兜底那一格。** 改前是"枚举已知类、**其余全算环境问题**"，
    于是"新增一个错误类忘了回来登记"的后果是**编出一个像样的假答案**：值班人拿去查一个
    不存在的环境问题，而 CI 照 `CI_HINT` 的"5 → 标 error 重试一次"白重试一遍
    （用例里那条路径不会因为重试而变合法）。改成 `untriaged` 之后，没登记的新类拿到的是
    一个**明说"没人认领"**的值 —— 而 `FAILURE_CAUSE` 里 `untriaged` 的定义就是"归因不明"，
    上面那张五处各说各话的表恰好证明"归因"这件事**本来就没有**权威答案，那就别假装有一个。

    只读 `report.html` 与退出码的人 —— 也就是绝大多数人 —— 拿到的是"全绿"。

    **修法取事件流而不是给每个 emit 点加字段**，理由是要防的正是这一族本身：
    挨个加字段意味着"新增一条 emit 必须记得同时加字段"，忘了就静默。
    现在是按 `kind === 'lint.reported'` 筛（**不是**按 code 白名单筛），
    所以新增一条 emit 天然进得了页面。三个出口共用一份筛选与一句措辞
    （`engine/src/advisories.ts` → `html.ts` 的提示带 / `junit.xml` 的 `atest.advisories` / `summaryText` 末段），
    与 `redact.ts` 那条"三个出口同一份规则"是同一条理由。

    **两个出口形状不同是刻意的**：页面上按 **code + detail** 分行（`DEPRECATED_OPERATION` 的 detail 就是那个废弃接口名，
    三个不同接口合成一行 ×3 就是**少报**），而 JUnit 的 property 按 **code** 聚合（CI 判的是"这一类有没有出现"，
    列 200 个同名条目把一行能判掉的东西变成一张要解析的长表）。
    聚合键用 `JSON.stringify([code, detail])` 而不是拼接 —— 手挑的分隔符（`|` / `::` / 空格）
    总会撞上 detail 里本来就有的东西，于是**两条不同的事实合成一条**，那是少报。
    截断（detail 280 字、条目 20 条）**必须说出来**：静默截断的产物说"就这些"而实际更多，
    与本仓最恨的"真话在报告里、不在产物里"是同一件事的另一半。

    **(乙) 散文出口的密钥泄漏。** 脱敏有**三条**通路而不是两条：
    结构化按字段名（`redactForDisk` → JSON），散文按**值形态**（`redactSecretText` → HTML 正文 / XML 文本节点 / `summary.txt`）。
    改前实测同一次 run：`trace.jsonl` 干净，而 `report.html` / `junit.xml` / `summary.txt` 里的 `assertionSummary`
    躺着真 JWT 与真 AWS key。根因**不是规则表缺项**（规则表两边共用），是**三个散文出口一个都没过值形态规则**。
    修在**序列化那一刻**的三个 chokepoint（`html.ts` 的 `esc`、`report.ts` 的 `xmlSafe` 与 `plainSafe`），
    不在显示层、也不靠提示词约定 —— 与既有的"落盘那一刻脱敏"是同一条纪律。

    然后是这一轮真正的四件事，都不是"少写了一行"：

    1. **五个 code 在 HEAD 的任何测试文件里连名字都不出现**
       （`ROW_LEASE_NOT_IMPLEMENTED` / `VALIDATE_REQUEST_UNAVAILABLE` / `REQUEST_SCHEMA_MISMATCH` /
       `LLM_ADAPTER_MISSING` / `LOOP_TRUNCATED`，`git grep -l <code> HEAD -- '*/test/*'` 返回空）。
       也就是说"这条 emit 确实发得出去"从没被断言过。
       ⚠ **这句结论的强度要说准**：grep 只证明"**没人断言过它**"，不证明"它从没发出去过" ——
       后者要在 HEAD 的工作树里给引擎装一个事件收集器跑全量才有答案，本轮没做。
       所以下面那条判据**不依赖**这个区别：本轮那张十一条表的**第一条断言就是"这条事件真的发了"**，
       夹具发不出去就直接红，不需要先知道它历史上响没响过。
    2. **`LOOP_TRUNCATED` 有一个专门的测试文件，而它从没验过那条事件。**
       `loop-truncated.test.ts`（上一轮写的）钉的是 `note` 那句话与 `keyContext` 的计数。
       所以**"有测试文件的 code"与"发得出去的 code"是两件事** —— 我一开始把前者当成后者的证据，
       是那一行的 grep 把我纠正过来的。**"这块有测试"不等于"这条通路有测试"。**
    3. **第一轮"改前实测"是假的 —— 不是假在结论，假在它是恒真的。**
       我把三个出口的调用点中和掉之后，`advisories.test.ts` 红了 17/25；
       而我最初跑的那次是 `git stash` 掉整个 `advisories.ts`，红的原因是
       `SyntaxError: does not provide an export named 'advisoriesHidden'`。
       **一条测试因为少个 import 而红，不是行为被覆盖的证据。**
       正确的对照是：**留着** `advisories.ts`、只把三个出口接回空值 —— 那才是"载体不存在而生产者还在"的那个改前状态。
       这一条与本文件 §6 第 16 条第 5 点（"注释里那句'我量过'如果没重跑，就是编的"）是同一条错的**更隐蔽的一版**：
       那次我确实跑了命令，只是跑的是另一件事。
    4. **夹具的"少跑了几条"会把自己变成另一条判据的假证据。**
       `×N` 聚合那条我起初不给 `pathParams`，而 `urlTemplate` 是 `/t/{id}` ——
       于是"URL 里还有未填的参数"让容器在**第 1 轮**就 error 中止，只剩 1 条事件，实测 `count=1`。
       那条测试当时"通过"的原因是它压根没跑到聚合逻辑。补上 `pathParams: { id: '$x' }` 之后才真是 ×3。

    **刻意没做的一件事，记在这里以免下一轮顺手优化掉**：LOOP_* 这一族**同时**出现在上一轮那条循环提示带
    与本轮这条提醒带里，**不去重**。做去重要一张"哪些 code 已有更好的载体"的抑制清单，
    而那张清单的失效方式正是本轮在修的事：将来谁把提示带搬走，那些 code 因为"还挂在抑制清单上"
    而从页面上消失，且**没有任何东西会红**。而且 `summary.txt` 与 `junit.xml` 压根没有循环提示带 ——
    抑制在那两个出口上等于直接抹掉。有测试专门钉这一点（它同时断"两个带子都在"与"提示带不在 `summary.txt` 里"）。

    5. **我给一条变异写了个抓不到的理由，而那个理由是错的。**
       聚合键那条变异（`JSON.stringify([code, detail])` 换成 `` `${code}|${detail}` ``）我标的是 `caught`，
       实测**存活**。查下去发现存活是**如实的**，但我原先写的理由（"detail 里有 `|` 就会合成一条"）**不成立**：
       code 全是 `A-Z_` 常量，所以第一个 `|` 仍是唯一边界，detail 里带多少 `|` 都不影响解码。
       真正的问题是那条键**把正确性压在一个没写下来的假设**上（"code 里不会有序列符"），
       而 `code` 是从 `e.data.code` 读的**任意字符串** —— 今天所有 emit 点写死成大写标识符是**习惯，不是约束**。
       两个选择：标 `equivalent`（**会说谎** —— 它不是行为等价的改写，它只是当前不可达），
       或者**补一条用带 `|` 的 code 构造的测试**把它打死。选了后者：
       合成一条的表现是**少报一条提醒**，正是本轮在修的那个缺陷，不该留在"没人守"那一栏里。
       **规矩**：`survived` 只允许推出"测试不够"或"这条根本不该在集里"，
       而**在写理由之前先问"我以为可达的那个输入真的可达吗"** —— 我这轮已经在这条上错过一次（§6 第 16 条第 4 点），
       那次是反方向（把真判据当成冗余）。

    **守它的东西**：`engine/test/advisories.test.ts`（十一条逐个：夹具自检 + 三个出口 + **detail 那句人读的话也要在**；
    另加形状判据 —— 无提醒时整块不出现且配正对照、**提醒不进任何计数也不出行**（行 ↔ `<testcase>` **双向**比对，
    用的是 §6 第 16 条第 1 点那条教训）、detail 属不可信内容（注入 + AKIA 双 payload，内容以转义后的文字保留）、
    截断标记在 HTML 与 `summary.txt` **两侧**都要在而 JUnit 那份不截断也不该有、`reportOnly` 的"有一条是就说是"、
    properties 块与 DTD 产生式 `properties?, (testcase|error|failure)*` 的顺序与"只能有一个块"，用 CPython 真解析）
    + `engine/test/report-redaction.test.ts`（三个出口 + **CLI stdout** 那份，四条判据各配正向对照：
    良性值必须在四个出口里都出现，否则"没有 AKIA"可能只是因为这一段压根没渲染）
    + 变异集 `tooling/mutate/advisories.json` 与 `tooling/mutate/prose-redaction.json`。
    **抓到几条不写在这里**（本文件末尾那条规矩），跑 `npm run mutate tooling/mutate/advisories.json` 自己的输出才有。
    两个集里**只有 `prose-redaction.json` 有一条** `expect:"equivalent"`：那条"esc 里先转义再脱敏"
    （五道值形态规则匹配的字符集里没有 `& < >`，所以顺序今天不可观察 —— 留在集里是**入口扩张报警器**：
    将来谁往规则表里加一条会撞上转义结果的规则，它立刻变 caught）。
    `advisories.json` 一条没有，**而那里本最像该有一条的（聚合键换成拼接）我第一版就误标成了 `caught`**，
    见上面第 5 点：它既不是等价改写、也不该标 equivalent，正解是补测试。

    **顺带修掉的一处真缺陷（在我自己的测试里）**：`RunOverrides` 压根没有 `artifactStore` 这一栏（它在 `adapters` 里），

    `typecheck:test` 红，而 `npm test` **一条不红**（tsx 不做类型检查）。
