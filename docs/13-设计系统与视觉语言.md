# 13 · 设计系统（视觉语言 / 设计 token / 组件）

`docs/12` 定"有哪些页面、怎么流转"，本文件定"长什么样、按什么规则长"。

**先定调**：这是一个**给人连续看 4 小时排障的工具**，不是给人演示用的门户。所以目标是**低视觉噪音 + 高信息密度 + 状态一眼可辨**。审美参照系是 Linear / Vercel / Raycast（信息密度高、克制、键盘优先），**不是** Ant Design Pro 演示站（大留白 + 卡片墙 + 蓝紫渐变）。这个参照系差异要在写第一行样式前对齐，否则 AntD 默认主题会把你拽回后者 —— 它是最容易滑进去的默认值，因为我们就用它做基础库。

---

## 1. 密度系统（最重要的 token）

三档，**默认紧凑**：

| token | 紧凑 | 标准 | 宽松 | 用在哪 |
|---|---|---|---|---|
| `--control-h` | 28px | 32px | 36px | 按钮/输入/选择器 |
| `--row-h` | 32px | 40px | 48px | 表格行、步骤行 |
| `--space-1..6` | 2/4/6/8/12/16 | 4/8/12/16/20/24 | 4/8/12/16/24/32 | 内外边距 |
| `--font-13/14/16/20` | 12/13/15/18 | 13/14/16/20 | 14/16/18/24 | 正文默认 **13px**（不是 14） |
| `--radius` | 4px | 6px | 8px | **统一小圆角，禁止大圆角** |
| `--border` | 1px `--line` | | | **用描边分层，不用阴影分层** |

三条硬约束：
1. **表格与步骤表默认紧凑档**（13px / 32px 行高）。测试人员要在不滚动的情况下扫过 30 条用例，宽松档是在浪费他们的时间。允许用户切档并把选择存到个人设置（有人确实要看宽松的）。
2. **层级用 1px 描边 + 背景明度差表达，阴影只用于浮层**（下拉、抽屉、弹窗）。卡片阴影套卡片阴影 = 视觉噪音地狱，也是"后台感"的主要来源。
3. **禁止用 `space-between` 把内容拉到两边**（会造成"到处是空隙"的空洞感）。表单和详情用固定栅格（`12/24` 或 `16/8`），标签列定宽右对齐。

**字体**：`ui-sans-serif, system-ui, "PingFang SC", "Microsoft YaHei", sans-serif`（中文优先系统字体，别引入 webfont —— 加载慢且中文渲染不如系统字体稳）。**等宽**：`ui-monospace, "JetBrains Mono", Consolas`，用于变量名、JSONPath、选择器、耗时、状态码。**数字一律 `font-variant-numeric: tabular-nums`** —— 通过率、耗时、成本这些列不对齐会显得非常廉价，这是低成本高回报的细节。

**中文排版**：数字与中文之间留半角空隙（`letter-spacing` 不做，靠 `text-autospace`/手动空格）；**表格里的中文表头不超过 6 字**，超了就改成两行或用 tooltip；**避免全大写**（中文无大小写，混排时很怪）。

## 2. 语义色是主角（本产品的第一色彩系统）

一般后台：品牌色为主，语义色点缀。**本产品反过来**：六态语义色为第一系统，品牌色只用于交互态。理由：用户 90% 注意力在读状态，如果品牌蓝和"运行中"蓝抢注意力，红绿就不可读 —— 而红绿可读性 = 产品可信度。

| 状态 | 语义 | 建议色（浅/深双值）| 图标 | 附加 |
|---|---|---|---|---|
| `pass` | 通过 | 绿 `#15803d / #4ade80` | `✓` | |
| `fail` | 失败 | 红 `#b91c1c / #f87171` | `✗` | 行/卡片左侧 3px 色条 |
| `error` | 执行异常（非用例失败） | 橙红 `#c2410c / #fb923c` | `!` | **必须与 `fail` 区分**：环境问题不是产品 bug |
| `healed` | 自愈通过（未毕业） | 青 `#0e7490 / #22d3ee` | `⚕` | **不许显示成绿**（`docs/00` §5.6 软失败） |
| `skipped` | 前置不满足/无设备 | 灰蓝 `#475569 / #94a3b8` | `⊘` | 不算失败（`docs/05` §5） |
| `triaged` | 待人工确认（首轮策略） | 琥珀 `#a16207 / #fbbf24` | `◐` | 不计入通过率（`docs/05` §3） |
| `running` | 进行中 | 品牌蓝 | `◌` | 动画 + **必须有耗时数字**，光转圈不算反馈 |
| `stale` | 用例可能过期（spec 变更） | 紫灰 `#6d28d9 / #a78bfa` | `⟳` | 不阻断执行（`docs/05` §1.1） |

四条规则：
- **色 + 图标 + 文字三重编码**（`docs/12` §7）。色盲用户、灰度打印、截图转发都不能丢信息。
- **红/绿/橙必须通过 4.5:1 对比**（浅背景下正文用深值，色块背景用白字）。`healed` 的青色和 `pass` 的绿要拉开可辨距离，否则"自愈当通过"这个最重要区分就白设计了。
- **通过率等关键指标旁必须有绝对数字**（`142/12 ✗ 3 ⚕`），百分比单独出现会被误读。
- 置信度色阶（`docs/11` §4）用**同一套 token 的另一组明度**，不要另发明一套调色板。

**暗色模式不是可选项**：测试人员夜间盯 CI、投屏页在暗环境更好用、执行日志大量等宽文本。做法是 AntD v5 的 `theme.darkAlgorithm` + 我们自己的 token 语义层（`docs/13` §6），确保所有颜色都从语义 token 取，绝不硬编码 hex。**Day-1 就走 token**，否则后面补暗色等于重刷全站样式。

## 3. 布局骨架（两套，共享顶栏与 token）

```
┌ 顶栏 56px：项目切换 · ⌘K · 搜索 · 通知 · 用户 ──────────────────────┐
│                                                                     │
│ 【工作台骨架】(A1/A2/E2/G3 —— 需要专注的任务态)                      │
│  ⌈ 左 240 可收：会话/场景树/队列        主区（对话+工具流 或 审校）    │
│  ┊ 右 360 可关：上下文面板 / 检查器 / 产物预览                        │
│  · 主区最大宽 1100px，超宽时左右留白，不拉满                        │
│                                                                     │
│ 【控制台骨架】(B1/C1/D*/F* —— 浏览与配置态)                          │
│  ⌊ 左导航 208（可收 64）  内容区自适应，表格铺满、内边距 16         │
└─────────────────────────────────────────────────────────────────────┘
```

- **不做全屏固定宽 1920 的"大屏"**，也不做 1200 居中窄栏。表格页铺满（排障要看宽表），内容页限宽（长文不拉长视线）。
- 左导航收起后保留图标 + tooltip；**图标不能是唯一标识**（同样三重编码）。
- 抽屉宽度 480/720 两档，**不用全屏弹窗**（保留上下文：用户要能同时看到列表和详情）。
- **1280px 是最低支持宽度**，投屏页需 1440；移动端**不做**（测试台不会在手机上用，但通知落地页要做**只读移动版**——半夜看失败是真实场景，成本很低：C2 详情页单独适配一档即可）。

## 4. 关键组件规范（AntD 之上的 8 个自研件）

| 组件 | 规范要点 |
|---|---|
| **`StatusDot`** | 8px 圆点 + 图标 + 文字；三种尺寸（12/14/16）；`running` 是唯一有动画的状态，且必须与耗时数字同现 |
| **`VarChip`** | 等宽字体；显示**来源步骤名**而非路径（`创建订单.orderId`），hover 展开完整 JSONPath + 当前值；点击滚到来源步骤；未定义 → 红底 + `⚠`；跨端来源加目标端小图标。点击复制路径 `⌥点击` |
| **`ProvenanceBadge`** | `人写` / `🤖Agent` / `⚕自愈`；附 `置信度 0.86` 与 `prompt v7`；hover 显示模型与时间；`⚕自愈` 可点开 IR diff |
| **`LocatorPreview`** | 截图上画框：当前框实线 + 候选框虚线 + 置信度标签 + **`occurrences>1` 时画红框警示**（`docs/10` §2 同图多实例）。A 级与像素级共用同一组件 |
| **`IrDiffView`** | **结构化 diff**，不是文本 diff：以"步骤"为最小单元显示新增/删除/移动/改参；改参只显示变化的字段（`timeoutMs 5000→15000`）；整块移动要识别成移动而非删+增。IR 是结构化数据，用文本 diff 是浪费 |
| **`ArtifactTile`** | 截图/ARIA/DOM/HAR/logcat/LLM 原文统一磁贴：类型图标 + 缩略 + 字节数 + 时间点；点开全屏预览器，**支持左右键翻帧**（排障靠翻帧） |
| **`CostMeter`** | `¥0.42 / ¥2.00` + 细进度条；80% 变琥珀、100% 变红并显示"已中断"；hover 展开按 taskGroup 的分解（`docs/03` §2） |
| **`EnvStamp`** | `staging · r37` 徽章；点开=该修订的键值；**`[对比 r36]` 按钮常驻**（`docs/00` §4.5 环境漂移）；若本次失败且近期修订过 → 徽章旁提示"环境 12 分钟前有变更" |

**空状态/加载/错误规范**（这些是最容易显廉价的地方）：
- 空状态 = **下一步动作 + 快捷键**，不放插画。例：场景库空 → "还没有场景。`⌘K` → 输入 `/import-openapi` 一句话生成" —— 空状态是最好的教学位。
- 加载 = 骨架屏（同结构骨架，不用转圈占位）；>2s 才显示"已耗时 Ns"；>10s 必须给"取消"。
- 错误 = **说清哪一步失败 + 原始错误可展开 + 下一步动作**。例：`生成失败 · 模型不支持 tool calling（FundGPT-coder-next）` + `[查看原始响应]` + `[切换模型]`。这类报错质量直接决定平台能不能自己活（我们自己的环境此刻正卡在这上面，`docs/03` §1）。

## 5. 交互与动效预算

| 项 | 规则 |
|---|---|
| 时长 | 120–180ms；`cubic-bezier(0.2,0,0,1)`。**只有状态变化与位置变化有动画，数据刷新不动画**（表格每 2s 刷一次，动一下就会晃） |
| 允许动 | hover 底色、抽屉/面板位移、状态点切换、新增行淡入 |
| 禁止动 | 页面进场编排（stagger 卡片）、视差、渐变流动背景、logo 动效 —— 工具类产品的这些动画每天都在消耗耐心 |
| 实时 | SSE/WS 驱动，**新日志自动滚到底但用户上滚即锁定 + 显示"↓ 新 N 条"**（滚动手势被抢是工具产品最招人烦的行为） |
| 键盘 | `⌘K` 命令面板 · `J/K` 上下 · `⏎` 打开 · `⌘⏎` 主操作 · `Y/N/E/S` 审校 · `G` 前缀跳转（G-R 运行 / G-S 场景）· `⌘.` 停止 Agent。**所有主操作必须先有快捷键，再配按钮** |
| 表格 | 列宽可拖 + 持久化；行右键菜单（重跑/复制链接/标记 flaky/提 BUG）；单元格 `⌘C` 复制原值；**筛选条件同步到 URL**（分享一个筛选视图是刚需） |
| 破坏性操作 | 删除/冻结/清数据/执行不可逆动作 → 二次确认**要求输入名称**，且写明影响范围（"将影响 37 个引用此场景的套件"） |

## 6. 技术实现约束（避免"设计系统"变成第二套真相）

| 约束 | 做法 | 不做的后果 |
|---|---|---|
| **AntD v5 token 是唯一源** | 所有颜色/圆角/间距通过 `ConfigProvider` 的 `theme.token` + `components` 覆写；**自研组件只消费 CSS 变量，不写 hex** | 出现"设计稿一套、AntD 一套、业务组件一套"三套真相，暗色模式永远补不完 |
| **Tailwind 只用于布局** | `flex/gap/p-*/text-*` 类做布局与字号；**颜色一律走 token 变量**（`text-[var(--text-2)]` 或自定义 `text-muted` 映射到 token） | Tailwind 的调色板和 AntD 的 token 各长各的，两个月后同一层级出现 4 种灰 |
| **暗色 = 换 token 值** | `darkAlgorithm` + 我们的语义 token 覆盖；组件代码零改动 | 全站补暗色 = 重写样式 |
| **间距只用 `--space-*` 阶梯** | ESLint/Stylelint 规则禁止任意 `padding: 13px` 之类 | 间距失控，"看起来不整齐但说不出为什么" |
| **图标单源** | 只用 `@ant-design/icons` + 自绘的 `状态图标`（内联 SVG，与 `StatusDot` 同文件） | 三种来源的图标粗细不一致，最显廉价 |
| **状态机色板进 IR/引擎** | `docs/13` §2 的六态与引擎 `trace.jsonl` 的 status 枚举**同一个 TS 常量**（放 `packages/ir`） | 前端有 `healed`、引擎有 `auto-fixed`，报表对不上 |

## 7. 已确认的 UI 决策

| # | 决策 | 由此产生的硬约束 |
|---|---|---|
| **U1** | **没有设计师，纯工程实现** | 见 §7.1 —— 这条把"视觉品质"的责任转成了"工程纪律"，必须用几条替代机制补 |
| **U2** | **独立后台系统**（不嵌客户系统） | 免掉样式隔离/微前端/登录态打通/主题继承/菜单权限下发。**路由、登录、主题、构建产物全部自控**，UI 层不需要"壳层 + 可嵌入业务层"的拆分。省下的工作量相当可观，别自己又加回来（比如"顺手支持 iframe 嵌入"） |
| **U7** | **三档密度都给，默认紧凑** | 顶栏右侧常驻密度切换 `[紧凑\|标准\|宽松]`，**写入个人设置而非全局**（演示者自己切宽松，不影响别人日常视图）。三档 token 见 §1。**技术前提：间距/字号/控件高三组 token 必须真正参数化**，否则切档会破版 —— 这是"三档"这个功能的唯一成本，且必须 D1 就参数化（事后补 = 全站刷样式） |

### 7.1 没有设计师时的四条替代纪律

没有设计师不等于"随便长长"。品质来源从"视觉稿"换成"工程纪律"，以下四条替代设计师的作用，**且都是可 lint / 可 review 的**：

1. **一致性优先于美观。** 同一层级永远同一个 token、同一类操作永远同一个位置。**"看起来不专业"九成来自不一致，而不是不漂亮** —— 而一致性是可以被 lint 强制的（Stylelint 禁任意值、间距只用 `--space-*`、颜色只用 token 变量、图标单源）。这条能替代设计师约一半的价值。
2. **抄结构而不是抄视觉。** 参照系是 Linear/Vercel/Raycast 的**信息结构**（列表密度、抽屉、命令面板、键盘流、克制的动效），不是它们的配色。具体做法：每个新页面开始前先回答"这个页面在 Linear 里对应哪一类页面"，照它的布局骨架排。
3. **只维护一套"黄金页"并定期回归。** 选 **C2 运行详情·时间旅行** 与 **B2 场景编辑器** 作为黄金页 —— 新组件/新 token 必须先在这两页验证过才进组件库。没有设计师时，"品质"实际是靠两三个高频页面的口碑撑起来的，而这两个页面恰好也是产品信任所在（`docs/12` §1）。
4. **每个 PR 的 UI 截图进 review。** 没有设计师把关，就把"人眼一致性检查"变成流程。成本极低，能挡住绝大多数"这页跟别的不一样"。

**明确不做**：自己的图标库、自绘插画、营销页、引导蒙层、空状态插画、自定义光标/滚动条。这些都需要设计师才不显廉价。
