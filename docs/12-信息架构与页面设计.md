# 12 · 信息架构与页面设计

前提：本产品的界面是**两种气质**的混合 —— ① Claude Code 式的 Agent 工作台（对话、工具流、审校 AI 产物）② 后台管理系统（表格、配置、看板）。硬塞进一个 AntD Pro 模板会让 ① 失去灵魂、② 显得花哨。解法是**两套骨架共享一套实体路由**，而不是把所有东西摊平在一个导航里。

---

## 1. 设计原则（每条都有反面教材）

| 原则 | 反面 | 落地要求 |
|---|---|---|
| **待办驱动，不是统计驱动** | 首页 4 个统计卡 + 2 个饼图，看完不知道干嘛 | 落地页首屏是"需要我处理的事"清单；统计图全部放分析页 |
| **状态色 > 品牌色** | 品牌蓝与"运行中"蓝打架，红绿不可读 | 六态语义色为第一系统，品牌色只用于交互态（`docs/13` §2） |
| **AI 产物必须可见来源与置信度** | 生成结果直接铺在表格里，用户不知道哪句是猜的 | 全站统一的 `ProvenanceBadge`（人写 / Agent 生成 / 自愈改写 + 置信度 + prompt 版本） |
| **Agent 过程可见可中断** | 转圈 40 秒后突然出结果 | 工具调用卡片流 + 实时 token/成本计数 + 停止按钮 + 单步"撤回" |
| **红绿必须带理由** | 只给 fail | 每个 fail 强制一个**归因标签**（产品缺陷/用例过期/环境不可用/定位失效/数据冲突/flaky），归因不明时不许关闭 |
| **变量流动可见** | 脚本里一串 `${var}` 文本 | 变量 chip 化，可点击跳来源、悬停看值、未定义标红 |
| **一屏能看完当前判断所需的全部信息** | 详情弹窗套三层 | 排障所需信息在同一屏（时间旅行 + 证据 + 变量 + 日志），禁止"点开才能看" |
| **键盘优先** | 千级审校量用鼠标点 | 审校队列、场景树、命令面板全键盘可达（`⌘K` 是全站入口） |

## 2. 导航结构（7 个一级，刻意压住）

```
┌ 顶栏：项目切换器 · ⌘K 命令面板 · 全局搜索 · 通知(自愈待审/预算/设备掉线) · 密度档 · 用户
│        ↑ 密度档 [紧凑|标准|宽松] 常驻顶栏，写入个人设置而非全局（演示者切宽松不影响他人，docs/13 §7）
│
├ 🤖 Agent 工作台      ← 默认落地页（对话 + 工具流 + 产物审校）
├ 📋 场景库            场景列表 / 编辑器 / 版本与 diff
├ ▶ 运行               运行列表 / 运行详情(时间旅行) / 队列与实时
├ 📦 资源              API 文档 · 页面画像 · 设备池 · 数据源 · 环境与密钥
├ 🔄 迁移              导入源 · CaseDraft 审校 · 覆盖矩阵
├ 📊 分析              通过率 · flaky · 定位器健康 · 成本 · 需求覆盖
└ ⚙ 设置               LLM 配置 · 权限与审批 · MCP/Skills · 通知与集成
```

- **迁移独立成一级**，因为它来自 `docs/11`：存量迁移是第一个产生价值的里程碑（P1 首位），藏在"资源"下面等于告诉用户这是附属功能。
- **Agent 工作台是默认页**。若客户团队更传统，可配置默认落地页为"运行"（这个开关很便宜，但值得有）。
- **不设"Dashboard"**。分析类内容全部收进"分析"，落地页交给 Agent 工作台。

## 4. 四个 must-nail 的流程设计

### 4.1 一句话导入 swagger → 生成 → 冻结（体现四道闸）

```
┌ Agent 工作台 ──────────────────────────────────────────────┐
│ 你: /import-openapi https://x.com/swagger.json             │
│                                                            │
│ ┌ 工具 ─ openapi.fetch ──────────────── 1.2s ✓ ──────┐     │
│ │ 解析 312 个 operation，跳过 7 个(deprecated) [详情] │     │
│ └────────────────────────────────────────────────────┘     │
│ ┌ 工具 ─ engine.lint (生成 24 条草案) ────── ⚠ 3 warning ┐ │
│ │ LITERAL_OVERFIT ×2  HARDCODED_SECRET ×1   [逐条查看] │     │
│ └────────────────────────────────────────────────────┘     │
│ ┌ 覆盖增量预览 ────────────────────────────────────────┐   │
│ │ 新增接口×错误类组合 168 / 24 条                       │   │
│ │ ⚠ 其中 5 条与已有场景等价(相似度>0.94) → 建议删除     │   │
│ │ [✓ 保留 19] [展开等价组]                             │   │
│ └────────────────────────────────────────────────────┘   │
│ ┌ IR diff (可编辑) ───────────────────────────────────┐    │
│ │ + scenarios/order-create-happy.json    [接受][改][弃]│   │
│ │ + scenarios/order-create-401.json      [接受][改][弃]│   │
│ └────────────────────────────────────────────────────┘    │
│ [冻结这 19 条 → 可进 CI]  成本本次 ¥0.42  ⏹ 停止          │
└────────────────────────────────────────────────────────────┘
```

设计要点：
- **覆盖增量预览必须内联在流程里**，而不是事后的分析页 —— 它是抑制过度生成的唯一时机（`docs/00` §6.1）。
- **"冻结"是显式动作**，冻结后 `provenance` 锁定（`docs/02` §1）。UI 上未冻结场景标灰 + "CI 不会执行"提示，避免用户以为已经生效。
- **成本实时显示**，每次 LLM 调用都往里加（`docs/03` §2）。
- 工具卡片可折叠、可复制原始输入输出（排障必需）。

### 4.2 一次失败运行的排障（产品信任所在）

```
┌ 运行 #4821 · API 造订单→APP验证 · staging · 3m12s · ✗ 失败(定位失效) ──────┐
│ ┌ 步骤树(失败路径高亮) ─┐ ┌ 时间旅行 ──────────────────────────────────┐ │
│ │ ✓ dev 申请设备        │ │  ◀ ●─●─●─●─◉─────────────▶  第 6/11 步      │ │
│ │ ✓ app.clearData       │ │  [截图] [ARIA] [DOM] [请求] [变量] [日志]   │ │
│ │ ✓ app.launch          │ │  ┌──────────────┬──────────────────────┐   │ │
│ │ ✓ mk 创建订单 201     │ │  │  截图缩略图   │ orderList.aria.yaml  │   │ │
│ │ ✓ settled 等待 1.2s   │ │  │  (点开全屏,   │ - button "新建"      │   │ │
│ │ ✗ verify 文本断言     │ │  │   可对比前帧) │ - text "共 0 条"     │   │ │
│ │   ↳ mine 我的         │ │  └──────────────┴──────────────────────┘   │ │
│ │   ✓ orders 订单入口   │ │  期望包含: ORD-20240815  ← 来自「创建订单」 │ │
│ └───────────────────────┘ │  实际:      "共 0 条"                       │ │
│ ┌ 归因(必须选一个) ──────┐ ├────────────────────────────────────────────┤ │
│ │ ○产品缺陷 ●用例过期    │ │ 断言: 文本包含 $.mk.resp.data.orderId       │ │
│ │ ●环境不可用 ○定位失效  │ │ 变量: ORD-20240815   [跳来源步骤 ↑]        │ │
│ │ ○数据冲突 ○flaky       │ │ 请求: GET /api/orders → 200 [] (空数组)    │ │
│ │ 备注…                  │ │ [查看 LLM 当时看到的上下文] [JUnit] [zip]  │ │
│ └────────────────────────┘ │ [提 BUG(带证据包)] [重跑此步] [标记 flaky] │ │
└────────────────────────────┴────────────────────────────────────────────┘
```

**"请求: 200 [] 空数组"这一行是这个页面的价值所在** —— 它让用户 3 秒判断出"不是 UI 坏了，是数据没落库"，而不用重跑。这就是 `docs/00` §5.3 说的"重跑正是客户凌晨 2 点做不到的事"。

- 归因下拉强制单选，选不出来不能归档（数据质量的地基，`docs/08` §3 "失败归因"）。
- 变量 chip 点击跳来源步骤 —— 跨端传参的可解释性。
- **"查看 LLM 当时看到的上下文"**（`docs/00` §5 决策溯源）是竞品没有的入口。

### 4.3 场景编辑器（最难的页面，三视图）

**主视图是"可折叠步骤表"，不是流程图。** 流程图只读、用于汇报场景；画布编辑嵌套循环/`call` 是 UX 黑洞（`docs/01` §2 已定）。

```
┌ 场景: API造订单→APP验证   [步骤表|流程预览|JSON|TS SDK]  ✓lint ✗dryrun ─┐
│ ┌ 步骤表 ──────────────────────────────────────┐ ┌ 检查器 ────────────┐ │
│ │ ⋮≡ ▸ 📱 device   申请设备  android≥12         │ │ 断言                │ │
│ │ ⋮≡   📱 watcher  弹窗守望  2 规则    [编辑]   │ │  ▾ 文本包含         │ │
│ │ ⋮≡   📱 app      清除数据                     │ │   值: [ORD-创建订单]│ │
│ │ ⋮≡ ▸ 📱 app      启动 com.acme.shop           │ │   ▲ 悬停看当前值    │ │
│ │ ⋮≡   🔌 创建订单 POST /orders  ⚠ 无teardown   │ │   ⧉ 改为正则        │ │
│ │ ⋮≡   ⏱ 等待      DB行存在 + UI空闲  15s       │ │ 等待: 15s/500ms     │ │
│ │ ⋮≡   📱 tap      「我的」        🤖Agent生成   │ │ onTimeout: fail     │ │
│ │ ⋮≡   📱 tap      「我的订单」    ⚕已自愈      │ │                     │ │
│ │ ⋮≡ ✓ 📱 断言     包含 [ORD-创建订单]          │ │ ┌ lint ──────────┐  │ │
│ │ ＋ 添加步骤   ⌥↑/↓ 移动  ⌘D 复制              │ │ │⚠ 无 teardown   │  │ │
│ └───────────────────────────────────────────────┘ │ │⚠ CROSS_TARGET │  │ │
│ ┌ dry-run 输出: 变量表 / 未定义 / 依赖图          │ │ │  等待缺失     │  │ │
│ │ orderId=ORD-… ✓   sku=SKU-1 ✓  ✗ undefined:xx │ │ └───────────────┘  │ │
│ └────────────────────────────────────────────────┘ └────────────────────┘ │
└──────────────────────────────────────────────────────────────────────────┘
```

要点：
- **步骤行的图标区分目标端**（🔌API / 🌐Web / 📱Android），跨端场景一眼可辨 —— 这是本平台的招牌能力，UI 要持续强化。
- **状态徽章叠在步骤上**：`🤖Agent生成`（待人审）、`⚕已自愈`（未毕业，非绿）、`⚠lint`。
- 变量 chip 在**步骤摘要和检查器里都渲染**，两处都能跳来源。这是"变量流动可见"的落点。
- dry-run 是**编辑器的常驻面板**，不是菜单动作（边改边看未定义变量）。
- 三视图切换不保存私有状态，IR 是唯一真相（`docs/02` §8）。切到 JSON 时提示"直接改 JSON 会产生新草稿版本"。

### 4.4 审校队列（迁移 + 自愈共用一套 UI 模式）

`docs/11` §4 与 `docs/00` §5.6 是同一个交互模式：**左右对照 + AI 推断高亮 + 键盘流 + 队列进度**。做成一个通用组件 `ReviewWorkbench`，供三处复用（迁移 CaseDraft、定位器自愈 diff、模板重录）。

```
┌ 待审 128 · 已审 214 ────────────────── 进度 ▓▓▓▓░░ 62% ────────────┐
│ 高置信(≥.9) 41 ✓   中(.7–.9) 57   低(<.7) 30 ⚠                      │
│ ┌ 原始(禅道 #3821) ────────────┬ 生成草案 ─────────────────────────┐│
│ │ 前置: 已登录                 │ 场景: 创建订单-正常  [IR]          ││
│ │ 步骤: 1.进入商品详情         │ 1. navigate 商品详情               ││
│ │       2.点击立即购买         │ 2. tap 「立即购买」                ││
│ │       3.确认收货地址         │ 3. tap 地址                        ││
│ │ 预期: 生成成功               │ 4. submit                          ││
│ │                              │ 5. ⚠断言 包含"订单号"(AI推断)     ││
│ │                              │    ↳ 依据: order.create 响应 schema││
│ └──────────────────────────────┴────────────────────────────────────┘│
│ [Y]接受 [N]打回 [E]编辑后接受 [S]跳过 [J/K]上下  ⌘⏎ 批量接受剩余高置信│
└──────────────────────────────────────────────────────────────────────┘
```

**`⚠断言(AI推断)` 那行必须同时显示"依据是什么"** —— `docs/11` §2.2 的核心（断言从资源推导，不是想象）。只说"这是 AI 猜的"而不说依据，用户无法判断，审校就退化成盲签。

## 5. Agent 工作台的关键交互（与普通后台最大的差异）

| 交互 | 设计 | 为什么 |
|---|---|---|
| 流式输出 | 文本 + 工具卡片交错，卡片可折叠看原始 JSON | 让用户随时知道"现在在干什么、花了多少钱" |
| **成本与预算** | 顶栏常驻 `¥0.42 / 本场景上限 ¥2.00`，超 80% 变琥珀 | 成本失控是放弃 AI 测试工具的第一原因（`docs/00` §6.9） |
| **停止** | 永远可见，中断后保留已产出 IR 草案（不丢工作） | Agent 跑偏时用户的唯一逃生门 |
| 斜杠命令 | `⌘/` 唤起补全，显示参数与危险级 | 我们自己的产品也要吃自己的狗粮（`/slash` 是卖点） |
| Skills 展开 | 显示"当前加载了哪个 skill 及其 token 成本" | 让 progressive disclosure 可被感知与调试 |
| 上下文面板 | 右侧抽屉：本轮注入的资源（spec 摘要、页面画像、变量表、脱敏了哪些字段） | 用户必须知道模型看到了什么（`docs/03` §5） |
| 产物落到编辑器 | Agent 产出的 IR 不直接在对话里编辑，**"在编辑器打开"跳到 B2** | 避免"对话里改一处、场景库另一处"的双真相 |
| 只读/可写模式 | 顶栏显式切换；可写模式列出将被执行的工具与危险级 | Agent 不直接驱动执行器（`docs/01` §3），UI 要体现 |
| 提示注入守卫 | 页面/app 内容在上下文面板里以"数据块"呈现，并标"已按 N 条规则脱敏" | 把不可见的安全机制可视化 |

## 6. 全局 UI 模式（一次定义，全站复用）

`ProvenanceBadge`（人写/Agent/自愈 + 置信度 + prompt 版本）· `VarChip`（变量引用）· `StatusDot`（六态）· `LocatorPreview`（截图上画框，A 级与像素级共用）· `IrDiffView`（结构化 diff，不用文本 diff）· `ArtifactTile`（截图/HAR/ARIA 快照统一磁贴）· `ReviewWorkbench`（§4.4）· `CostMeter` · `EnvStamp`（环境名+修订号+`[对比修订]`）· `DeviceChip`（型号+系统+占用者+健康）。

**`LocatorPreview` 值得单独强调**：任何涉及定位的地方（编辑、自愈审校、失败排障、模板重录）都在截图上画出框 + 置信度。人类判断"AI 是不是点错了地方"的唯一可靠方式就是画出来 —— 而 `docs/10` 的模板指纹方案能不能被用户接受，取决于这个组件。

## 7. 反模式清单（明确不做）

| 不做 | 原因 |
|---|---|
| 首页统计卡片 + 饼图 | §1 待办驱动 |
| 详情三层弹窗 | 弹窗套弹窗导致上下文全丢，改右侧抽屉或整页 |
| 拖拽画布做主编辑器 | 嵌套循环/`call` 不可维护（`docs/01` §2） |
| 用颜色作为唯一信息载体 | 色盲 + 打印 + 截图分享会丢信息 → 色 + 图标 + 文字三重编码 |
| "AI 一键生成全部用例"按钮 | 必然产出几百条无断言用例（`docs/00` §6.1），且一次性产出无法审校 |
| 假实时（轮询包装成流） | 用户能感觉到；宁可显式"每 5s 刷新" |
| 空状态放插画 | 空状态放下一步动作 + 快捷键 |
| 全站统一 loading spinner | 长任务要进度、要已耗时、要可取消 |
