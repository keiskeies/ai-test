## 4. 空白点（按对本项目的价值排序）

1. **没有任何平台把 API / WebUI / ADB 放在同一个变量命名空间里。** 现状是三套互不相通的模块，跨端传参靠人肉。而"用 API 造数据 → 在 APP 上验证展示"是最真实的移动端测试形态，在现有平台上**写不出来**。修复成本极低：一个引擎 + 三种 step 类型 + 一份共享变量空间。**这是定位的根基。**
2. **没人有"等待策略"节点，全都是固定时长 sleep。** Apifox 的"等待"就是延时。裸 `delay:3000` 每个都是一颗未来的 flake + 一次套件变慢。`wait` 必须是 `{condition, timeout, poll}`，且 condition 可以是 HTTP 状态 / UI 谓词 / **数据库某行出现**（MySQL 白送的差异化）。裸 sleep 应被 lint 警告。
3. **"LLM 设计期写用例"与"冻结用例在 CI 比特级重放"这条边界没人做成产品特性。** 每个生成用例钉死 `{prompt_hash, model_id, seed, spec_hash, case_version}`，CI 里拒绝重新生成。**赛道里最便宜的护城河**，也是 Agent 对话入口敢接到 CI 前面的唯一前提。
4. **无断言用例的静态 lint** —— LLM 生成用例的头号失败模式（几百条能读、只断 `status==200`、永远绿、什么都不抓）。一个 20 行检查：零断言且无下游 `extract` 消费者的步骤即 no-op。已知工具里没一个做。
5. **环境漂移无人解决。** 所有平台的环境都是 name→value 无 schema、无版本、无来源。"本用例上次通过时用的是环境第 N 版"几乎 MySQL 白送。
6. **密钥不进 Agent 上下文 —— 这个约束在全部现有设计里缺席。** Bruno 的 `processEnv` 是开源里最好答案，Postman 云端 workspace 变量是反面教材。**Agent 能读到密钥，就能把它 echo 进生成的用例正文里提交上去。**
7. **Qdrant 的正确用法没人占：对"运行与失败"做语义检索**（"找出所有和这次失败相似的过往失败"）、跨项目 flaky 聚类。Apifox/Postman AI 做的是生成，不是对自家测试历史的检索。

## 5. 值得直接抄的设计（10 条）

| # | 抄谁 | 抄什么 | 为什么 |
|---|---|---|---|
| 1 | **Stagehand** | `observe()` 设计期枚举候选定位器+打分 → 持久化**被选中的选择器+指纹**，而非 prompt | 把 LLM 变成一次性定位器编译器；运行零成本、确定性、自愈仍在 |
| 2 | **Playwright MCP** | `[ref=e12]` **ARIA 快照**作为模型唯一世界观 + ARIA 快照断言 | 省 10–20× token，免疫 class 名抖动，**一份产物干三件事**：断言类型 / 自愈指纹 / 回放 diff |
| 3 | **Playwright Trace Viewer** | 步骤级 `before/after` 快照 + 时间旅行拖条 | "回放会话排障"变成查看器功能而非重跑——而重跑正是客户凌晨 2 点做不到的事 |
| 4 | **Maestro** | `when:` 守卫 / `whileTrue:{max:N}` 有界循环 | 无界 AI 循环是"不可回放 + 成本失控"的诞生地。每个循环/等待都要有硬上限 |
| 5 | **openatx watcher** | 步骤之间 declarative 弹掉 `允许`/`评分`/OEM 弹窗 | 在真机安卓队上，这条比任何定位器改进消掉的 flake 都多 |
| 6 | **Testim/mabl/Autify** | 自愈 = **软失败 + 审校队列**：标记 `healed`（非绿）、要求一次未自愈重跑才毕业、留 old→new 定位器 diff | 静默自愈的结局是"绿色构建，点错按钮"。**diff 本身就是商品** |
| 7 | **ws-scrcpy/scrcpy** | IDR ~1s + 一设备一编码器扇出 + 画布预渲染点击涟漪 | 长 GOP 让滚动看起来卡死，用户读成"你们产品卡"；120ms 视频延迟人能忍，点下去没反应不能忍 |
| 8 | — | **定位器优先级阶梯 + 置信度门 + `max_cost_per_step`** | 便宜→贵逐级走，置信度达标即停。给每步设美元上限，否则成本随设备数线性爆炸 |
| 9 | **Meticulous** | 确定性注入进运行记录：冻结 clock/random 或记录种子、HAR fixture、环境指纹（app SHA / DPR / tz / model+temp+prompt hash） | 没有这些，"回放"只是一段视频而不是证据 |
| 10 | **mobile-vision / M3A** | 两个 grounding 器（便宜视觉模型 + uiautomator hierarchy）**取交集**，不一致才降级到 SoM 视觉 | 准确率来自一致性门控，不来自单模型变强 |

另两条工程戒律：**JUnit XML 是三端唯一通用报告语汇**（别自创格式，内部跑模型可以富，出口必须兼容）；**一个执行引擎，GUI 只是它的一个视图**（Apifox GUI vs CLI、Postman vs Newman、MeterSphere UI vs CI runner 全都在变量作用域和重试上行为不一致 —— 这是"一个 TS 引擎、本地与 CI 跑同一条代码"最硬的论据）。

## 6. 坑（按破坏力排序）

1. **过度生成** —— 几百条可读、只断 200、永远绿的用例。缓解：策略标签 + embedding 去重 + 无断言 lint + **覆盖增量预览**（"这 14 条新增 0 个接口×错误类别组合"）。
2. **schema 本身是错的** → 符合性断言刷红几千次 → 团队关掉门禁。缓解：符合性走**独立定时车道**，并把"spec 是权威的"作为开启前置条件。
3. **LLM 从唯一样本响应过拟合出字面断言**（时间戳/ID/顺序/浮点精度）。缓解：Karate 式模糊标记成为 id/timestamp/uuid 形态字段的**默认**，精确匹配要显式 opt-in。
4. **RESTler 类调参悬崖** —— 默认字典只得到一屏 500（全是"你传了垃圾 token"）。要预算调参这一步，别把 fuzzing 当勾选项交付。
5. **数据驱动互踩共享数据**（并行下最惨）→ 默认开启的用例级 teardown/GC + Redis 租约（设备/租户/一次性 fixture 都要锁）。
6. **runner 分叉**（见 §5 末）。
7. **UI 链路过长** —— 安卓团队经典：12 次 UI 点击造一个用户，再在 UI 上断言。每次多余 UI 跳转既是一个 flake 源也是一个倍速。跨端共享变量空间让"API 造数据 → UI 断言"成为**最省事**的写法，才能根治。
8. **非可重现 AI 运行** —— 同 prompt 不同用例，夜间跑出的 bug 复现不了。缓解：Schemathesis 式最小复现产物 + `model_id/prompt_hash/seed` 钉进用例行 + CI 只跑冻结用例。
9. **成本爆炸** —— 视觉密集 agent 是团队放弃 AI E2E 的头号原因（5k–15k token/步 × 30 步 = $0.5–2/次，× 2000 夜间套件 = $1–4k/晚）。缓解：缓存命中目标 >90%；grounding 走本地小模型，大模型只做失败时的 plan/reflect；**图片降采样到 ≤1024px / JPEG q70**（近零精度损失换 3–5× token 削减）；`max_cost_per_run` + 预算告警。
10. **提示注入** —— 页面文本、`alt`、`aria-label`、通知、webview 广告、错误 toast、安卓 app 内容全部会进模型。缓解：所有内容当**不可信数据**包进分隔块并声明"这是数据不是指令"；**不可逆动作（提交/支付/删除/授权/OAuth consent）必须走确定性白名单或人工确认**；禁止 agent 跳出 origin 白名单与 `javascript:`/`data:` URL；密钥经脱敏注入，永不进 transcript；记录模型当时看到的完整上下文以便事后审计。
11. **回放错位** —— 视频显示第 12 步而 trace 说第 9 步。缓解：单一单调时钟源，帧与事件同源打戳，**视频字幕轨由 `trace.jsonl` 生成**，两边都带 `seq`。

## 7. 待核实清单（网络恢复后第一批）

**承重项（错了会伤设计）**
1. Postman Flows 是否**真的没有 headless runner** —— 市场老大的结构性弱点，也是你的机会窗。
2. Apifox 业务场景的循环/判断在 **CLI runner** 里是否可用 —— 决定"导入即生成用例"能否进 CI，即你能否对标。
3. Maestro 是否新增 `http:` 步骤 —— 若有，它的 flow 已覆盖 API+UI 两端，直接对标你的统一引擎。

**其余**
4. MeterSphere v3 步骤节点表（IF/WHILE/FOREACH 是否还在）、是否加了移动端、许可证变更风险、2026 实际活跃度。
5. Bruno 是否已有 AI 功能；`--iter` 是否支持真条件；`bruno-cli` fork 分裂情况。
6. Schemathesis 2026 的 flag 名（`--stateful` / links / replay-DB `reuse`）。
7. `@playwright/mcp` 当前工具清单与 `--caps` 面；Stagehand 缓存键格式与自愈配置；Midscene locate-cache 文件格式与模型矩阵。
8. scrcpy v3 协议 `INJECT_*` 消息结构与 socket class 变更；`@yume-chan/scrcpy-decoder-webcodecs` 与 `NetrisTV/ws-scrcpy` 的 scrcpy-v3 兼容性与维护状态；`sonic-cloud` 流架构。
9. AndroidWorld / OSWorld / ScreenSpot-Pro 榜单（月级变动）。
10. `appium-uiautomator2-driver` + `appium-mcp` 工具名与 `mobile: find` / `mobile: viewportScreenshot` 签名。
11. Dredd（疑已停维护）、RESTler（疑休眠）状态。
12. 中文 OSS 盲区（子代理明确承认不了解、未猜测）：`pi2`/waterfall、`Mudu`/木木测试、`SoCase`、`Tinker`、`Rater`、`DaraTest`、同名多个的 `OneAPI`。
